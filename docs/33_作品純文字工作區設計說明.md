# 作品純文字工作區設計說明

狀態：主要程式已調整；使用者已執行本機資料庫 SQL，新增欄位已確認存在，實際環境和畫面驗收尚未完成。

## 目標與範圍

將作品的站內編輯統一為純文字，方便在手機、電腦及其他應用程式之間直接複製、貼上和整理長文。純文字內容應保留使用者輸入的文字、空白與換行，不將特殊符號解讀為格式。

本文件描述純文字工作區的需求；既有作品設計文件中關於 Markdown 的內容保留為歷史決策。實際環境驗收完成前，不應視為已全面驗證。

## 三個獨立編輯區

每件作品都提供以下三個純文字區域，包含使用外部文件的作品：

| 區域 | 用途 |
| --- | --- |
| 主專注 | 目前最核心、正在編輯的內容。 |
| 構思 | 非正文的想法、備忘與草稿紙。 |
| 已寫稿件 | 較確定的稿件內容，可持續編輯與累積段落，亦可能是長篇文字。 |

使用者可以選擇區域並切換編輯。每個區域直接提供「複製全文」按鈕，複製該區完整的純文字內容。三區內容分開保存，切換不自動搬移、合併或清除文字；使用者可以自行複製與貼上。

三區不設定面向使用者的固定字數上限；實際容量仍受資料庫、請求大小及裝置資源限制。

## 介面配置

- 將作品內容的切換入口放在「關聯探索線」等輔助小卡之前，顯示「主專注／構思／已寫稿件」。
- 三項是內容區域，不代表作品的進度階段。既有「作品階段」仍有獨立的狀態語意與相關功能，不能因切換編輯區而改變。
- 手機上須能方便切換區域，不應為了切換反覆滑到長文底部。可在編輯區上方提供同一組切換控制；實際版面與既有畫面對齊後決定。
- 編輯器使用純文字，移除作品流程的 Markdown 格式工具、格式轉換與 Markdown 預覽／匯出。純文字複製應直接複製原文，保留換行。

## 外部文件與展品閱讀

- 保留外部文件網址功能。無論主要稿件來源選擇站內或外部文件，三個站內純文字區域都可使用。
- 使用外部文件的作品，預設以外部文件作為主要稿件來源；使用者可切換為站內「已寫稿件」。
- 展品閱讀依作品目前的主要稿件來源顯示：選擇外部文件時顯示「開啟外部文件」；選擇站內稿件時顯示「已寫稿件」。
- 切換主要稿件來源只改變閱讀入口，不自動同步、搬移或刪除外部網址與站內文字。三區的「複製全文」各自複製站內內容。

外部文件網址未填寫或站內稿件為空時顯示提示，不以其他區域的文字冒充主要稿件。外部網址的目標是否有效由目標網站決定，系統不保證連結持續可用。

## 既有作品與資料處理

- 既有正文原樣放入「主專注」，直接視為純文字。既有 `#`、`*` 等 Markdown 符號保留，不做格式轉換。
- 使用者已明確表示不需要另行保留原始 Markdown 備份供核對。規劃資料庫變更時仍須先確認實際資料表現況與執行方式，由使用者決定 SQL 內容及執行時機。
- 新增區域預設為空；既有來源模式、正文與外部網址保留。

## 儲存與跨裝置

既有作品編輯已有自動儲存、版本衝突處理及瀏覽器復原草稿。新設計應維持可辨識的儲存狀態及未儲存內容保護：

- 切換區域時，內容與儲存結果必須對應正確區域。
- 儲存失敗、離線、切換裝置或多分頁同時編輯時，不可靜默覆蓋其他內容；應提供明確狀態與處理方式。
- 封存作品應維持可閱讀與複製，還原後才能編輯的既有行為。

原有 API 對單一正文的 500,000 字元驗證限制已移除；資料庫欄位為 `TEXT`。仍須檢查部署環境的請求大小、長文效能及既有本機復原資料，不能只新增欄位就視為完成。

## 實作與資料庫

- `creative_works.body` 為主專注，`ideas` 為構思，`manuscript` 為已寫稿件；各區有獨立版本號。沿用 `editor_mode` 決定主要稿件來源。
- `PUT /api/creative-works/{id}/sections/{section}` 儲存指定區域並檢查版本；原 `/body` 入口保留主專注語意。外部文件來源也可以儲存站內區域。
- 保留自動儲存、離頁保護與本機復原草稿；舊復原草稿歸屬主專注。封存作品可閱讀及複製，還原後才能編輯。
- 作品流程的 Markdown 編輯器、預覽、匯出與專用相依套件已移除；支援各區純文字複製及下載。
- 本機 SQL 草稿已由使用者執行並確認新欄位存在。其他環境應先確認現有結構與備份，再由使用者決定 SQL 執行內容及時機；SQL 草稿不納入 Git 暫存或提交。
