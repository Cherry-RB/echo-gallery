# 實驗場需求改動與設計說明：以探索紀錄為中心

- 版本：v1.0，依本輪需求討論重新編寫，取代原 v0.1 草案。
- 範圍：Echo Gallery 實驗場，以及必要的首頁、收藏卡片、作品與目標整合。
- 狀態：本輪程式實作與自動驗證已完成；各環境的資料轉換、部署及人工驗收仍須分別核對。
- 定位：本文件是現行實驗場的唯一長期需求、設計與驗收依據；畫面細節後續可在不改變本文件已確認流程與資料語意的前提下迭代。
- 以使用者本輪明確決策與「其他默認採用」為依據。正式環境仍須另行核對，不能以測試環境資料推定正式環境也相同。

## 1. 目的與改變

實驗場協助使用者圍繞一個希望發生的改變，持續嘗試、記下觀察與想法，並回頭看見理解的變化。

要改善的痛點：

1. 實驗目的與探索方向發散，難以聚焦自己想改變什麼。
2. 記錄前必須理解探索線、行動、發現與整理，操作負擔較大。
3. 資訊與經驗不容易自然累積，也不容易找回理解的變化或下一個想試的可能。

新流程為：

**看見實驗方向 → 新增探索紀錄 → 按需要填寫內容與做法 → 儲存 → 透過主題、搜尋與標記回顧 → 需要時用同一做法再記一筆。**

紀錄可以是實作經驗、閱讀心得、疑問、想法或尚未執行的做法。新增前不必建立探索線、設定下一步或完成整理。

介面追求 Google Keep 般容易開始、彈性記錄的操作感，並延續 Echo Gallery 既有卡片及搜尋介面的風格。降低認知負擔與提升探索動機是設計目標，仍需透過實際使用驗證。

## 2. 範圍與簡化原則

本次包含：

- 起點、終點與實驗方向的呈現。
- 探索紀錄新增、閱讀、編輯、刪除及做法重用。
- 實驗內主題、理解節點、方法備選與本次亮點。
- 實驗內搜尋、篩選、排序及卡片／列表檢視。
- 常駐最多三種與最近最多三種做法。
- 收藏卡片「記到實驗」、探索紀錄作為作品來源、首頁最新紀錄。
- 舊探索資料完整轉換，以及實際環境可能存在的舊目標處理。

不增加以下功能：

- 獨立方法管理頁、方法版本庫、下一步管理系統或紀錄父子關係。
- 必填結案表單，或行動 → 發現 → 理解的強制階段。
- 探索紀錄與全域收藏卡片搜尋整合。
- 長期使用的舊版探索唯讀區、舊版目標管理介面。
- 只為搬資料而增加的永久來源註記欄位。
- `practice_saved_at`、獨立最近方法表或方法使用歷程表。
- 自動判定用途、亮點或因果關係。
- 與本次必要整合無關的其他模組全面改版。

備份、轉換核對及失敗復原是一次性工程工作，不應變成使用者長期維護的功能。

## 3. 實驗方向：起點與終點

### 3.1 定義與規則

- **終點：想達成的改變。** 實驗希望幫助使用者產生的行為、想法、情緒或成果變化，不限可量化指標。
- **起點：目前的狀況。** 相對於終點，目前怎麼做、有什麼感受、最常卡在哪裡。
- 尚不清楚時可以先寫已知或感受到的部分，終點可以留空；不以完整、量化的規劃阻擋建立實驗。
- 既有實驗說明、目標／假設保留為選填補充資訊，避免重複問答。
- 不新增必填「實際終點／結案結果」表單，成果及理解可以繼續寫在紀錄中。
- 封存實驗仍允許新增與編輯探索紀錄。

### 3.2 引導文字

建立時可先思考終點，再描述起點；儲存後以起點 → 終點呈現。

| 欄位 | 引導文字 | 範例 |
| --- | --- | --- |
| 終點：想達成的改變 | 你希望自己能做到什麼、改變什麼感受，或完成什麼？ | 下班後即使很累，也能畫十分鐘，不再一直等有空才畫。 |
| 起點：目前的狀況 | 針對這個改變，你現在通常怎麼做？最常卡在哪裡？ | 總覺得至少要有一小時才值得開始，結果最近一個月只畫過一次。 |

共用輔助說明：

> 還沒想清楚，可以先寫目前的感受。例如：「想畫畫，但每次想到要開始就覺得累，還不知道為什麼。」

### 3.3 呈現位置

標題、方向及起點／終點集中在詳情頁上方。寬螢幕可並排，窄螢幕上下排列；可收合成摘要並展開閱讀。不把期待終點放在整串紀錄頁尾，避免資料增加後看不到方向。

紀錄編輯器可呈現「想達成的改變」摘要；未填時不顯示空占位或強迫補填。

## 4. 探索紀錄欄位與驗證

| 欄位 | 已確認規則 |
| --- | --- |
| 標題 | 選填，允許只填標題儲存。 |
| 內容 | 選填，可記經驗、觀察、發現、閱讀心得、疑問或想法。 |
| 做法 | 選填，可寫已採用或接下來想試的做法，文字直接屬於這筆紀錄。 |
| 參考素材 | 選填，可多筆收藏卡片或網址。 |
| 主題 | 選填，可複選，只屬於目前實驗。 |
| 理解節點 | 獨立開關，預設關閉。 |
| 方法備選 | 獨立開關，預設關閉。 |
| 本次亮點 | 單選：一般、有所收穫、克服困難、高峰體驗；預設一般。 |
| 紀錄日期 | 預設今天，可補記過去，也可明確修改。 |
| 建立／更新時間 | 系統維護，使用者不用填寫。 |

**標題、內容、做法至少有一項非空白即可儲存。** 只有主題、素材或標記不能儲存。

理解節點與方法備選不額外強制某個文字欄位。方法備選可以是從讀書心得發現的可能性，做法留空也可以。兩個標記能同時開啟；開關不複製、搬移或清空紀錄。

- 理解節點：「這筆讓我有了新的理解，或修正了原本的想法。」
- 方法備選：「這裡有之後想試的做法或可能性。」

本次亮點保存的是主觀經驗，不是卡片顏色設定或能力評分。「一般」不必顯示徽章，其餘用文字搭配圖示；不依亮點調整預設排序。

每筆紀錄保存自己的做法文字，修改其他紀錄或快捷設定不會連動改寫。不使用「做法快照」作為介面名詞。不另設下次提醒欄位。內容限制須配合既有資料評估，不能靜默截斷長文。

## 5. 新增、編輯與重用流程

### 5.1 編輯器與確定文案

按鈕及編輯器標題使用「新增探索紀錄」，不用「留下這一步」。

內容在前、做法在後，兩者直接可見。選填標題可放於上方，但不要求先填；其他補充欄位按需展開。

| 欄位 | 確定採用的引導文字 |
| --- | --- |
| 內容 | 記下這次做了什麼、發現什麼、發生了什麼值得記下，或讀到什麼值得再試。 |
| 做法（選填） | 這次怎麼做，或接下來想試什麼？ |

可展開「不知道怎麼寫？」查看提示，不要求先選類型：

| 情況 | 提示 |
| --- | --- |
| 已經試過 | 我做了＿＿，結果＿＿。最有幫助／最卡住的是＿＿。 |
| 讀到或想到一個點子 | 我看到／想到＿＿，它可能有助於＿＿，想試試＿＿。 |
| 還沒弄懂 | 我原本以為＿＿，但這次＿＿，還不明白＿＿。 |

### 5.2 新增與修改

- 不要求先選主題、建立行動或整理歷史。
- 成功儲存才建立紀錄，開啟或取消草稿不建立資料。
- 編輯只改這筆紀錄，不連動其他紀錄或常駐文字。
- 有未儲存內容的離開保護，儲存失敗保留輸入。
- 重試不能重複新增，並行編輯不能靜默覆蓋較新內容。

### 5.3 用這個方法再記一筆

任何有非空白做法的紀錄，都可於更多選單提供「用這個方法再記一筆」，不限定方法備選。沒有做法時不顯示此操作，但仍可開啟方法備選標記。

操作開啟新草稿，只複製做法，可自行修改。不複製標題、內容、主題、素材、用途或亮點；日期預設今天，兩個用途關閉，亮點為一般。來源紀錄不變，不建立父子連結。

## 6. 常駐與最近做法

做法欄位旁提供入口，呈現目前實驗的「常駐最多三種＋最近最多三種」。下拉或彈窗由 UI 評估決定，不建立獨立管理頁。

選取只帶入文字；欄位已有不同文字時須確認替換。開啟、選取或取消草稿不算使用過。

### 6.1 常駐：後端快捷設定表

**已確認獨立保存於後端資料庫的「實驗常駐做法」小表。** 資料表至少表達所屬實驗、做法文字、顯示順序；實際名稱及必要技術欄位於工程設計決定。

- 每個實驗最多三種，不能空白或重複。
- 可由目前做法或最近選項設為常駐，並修改、移除及調整順序。
- 額滿時由使用者選擇替換或取消，不能自動淘汰。
- 設為常駐是獨立保存操作，不建立探索紀錄；成功後取消草稿，設定仍保留，介面須明確提示結果。
- 修改或移除常駐不改寫既有紀錄，刪除提供文字的紀錄也不移除常駐。
- 刪除實驗時一起清除；後端保存讓不同裝置取得相同設定。
- 這是文字快捷設定，不是共享方法實體或方法版本庫。

### 6.2 最近：直接查詢探索紀錄

**後端從整個實驗仍存在的紀錄查詢，不另建最近方法表，也不保存 `practice_saved_at`。**

1. 依建立時間由新到舊。
2. 跳過沒有做法的紀錄。
3. 依文字去重，排除已常駐的文字。
4. 往前找，最多三種，不足則照實顯示。

補充規則：

- 不限於前端當頁資料，不按紀錄日期或更新時間排名。
- 修改舊做法會反映新文字，但仍維持原紀錄的建立順序。
- 刪除紀錄或清空做法後，從其他仍存在紀錄重新計算。
- 只改標題、內容、標記不改變最近順序。
- 文字去重可統一首尾空白及換行，不自動合併同義句或忽略標點、大小寫。
- 不保存每次改寫前的做法作為永久歷史。

例如最近四筆為 A、B、A、C，顯示 A、B、C；A 已常駐時排除 A，再往前找其他不同做法。

## 7. 實驗內主題

- 與收藏卡片的全域 Tag 分開，僅屬於單一實驗。
- 一筆紀錄可有多個主題，也可以沒有主題。
- 提供全部、未分類及主題入口；未分類代表沒有主題，不必建立實體主題資料。
- 最多釘選三個快捷主題，與常駐做法的額度互相獨立。
- 可新增、改名、刪除主題；刪除只移除分類，不刪紀錄。
- 失去所有主題的紀錄自然出現在未分類。
- 釘選與目前篩選狀態要能區分，不能只依賴顏色。
- 寬螢幕可採左側導覽、窄螢幕收合，具體布局於 UI 設計確認。

## 8. 瀏覽與搜尋

### 8.1 延續既有風格

卡片沿用專案既有外觀、間距、標籤、更多選單及對話框。可重用元件或沿用原結構改寫，不強迫不同業務共用所有邏輯。

搜尋以現行 `echo-gallery-frontend/src/views/SearchView.vue` 為基礎，延續條件輸入、套用查詢、條件摘要、清除、排序、分頁的操作。不要另做一套查詢風格，也不要帶入收藏卡片專屬的回流等欄位。

UI 規劃對照 `docs/DESIGN_SYSTEM.md` 第 9.1 節及現有元件，聚焦本次流程。

### 8.2 查詢範圍與收合

- 實驗內獨立查詢，搜尋標題、內容、做法。
- 篩選主題、理解節點、方法備選、本次亮點、紀錄日期範圍。
- 同一維度多選採 OR，不同維度採 AND；同時選兩個用途時找兼具兩者的紀錄。
- 後端處理完整授權資料的搜尋、篩選、排序與分頁，不只篩選已載入項目。
- 本次不整合全域卡片搜尋；做法專用搜尋、同素材查找不列為已確認的獨立功能。

收合的具體設計仍待評估。方向為保留文字搜尋與篩選入口，其他條件可收合；收合後仍顯示已套用條件與清除入口，排序及檢視切換保持容易找到。

### 8.3 時間與排序

| 時間 | 意義 | 修改文字後 |
| --- | --- | --- |
| 紀錄日期 | 想把這筆記在哪一天，預設今天，可補記 | 不自動改變，明確編輯日期才改變 |
| 建立時間 | 首次成功新增的系統時間 | 不變 |
| 更新時間 | 最後成功修改的系統時間 | 更新 |

預設依紀錄日期由新到舊，可反向閱讀；排序可提供紀錄日期、建立時間及更新時間，相同值需有穩定次序。修改文字會影響更新排序，不改變新建排序與紀錄日期排序依據。

最近做法固定依建立時間取得，與畫面排序互相獨立。

### 8.4 卡片／列表

- 共用同一批資料、搜尋、篩選與排序，切換不清空條件。
- 記住檢視偏好；範圍與保存方式於工程設計沿用既有可用方式。
- 卡片呈現標題、做法、內容摘要、素材提示、主題／標記及日期；未填項目不留空占位。
- 沒標題時可用內容或做法摘要辨識，不自動寫回標題。
- 點卡片讀完整內容，更多選單及內部按鈕避免誤觸導航。
- 列表方便掃讀日期、做法與摘要，手機不依賴寬表格。
- 無資料、無搜尋結果、載入中、失敗須分開呈現；失敗不可當作零筆。

## 9. 周邊整合與刪除

### 9.1 收藏卡片與作品

- 收藏卡片詳情提供「記到實驗」，選實驗後開啟同一編輯器並帶入該卡片作為素材。
- 仍需填標題、內容、做法之一；不只因選了素材就建立空紀錄，也不自動複製收藏卡片全文。
- 作品可以直接引用探索紀錄，不要求先整理成收藏卡片。
- 作品來源選擇區分收藏卡片與探索紀錄，顯示所屬實驗並可開啟閱讀。
- 保留既有作品與實驗關係；一般成果作品連結與「作品引用此紀錄為來源」是不同方向，不能混用。
- 引用資料及紀錄須檢查 owner，不允許跨帳號關聯。

### 9.2 首頁與舊入口

- 移除目前行動／`currentTry`，改顯示最新一筆探索紀錄內容摘要。
- 最新預設跟隨紀錄日期排序；只有標題或做法時以其文字補足摘要。
- 移除獨立設定下一步及探索線管理作為新紀錄前置流程。
- 首頁素材區、活動統計、收藏卡片及作品反向連結等需隨新模型調整，不能留失效探索線入口；未定版面另行評估。

### 9.3 刪除與儲存保護

- 刪主題不刪紀錄；刪常駐不改紀錄；刪紀錄不刪參考收藏卡片。
- 已被作品引用的紀錄不可直接刪除，列出引用作品，先解除來源引用。
- 刪除整個實驗也需檢查其紀錄是否被作品引用。
- 刪實驗需清理紀錄、主題、快捷設定及關聯；原始作品與收藏卡片不能被誤刪。
- 保留版本衝突保護，避免兩個視窗靜默互相覆蓋。
- 新增具防重複送出能力，避免重試產生兩筆。它與版本衝突保護用途不同，實際機制於工程設計決定。
- 技術保護欄位不放到使用者表單。

## 10. 舊探索資料完整轉換

### 10.1 已確認映射

一次完整轉成新探索紀錄，不長期保留舊版唯讀介面。

| 舊資料 | 新去向 |
| --- | --- |
| 一個行動／方法及其發現、整理歷史 | 合成一張紀錄。方法放做法，發現與整理依序合併至內容。 |
| 只有方法、沒有發現 | 建立有做法的紀錄，保留已有整理文字；不假定已實作。 |
| 沒有行動的發現 | 每則獨立一張紀錄。 |
| 探索線名稱 | 轉實驗內主題，原系統未分類不建同名主題。 |
| 行動的探索線歸屬 | 新紀錄帶入相對應主題。 |
| 探索線結論與未歸屬整理 | 合為該主題的一張紀錄；沒有文字不製造空紀錄。 |
| 探索線素材、成果卡片、作品 | 集中成該主題的「原有素材與成果」紀錄，保留連結、角色及備註。 |
| 明確設定的常駐偏好 | 轉成實驗常駐做法文字與順序，依三種上限及去重規則核對。 |

- 不把探索線素材散布到每個行動紀錄。
- 成果作品連結不自動轉成作品來源引用；以正常連結能力呈現，避免另建舊版專用功能。
- 合併內容保留原發現日期與原文順序，不需新增永久遷移註記欄位。
- 採用舊行動現存做法，不宣稱能還原每則發現當時的方法版本；已有歷史文字完整納入。
- 用途預設關閉、亮點一般，不根據舊文字自動推斷。
- 新功能每次新發現可新增一筆，不繼續自動合併到舊行動那張紀錄。
- 其他舊欄位及關聯須盤點，未列在表內不代表可以丟棄；需保留的使用者文字優先放正常紀錄內容。

### 10.2 執行要求

1. 針對實際環境確認 schema、owner、外鍵、資料量及依賴。
2. 備份後試跑，核對原文、日期、主題與連結。合併會改變筆數，不能只比較新舊總數。
3. 確定切換的停寫方式，避免新舊同時寫入。
4. 以交易、執行前檢查或一次性核對防止重跑重複建立，不增加永久遷移來源欄位。
5. 無法映射項目列出處理，不靜默略過。
6. 驗證新介面與周邊功能後，依核准方案清理不再使用的結構。
7. 回復方案涵蓋切換後新增資料，不能還原備份時丟失新紀錄。

本文件不授權執行 SQL 或刪表。schema 變更先確認資料表現況與備份，SQL 草稿由使用者決定內容及執行時機；不得啟動 ORM 自動改表替代確認。SQL 草稿不加入 Git 暫存或提交。

## 11. 目標功能與正式環境

### 11.1 新目標方向

- 提供「新增探索紀錄數」指標。
- 不再讓新目標依賴已移除的建立方法或整理操作。
- 用途及亮點不作為預設績效指標。
- 搬移舊資料不算今天新增紀錄，不重複增加進度。

### 11.2 舊目標處理狀態

已確認測試及正式環境的舊目標資料可依受控 SQL 清理；**「把舊整理次數直接換成新紀錄次數」仍不是核准方案。** 正式環境的實際備份、執行與核對必須由維護者逐環境完成。

- 若確認受影響目標僅供測試且不需保存，可先備份，再由現有應用程式刪除。
- 不需刪除無關目標。受影響範圍包括建立方法／整理指標、探索線追蹤來源，並須盤點各狀態及歷次規則。
- 遷移在實際環境檢查剩餘依賴；有未處理目標就列出並停止相關轉換。
- 需要保留者另定一次性處理方案，不擅自改指標、結束或刪除。
- 不以本機零筆忽略正式環境，也不增加永久舊版目標管理功能。

依目前 `GoalService.delete`，經應用程式刪除目標會清理其規則歷程、追蹤來源、進度紀錄、回顧、提醒、證據關聯與排除設定；無其他目標使用的活動計數資料也會清理，共用資料保留。

原始卡片、實驗、探索紀錄與作品不隨目標刪除，帳號目標看板偏好也不隨單一目標清空。這是目前原始碼行為，不代表已核對正式部署；直接刪資料庫目標列不等同應用程式完整清理。

## 12. 工程與驗收

### 12.1 工程要求

先完成資料模型、API 契約及舊入口替換清單；修改 endpoint 前說明計畫。新紀錄不得仍強制依賴舊探索線與共享方法。

盤點首頁、卡片、作品、目標、實驗刪除及 demo 清理。新測資需確認 owner、外鍵與清理策略，驗證建立、讀取、清理完整生命週期。

前端修改後執行 `npm run build`，後端修改後執行 `.\gradlew.bat test`，跨前後端或契約變動兩者皆執行。UI 使用既有工具做聚焦驗證，工具不足時列出人工驗收與限制。

### 12.2 功能驗收

- [ ] 起點與終點可先不完整，仍能建立實驗並逐步修改。
- [ ] 只填標題、內容或做法都能保存，三者全空白不能保存。
- [ ] 用途可獨立或同時開啟，不強迫填做法或內容；亮點四種單選。
- [ ] 不必探索線、下一步或整理即可記錄，封存實驗也能操作。
- [ ] 有做法的任何紀錄都能再記一筆，只帶入做法。
- [ ] 常駐後端保存最多三種，額滿不自動覆蓋，刪來源紀錄不移除常駐。
- [ ] 最近查詢整個實驗，依建立時間去重並排除常駐，最多三種。
- [ ] 修改舊做法反映新文字但不提升建立順序；刪除後重新查詢。
- [ ] 主題僅限實驗，可複選及釘選三個，刪主題不刪紀錄。
- [ ] 搜尋涵蓋標題、內容與做法，沿用既有風格，條件及排序正確。
- [ ] 卡片／列表切換保留條件並記住偏好，收合不隱藏有效條件的存在。
- [ ] 紀錄日期、建立時間及更新時間各自符合定義。
- [ ] 收藏卡片記到實驗帶入素材，仍遵守文字驗證。
- [ ] 作品可引用紀錄，刪除被引用紀錄或其實驗會提示先解除引用。
- [ ] 首頁最新紀錄摘要可辨識只有標題或做法的紀錄。
- [ ] 無草稿意外遺失、重複新增、跨 owner 存取或靜默覆寫。
- [ ] 長文、手機、鍵盤、焦點、彈窗及錯誤／空結果狀態完成驗收。

### 12.3 遷移驗收

- [ ] 舊行動合為紀錄，方法、發現、整理與內含日期可核對。
- [ ] 無行動發現、線結論、未歸屬歷史與其他舊文字沒有遺漏。
- [ ] 探索線轉主題，系統未分類不被誤轉成有效主題。
- [ ] 素材與成果集中保留，不捏造逐筆關係或作品來源。
- [ ] 沒有永久遷移註記欄位或舊版唯讀功能。
- [ ] 實際環境舊目標依賴已檢查，未處理資料會阻止相關轉換。
- [ ] 重跑不重複建立，遷移不重複增加目標進度。
- [ ] 周邊入口及 demo 清理無失效依賴。
- [ ] 備份、核對及回復已演練，切換後新增資料有保護。
