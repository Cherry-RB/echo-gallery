## 2. 產品定位與本輪範圍

### 2.1 核心定位

自由探索不必承諾成果；當使用者想完成一件作品時，Echo Gallery 提供能持續返回、保存正文、引用素材及交付內容的工作空間。

| 概念 | 核心責任 | 與作品的關係 |
| --- | --- | --- |
| 卡片 | 保存、回流與找回值得再次取用的內容 | 可以成為作品素材，原回流排程不變 |
| 實驗場 | 試法、發現、練習與探索 | 可作作品主要脈絡，探索紀錄可成為素材 |
| 作品 | 持續製作一件可辨識的文章、故事或外部成果 | 擁有獨立正文或外部主要編輯位置 |
| 奇珍 | 保存成果介紹，經營後續試煉與價值 | 可選擇與作品一對一關聯，閱讀作品最新版 |
| 總覽 | 快速返回當前脈絡 | 提供接著創作、建立作品與作品庫入口 |

作品完成、對外發表、收入奇珍為三種獨立行為。作品可以不屬於任何實驗、不公開發表，也不收入奇珍。沒有同時只能製作一件作品的限制。

### 2.2 已確認的第一版範圍

- 建立全域個人作品庫、作品詳情與必要的跨模組入口。
- 同時提供內建 Markdown 及外部工具連結兩種模式。
- 支援多來源、跨實驗搜尋與引用、來源全文閱讀及複製。
- 提供下一步、五階段、獨立發表標記、最近一筆分享資訊。
- 支援自動儲存、本機復原草稿與並行修改衝突處理。
- 支援閱讀預覽、兩種全文複製與 Markdown 匯出。
- 支援新建奇珍、連到既有奇珍及解除關聯。
- 作品庫搜尋篩選、首頁接續、實驗內三件作品預覽及手機完整操作均在第一版。
- Demo 開放完整作品流程，提供虛構範例並完成清理生命週期。

其他 UI 聚焦工作另案處理，包括土壤分類視覺收斂、全面調整奇珍資訊順序、總覽統計重排，以及記錄探索後是否保留目前試法。本輪不順帶改變這些既有行為。

## 4. 使用情境與成功判準

### 4.1 第一版使用情境

- 電腦創作短篇、心得與技術文章，單件通常在五萬字內。
- 手機可完整續寫、閱讀預覽與加入素材，不只是唯讀版。
- 可從一筆探索、卡片或全新念頭建立作品；不要求來源或主要實驗。
- 可跨日返回同一件作品，找到已保存的正文與下一步。
- 可以同時經營多件不同階段的作品。
- 外部作品可使用專用工具製作，Echo Gallery 保存連結、脈絡與基本分享資訊。

「通常五萬字內」是使用情境，不是已確認的正文硬性上限。容量、長文輸入與預覽效能須另行設計，不能自動截斷超出內容。

### 4.2 成功判準

1. 原有自由探索、收藏與回流流程正常，沒有新增必填成果欄位。
2. 使用者能跨日接續同一件作品，不必翻找多筆紀錄重建草稿。
3. 至少完成一件能獨立閱讀或交付的作品，不要求公開或入藏。
4. 用另一種內容驗證，例如技術文章或心得，避免設計只適用小說。
5. 斷線、重新整理、登入過期及衝突情境不會靜默丟棄或覆寫使用者內容。

正式驗收優先使用隔離的虛構作品；如需使用真實創作，由使用者自行選擇，不自動讀取、匯入或建立其私人作品測資。

## 5. 導覽與頁面資訊架構

### 5.1 全域導覽與作品庫

建議前端路由為 `/works` 與 `/works/:id`，既有議事廳維持 `/issues`。本輪新增作品路由，不重做已完成的議事廳命名遷移。

| 頁面 | 目標內容與行為 |
| --- | --- |
| 左側主選單 | 新增「我的作品」；手機導覽沿用同一選單來源 |
| 總覽 | 提供「建立作品」「查看全部作品」及最近編輯的三件未封存作品；原探索、奇珍與觀測功能保留 |
| 我的作品 | 頁首與建立入口 → 搜尋篩選 → 作品集合 → 分頁 |
| 實驗詳情 | 既有探索區 → 正在製作（三件）→ 既有材料與線索；只顯示主要歸屬於該實驗的未封存作品 |
| 作品詳情 | 返回導覽與頁級操作 → 主題 → 下一步與正文／外部文件 → 素材及階段／分享／奇珍 |
| 卡片詳情 | 增加「用於作品」及已引用作品連結，保留現有閱讀與管理功能 |
| 探索歷程 | 單筆增加「用於作品」及作品連結，與既有 exports／整理成卡片並存 |
| 奇珍詳情 | 顯示來源作品與閱讀入口；既有試煉、收益與其他來源保留 |

作品詳情應可返回作品庫或來源實驗。返回時保留合理的查詢、篩選及閱讀位置；無有效來源時回作品庫。

### 5.2 我的作品

- 標題搜尋。
- 篩選主要實驗，包含「無歸屬」。
- 篩選五個作品階段、未發表／已發表、未封存／已封存狀態。
- 依最近編輯排序；閱讀或單純開啟頁面不改排序。
- 卡片摘要呈現名稱、主要實驗、階段、發表狀態、下一步與最近編輯時間。
- 不加入每日任務、完成率、排行榜或拖曳看板。
- 分頁大小、搜尋延遲、預設篩選與 URL 狀態保存細節列入技術設計。

最近編輯包含正文、下一步或作品資訊的實際修改。來源、階段、分享及關聯變更是否影響同一排序時間，須在技術設計明確定義，不能直接把所有資料庫 updatedAt 都當作最近創作。

### 5.3 首頁接續與實驗預覽

- 首頁接續最近編輯的三件未封存作品；不排除可分享、已發表或已入藏作品。
- 顯示名稱、下一步與繼續創作入口，另提供全部作品入口。
- 沒有作品時，不顯示大型催促、零完成率或未完成警告。
- 實驗詳情預覽三件最近編輯且未封存作品；查看更多進 `/works` 並套用該實驗篩選。
- 只引用某實驗的素材，不會使作品自動出現在該實驗的「正在製作」。

## 6. 作品建立與編輯工作區

### 6.1 建立與作品資訊

設計規劃：建立表單包含名稱、選填簡述、主要編輯位置與選填主要實驗。內建為初始建議模式；建立後正文與下一步空白、階段為製作中、初始為未發表。

- 名稱不得全空白，允許不同作品同名的需求及欄位上限在技術設計確認。
- 從實驗直接建立可預填該實驗，但不預選探索紀錄。
- 從單筆來源建立時，帶入該來源關聯；不自動把全文插入正文。
- 加入既有作品可搜尋全域作品庫，不受來源所屬實驗限制，也不改變既有作品主要實驗。
- 成功後前往對應工作區；失敗保留輸入，提交中防止重複建立。
- 新建作品與預選來源須避免部分成功：不能顯示已完成關聯卻只建立作品。

### 6.2 內建 Markdown

- 支援標題、粗體、列表、一般連結、引用、程式碼及圖片網址。
- 提供基本插入按鈕與格式預覽；預覽不混入素材、下一步或分享備註。
- 不導入大型富文字、章節樹或無限畫布。
- 不上傳圖片或附件；外部圖片失敗提供適當替代，不影響正文保存。
- Markdown 預覽的 HTML 與 URL 安全處理為必要實作要求；不把任意 HTML 當成可執行內容。
- 正文為主要視覺與操作區；字數為資訊，不是目標或成熟度判斷。
- 複製 Markdown、複製純文字、匯出 Markdown 均含標題與完整正文，不含私人下一步、素材清單或分享備註。
- 匯出保留圖片與其他網址，不下載或打包外部檔案。
- 純文字複製須移除 Markdown 語法；圖片替代文字、連結文字／網址及程式碼的轉換細節待技術規格定義。

### 6.3 外部模式與模式切換

- 外部網址可稍後補；有有效 HTTP(S) 網址才提供開啟文件。
- 外部模式不顯示內建正文編輯器，不宣稱持有外部最新內容，不提供外部正文假預覽、字數或匯出。
- 可明確更換主要編輯位置；切換不刪除既有正文或外部網址，但只有一個主要編輯位置。
- 內建正文與外部文件不雙向同步；切回內建時也不自動抓取或匯入外部內容。
- 主要編輯網址與分享／發表網址責任不同，不可因更新其中一個而無提示覆寫另一個。

### 6.4 下一步與手機版

- 「下次接著做」選填、可修改與清空，不影響階段，不阻止結束創作。
- 桌面沿用 DetailShell／DetailHeading，以正文主區及輔助資訊組合；不足寬度時堆疊。
- 手機順序：主題與操作 → 下一步 → 正文／外部文件 → 參考素材 → 階段、分享及奇珍。
- 手機必須能續寫、預覽、搜尋及加入素材，檢查軟鍵盤、中文組字、游標及畫面重排，不以桌面建置通過替代。

### 6.5 Markdown 的必要性、完整性與實作建議

評估結論：**首版保留有限且完整的 Markdown 能力是必要的；不需要完整富文字編輯系統。** 文字創作、技術文章、閱讀預覽及可交付匯出都會用到同一份正文，若只存文字但不能正確預覽或帶出內容，就沒有完成已確認的創作流程。

目前 package.json 沒有 Markdown 解析器。現有表單、字數與圖片驗證可以重用，但不能視為已具備正文編輯、解析、純文字轉換及安全呈現。

| 能力 | 必要性與首版邊界 | 完整性要求 |
| --- | --- | --- |
| 原始正文 | 必須；保存 Markdown 原文作為唯一內建正文 | 保存與開啟不可經 HTML 往返轉換而改寫原文；清空正文也是有效編輯 |
| 基本語法與插入 | 必須；段落、換行、標題、粗體、列表、連結、引用、程式碼與圖片網址 | 工具列與解析支援一致；中文、選取範圍、游標、撤銷及手機輸入須驗證 |
| 閱讀預覽 | 必須；可切換撰寫／預覽，不要求即時雙欄 | 編輯、作品閱讀與奇珍入口使用相同解析規則；不重新載入舊正文取代本機稿 |
| 安全呈現 | 必須；停用原始 HTML，驗證連結及圖片 URL | 不接受腳本／事件屬性或危險協定；外連與圖片失敗語意一致，不改寫保存原文 |
| 複製純文字 | 必須；從解析結果抽取文字 | 不以正規表示式刪除所有符號；保留清單順序、程式碼文字、連結文字及圖片替代文字的可讀性 |
| 複製／匯出 Markdown | 必須；標題與完整正文，圖片只保留網址 | 與編輯中內容一致；明示取用目前稿件，不能假裝已存伺服器；失敗提供回饋 |
| 五萬字級操作 | 必須驗證；這是典型篇幅，不是已核准上限 | 量測輸入、切換預覽及匯出；不要每次按鍵同步解析與重建整頁，避免失去焦點與游標 |
| 擴充語法與視覺功能 | 可延後 | 表格、任務清單、語法上色、同步捲動、目錄及快捷鍵擴充，僅有實際需求才加入 |
| 大型編輯器與檔案系統 | 本輪不做 | 富文字、章節管理、附件上傳、PDF／HTML 匯出及外部文件同步 |

實作建議：一般多行文字輸入搭配小型工具列與成熟 Markdown 解析器，預覽及純文字抽取共用解析結果；不自製 Markdown parser。可評估 markdown-it 等候選，套件、版本與必要擴充仍須依相容性及依賴成本選定。其官方文件提供 CommonMark 與規則設定說明，不能因此推定任意外掛或自訂 renderer 都安全。[markdown-it 官方文件](https://markdown-it.github.io/markdown-it/)

首版驗證必須包括巢狀列表、中文換行、程式碼中的 Markdown 符號、帶括號網址、圖片失敗、危險 URL、清空全文、標題特殊字元及長文匯出。這些屬於既定功能的正確性，不是另外增加的編輯器功能。

## 7. 保存、復原與並行修改

### 7.1 已確認保存行為

- 正文自動保存到伺服器，明確顯示編輯中、儲存中、已儲存、儲存失敗。
- 只修改幾個字也是有效變更，不設最少修改字數；內容未變則不送出正文保存請求。
- 已儲存表示目前正文與最近一次伺服器成功確認的正文相同，且沒有尚未釐清的在途保存；不能只根據請求開始、本機寫入或曾經成功保存過判定。
- 已儲存不承諾其他裝置此刻沒有更新；本功能不做即時同步，版本落差在後續保存或重新讀取時發現。
- 停止輸入一小段時間後才自動送出；持續輸入時保留最大等待機制，具體時間依實測決定。
- 版本檢查整合於保存請求，不定期輪詢 API；沒有變更時不因版本檢查持續發送請求。
- 保留依帳號與作品隔離的本機復原草稿，與伺服器資料分開表達。
- 斷線、重新整理或登入過期後，同帳號可恢復尚未同步內容；登出時提醒處理未同步草稿。
- 不讓其他帳號讀取或恢復前一帳號草稿，不把 Demo 草稿帶到一般帳號。
- 網路失敗不清空正文，提供重試與內容帶出方式；不以短暫通知作為唯一錯誤提示。
- 離頁、重新整理、關閉、登出及模式切換都須納入未同步內容保護。
- 本機儲存不可用或容量不足時明示限制，仍保留畫面內容與離頁保護，不宣稱可恢復。

### 7.2 已確認衝突行為

首版採簡化處理：保存請求的預期版本與伺服器版本不同時，後端拒絕寫入；前端保留目前未保存稿，停止自動送出，提示「其他地方已更新，請重新載入」。

- 使用者可以先複製或下載本機稿，再重新載入伺服器最新成功保存的正文。
- 重新載入須明確告知會切換到伺服器稿；未同步本機稿仍依復原策略保留，只有明確放棄才清除，不因載入成功就靜默刪除。
- 若暫不重新載入，可留在畫面保留／帶出稿件；不繼續自動提交。完成重新載入並取得基準版本後，新的編輯才可再次保存。
- 首版不提供雙稿比較、差異高亮、合併或「以本機版取代」按鈕，也不保存完整正文版本歷史。
- 最新一份指伺服器最後成功提交的正文；不能靠裝置時間或最後抵達的舊稿直接覆寫。

技術設計應處理以下情況：

- 較舊請求不可覆寫較新正文；回應也不能倒退「已儲存」狀態。
- 重新載入後伺服器再被其他裝置更新，下一次保存仍須版本檢查，不能繞過保護。
- Query 重新抓取、視窗聚焦、切換作品及認證導頁不覆蓋本機未保存稿。
- 已被刪除、封存或失去存取資格的作品，不因本機復原而自動復活、還原或繼續寫入。
- 復原草稿與伺服器有差異時，不直接當成最新版送出；基準版本不同就走本節簡化衝突流程，不自動套用新版版本號提交舊稿。

### 7.3 技術細節待確認

保存延遲與最大等待時間、離焦與離頁的送出時機、本機草稿儲存方式／保留與清理策略、重新載入確認與版本欄位範圍，均須形成具體設計。第 7.4 節提出必要能力及驗證要求；時間參數須依中文輸入與長文實測決定，不先宣告為已確認數值。雙稿比較及手動取代不列入首版設計待辦。

本機草稿是復原機制，不代表完整離線應用、跨裝置離線佇列或長期備份。

### 7.4 保存復原與衝突處理的必要性、完整性評估

#### 7.4.1 評估結論與首版最低完整範圍

**伺服器保存、本機復原及並行衝突保護都必須在首版具備。** 三者處理不同失敗：只自動保存無法保證斷線後重整不丟稿；只留本機稿無法提供跨裝置續作；只保留兩份文字而沒有後端版本檢查，仍會發生先覆寫、後提示的資料損失。

作品預期會長時間編輯、跨日返回及使用手機，自動儲存可減少忘記保存與中斷損失，因此保留為首版必要能力。即使只有一名使用者，也可能開兩個分頁或先後使用手機、電腦；以簡單版本核對防止誤覆寫，不擴充即時協作或完整版本管理。

| 能力 | 首版判斷 | 邊界 |
| --- | --- | --- |
| 自動儲存與明確狀態 | 必須 | 實際變更才送出、適度延遲、最大等待、請求順序與真正成功確認；失敗可重試 |
| 手動立即儲存 | 可提供的輔助操作 | 與自動儲存共用流程、變更判斷及版本檢查，不另造第二套狀態 |
| 本機復原草稿 | 必須，為已確認需求 | 持續保存未同步編輯，重新開啟由使用者選擇恢復；不是只在離頁時才備份 |
| 認證失效與離頁保護 | 必須 | 配合既有 router、request 與登出流程，先保住稿件；不擴大重做帳號系統 |
| 後端條件更新 | 必須 | 預期版本與寫入原子核對；不能只靠前端排隊或時間戳排序 |
| 簡化衝突提示 | 必須 | 停止自動送出、保留可複製／下載的本機稿，確認後重新載入伺服器最新正文 |
| 雙稿比較、差異高亮與手動取代 | 首版延後 | 不要求並排、逐字比較或覆寫選擇介面 |
| 自動合併、編輯鎖與協作 | 本輪不做 | 不開發 CRDT／OT、即時廣播、編輯租約或多人共同編輯 |
| 全文版本歷史與備份系統 | 本輪不做 | revision 只供核對目前版本，不保存每次全文，不提供回溯任意歷史 |

簡化衝突流程、自動儲存與不輪詢機制已經本輪補充討論確認，取代先前較複雜的比較與取代設計；其餘實作建議仍不代表功能已完成。

#### 7.4.2 伺服器保存流程的缺口與建議

現有 CardDetail 的離頁確認與 AppDialog 保護可供互動參考，但不足以承接持續寫作。現有請求層也會把 409 當一般資料衝突通知、401／403 導向登入，需為作品保存提供可理解的業務狀態。

建議保存流程：

1. 編輯先更新獨立的本機工作稿，不直接改寫 Query 的伺服器快取。
2. 記錄本次內容序號與基準版本，排程本機備份；目前正文與最近一次成功保存正文不同時才排程伺服器保存。中文組字期間不插入格式或重建輸入框。
3. 同一編輯工作區依序送出保存，送出中的後續修改保留為待存最新版；持續輸入也須有最大等待時間。
4. 成功回應只確認該次送出的內容與新版本。若已有後續輸入，仍為待保存，不顯示整份已儲存，也不刪除更新的復原稿。
5. 網路失敗或伺服器回應超時，保留工作稿與備份；不可假設請求一定未寫入，也不能把未知結果當成功。
6. 重試前核對版本；若伺服器內容已等同該次稿件，可確認結果，否則依版本處理衝突，不盲目重送舊全文。
7. 變更階段、封存、切換模式或入藏等需要一致正文的操作，先處理尚未保存內容；失敗不得只更新其他欄位後宣稱整份已完成。

建議區分「編輯中／儲存中／已儲存／儲存失敗／需重新登入／待處理版本衝突」，另標示本機備份成功或失敗。離線與復原期間提供稿件複製／下載，不必為取得內容先成功連線。

正文變更判斷以完整原文是否相同為準，不以按鍵次數或字數差判斷，也不擅自忽略空白與換行，以免改變 Markdown 語意。

| 情境 | 正文保存與版本處理 |
| --- | --- |
| 只改或新增幾個字 | 有效變更，依自動儲存時機送出 |
| 加字後改回原文，尚未送出 | 若與最近成功保存正文相同且無在途請求，取消待送保存，不增加版本號 |
| 加字已保存成功，再改回原文 | 改回也是相對目前伺服器正文的新變更，需要再保存，成功後版本增加 |
| 請求已送出但尚未回應時改回原文 | 保留目前稿件，等該次結果；若加字已被保存，接著送出改回後的正文，不漏存也不因舊回應重設輸入 |
| 請求結果未知或失敗後改回原文 | 不能只因等於舊基準就宣告已儲存；先釐清在途結果或重試核對，再決定是否需要保存 |
| 內容一直沒變 | 不送出正文保存，也不另外查版本；其他頁面既有資料查詢不屬於正文版本輪詢 |

#### 7.4.3 本機復原的完整性與限制

建議優先評估 IndexedDB，使用非同步寫入保存典型長文；儲存方式仍待相容性驗證，不直接每次按鍵同步寫入 localStorage。IndexedDB 是非同步 API，但瀏覽器儲存仍有配額、清除與驅逐條件，本機稿不是永久備份。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)、[MDN 儲存配額與清除](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

完整實作至少處理：

- 草稿識別包含 owner、作品與編輯工作區識別；不能只用 owner＋作品當唯一 key，讓兩個分頁的未存稿互相覆蓋。每個工作區保留最新未確認稿即可，不建立長期版本歷程。
- 保存原文、基準 revision、本機內容序號與備份時間；不能靠裝置時鐘判定誰一定最新。
- 只有儲存交易確定完成後才標示已備份；記錄失敗、配額不足及不可用狀態。
- 重新登入同帳號後，先核對作品仍存在且可編輯，再提供復原選擇；封存、刪除、Demo 到期或跨帳號時不可自動提交。
- 復原內容與伺服器相同時可消除冗餘；不同且基準版本仍相同時可讓使用者明確恢復該本機稿。基準版本已改變時保留可帶出的本機稿，提示重新載入，不提供雙稿比較或自動合併。
- 伺服器確認、明確放棄、刪除作品及 Demo 清理的本機清除，僅處理對應稿件；較舊請求的成功不得清掉較新輸入。
- 登出須呈現「先同步、帶出後放棄、保留本機待同帳號復原」等具體選擇，實際操作文字與清理策略在實作前定案；不得默默清空未同步稿。
- 帳號 key 的隔離是應用程式存取規則，不代表本機文字已加密；不將原文寫進通用日誌或同步給其他帳號。

離頁事件只作最後補強，不能當成唯一保存入口。手機上 beforeunload 不一定觸發，關閉提示文字也由瀏覽器控制，因此需在平常輸入時備份，並在頁面隱藏等時機嘗試保存。不能承諾瀏覽器被強制終止前最後一個字永不遺失；驗收要量測未備份時間窗及異常回饋。[MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)

#### 7.4.4 簡單版本檢查與衝突流程

每件作品保存目前版本的整數識別；欄位暫稱 version（技術命名可為 revision）。開啟作品時，前端一起取得正文與版本。正文保存請求附上「我根據哪一版修改」的預期版本，後端原子核對 owner、可編輯狀態與版本，相符才寫入並增加版本號，回傳更新後版本。資料庫只需目前正文與版本號，不保存歷次全文。

| 操作範例 | 資料庫版本 | 結果 |
| --- | --- | --- |
| 電腦、手機同時開啟 | 7 | 兩邊取得正文與版本 7 |
| 電腦有修改，附預期版本 7 保存 | 7 → 8 | 原子核對成功，保存正文並回傳版本 8 |
| 手機有修改，仍附預期版本 7 保存 | 8 | 版本不符，拒絕寫入並回覆衝突，資料庫維持版本 8 |

檢查與寫入需在同一次資料庫條件更新或等效交易保護下完成；不能先讀版本、再無條件更新。HTTP 條件更新亦使用相同的防誤覆寫概念，參考 [RFC 9110 §13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)；首版以整數預期版本說明 contract，不另外增加一套 ETag 同步機制。實際狀態碼與錯誤格式在 API 設計確定，前端不得只顯示「資料已存在」。

版本是否相同是在原本保存請求內檢查，不另加「查版本」API，也不在使用者編輯期間輪詢。衝突後由使用者觸發的重新載入，或釐清結果未知請求所需的查詢，屬於明確事件處理。

首版處理流程：

1. 收到版本衝突後停止該作品自動提交，保留目前正文與本機備份，顯示「其他地方已更新，請重新載入」。
2. 提供本機稿的複製／下載，不必先取回另一份正文或開啟比較工作區。
3. 使用者確認重新載入後，讀取伺服器最新成功保存的正文與版本作為新基準；先前未同步稿不靜默清除。
4. 使用者在新基準上編輯後，依相同自動儲存與版本檢查流程保存；若有另一裝置再更新，可再次收到衝突。
5. 本機舊稿不自動重新送出，不提供強制覆寫。若需要保留部分文字，使用者可自行從帶出的稿件貼入新基準後正常保存。

正文使用專用 revision 或整份作品共用 revision，須依 API 更新範圍選定。無論採哪種，作品資訊、模式、封存及關聯操作都不能透過完整 PUT 或其他端點繞過正文保護；其他裝置封存或刪除後，仍須正確拒絕未完成的正文寫入。

#### 7.4.5 完整性驗證門檻與成本控制

目前這三類能力在既有程式中都尚未完成，文件定義也不代表已驗收。實作應以一個作品保存流程處理自動保存、手動保存、復原及衝突，避免每個彈窗或來源各自建立一套儲存機制。

首版至少測試：少量修改會保存、送出前改回原文不送出、成功保存後改回會再保存、在途請求期間改回不漏存、無修改不輪詢、同分頁快速輸入與亂序回應、請求成功但回應遺失、離線重整復原、登入失效、兩分頁各留未存稿、兩裝置先後寫入、衝突後停止提交及確認重新載入、清空全文、封存／刪除與寫入競爭，以及 Demo 重設後不可復活舊稿。後端條件更新以整合測試驗證；中文組字、手機背景切換與長文輸入另外做瀏覽器驗收。

可以延後雙稿比較、差異高亮、手動取代、跨分頁即時通知、游標同步、智慧合併、離線建立作品與完整歷史版本。首版保留後端條件更新、本機稿保留、登入失效保護與可理解的重新載入流程。

## 8. 五階段、完成日期與發表

| 階段 | 意義 |
| --- | --- |
| 製作中 | 正在產生作品內容或外部成果 |
| 初版完成 | 已有第一份完整版本，不代表公開或不再修改 |
| 編修中 | 正在修改、調整既有作品 |
| 編修完成 | 這一輪修改已結束，由創作者判斷 |
| 可分享 | 創作者確認已有能交給他人閱讀或使用的版本，不代表已公開 |

- 五階段全部手動切換，可跳選與回退；修改正文不自動改階段。
- 頁首只建議下一步，不強制依序通關，不自動評分。
- 保留首次初版完成日期，可查看及修正；另記錄目前階段最後切換時間。
- 完整階段歷程、編修輪次與正文版本快照延後。
- 未發表／已發表為獨立手動標記，與階段無綁定。
- 複製、匯出、填分享網址或收入奇珍都不自動標記已發表。
- 已發表作品可繼續編輯與回退階段，不鎖住正文。

技術設計須補充：跳過初版完成時的日期處理、初次設定日期是否提示、日期可用範圍，以及不同階段的頁首建議操作。不以小說必須有特定形式結局作為其他作品的通用完成條件。

## 9. 最近一筆分享／交付資訊

- 每件作品先保存最近一筆分享／發表網址、實際日期與分享／回饋備註。
- 更新時明示會替換原資訊，第一版不保存之前每次分享的歷程。
- 分享可以沒有公開網址，例如私人傳閱；網址存在時須驗證 HTTP(S)。
- 實際日期與資料更新時間分開，日期範圍及是否允許清除整筆資訊待技術規格確認。
- 匯出／複製不強制建立分享紀錄，也不保證對方已收到或已閱讀。
- 不驗證外部網站是否真的發表成功，不同步社群平台。
- Work 沒有入藏時，也可保存這一筆資訊；入藏後的持續價值優先使用既有奇珍收益，不新增第二套收益系統。
- 若分享後又改稿，介面應說明目前稿件可能不同於已分享內容；第一版沒有歷史正文快照可供還原。

## 10. 素材引用與來源閱讀

### 10.1 搜尋與選取

- 可一次選取多張卡片或多筆探索紀錄，兩種來源可在作品內並存。
- 卡片按標題或 ID 搜尋；探索按試法／發現文字搜尋並可篩選實驗。
- 預設可找到封存卡片及封存實驗的紀錄，清楚標示封存。
- 探索候選至少呈現實驗名稱、日期與內容摘要；既有紀錄沒有獨立標題，不為了來源選擇強加新必填欄位。
- 所有候選限目前 owner，後端分頁；不先下載所有實驗與完整探索再由前端搜尋。
- 同一來源可供多件作品使用，同作品不得重複加入同一來源。
- 加入來源不消耗、搬移原文，不改變卡片回流、土壤角色或作品主要實驗。
- 選擇器的單批數量及作品來源總量上限待技術設計，不直接沿用其他功能的 20 件上限。

### 10.2 閱讀、複製與反向連結

- 工作區可讀來源全文及複製；正文由使用者自行貼入，不做選取片段一鍵插入。
- 來源平常讀最新版，不另存加入時的文字快照。
- 貼入正文後為獨立草稿，不受來源修改影響。
- 卡片詳情及各處探索歷程顯示相關作品連結，與既有整理成卡片結果並存。
- 從來源加入既有作品不改其主要實驗；相關作品列表如何標示已封存作品在實作設計確認。
- 來源全文閱讀與返回須保留作品未同步稿及來源瀏覽脈絡，避免因跳頁而遺失輸入。

## 11. 作品與奇珍銜接

### 11.1 入藏與已有奇珍

- 只有可分享階段能新增奇珍關聯，不要求已公開發表。
- 可建立新奇珍，或選一件尚未對應其他作品的已有奇珍。
- 建立新奇珍重用 TreasureFormDialog，預填作品名稱、簡述、可用分享網址及主要實驗；完成日期須由使用者確認。
- 連到已有奇珍時，保留其原說明、完成日期、等級、來源與收益，不以作品內容覆寫。
- 同一作品最多對應一件奇珍，既有奇珍也不能重複對應不同作品；並行操作須維持此限制。
- 新奇珍從石級開始，原本四階試煉與收益規則保留，不要求設定檢定。
- 已有奇珍保留原等級，不因建立作品關聯重新從石級開始。

### 11.2 閱讀與後續修改

- 奇珍提供作品閱讀入口；內建作品進入 Work 的閱讀模式，讀目前最新版。
- 外部作品沿用外部主要文件入口，不宣稱可讀到同步的外部正文。
- 新建入藏時的說明預填後，雙方各自編輯，不建立自動同步。
- 入藏後可回退作品階段、繼續修改，奇珍仍保留。
- 可以明確解除關聯，不刪除任何一方；重新關聯須再符合可分享條件。
- 刪除奇珍後作品保留，可再次入藏。
- 刪除作品後奇珍與收益保留，但解除作品連結，不能再讀取已刪正文，也沒有入藏快照可恢復。
- 已封存作品仍可唯讀；關聯奇珍的閱讀入口不得因作品封存而失效。

已有奇珍若已封存，是否可選為新關聯目標，以及解除／改連對奇珍最近活動排序的影響，列入實作前邊界確認。

## 12. 封存、還原與刪除生命週期

| 操作 | 保留 | 解除或停止 |
| --- | --- | --- |
| 修改來源 | 作品正文 | 來源閱讀改呈現最新版，不自動改稿 |
| 刪除來源卡片或探索紀錄 | 作品、正文與其他來源 | 該來源有效關聯及反向連結，不留來源文字副本 |
| 封存主要實驗 | 作品編輯、首頁接續與主要歸屬 | 不自動封存作品 |
| 刪除主要實驗 | 作品正文、階段、分享與其他有效素材 | 主要實驗歸屬及隨實驗刪除的來源紀錄關聯 |
| 清除實驗探索資料 | 作品與既有正文 | 被清除紀錄的作品來源關聯 |
| 封存作品 | 作品、來源、分享、奇珍關聯及唯讀入口 | 退出首頁與實驗預覽，還原前不可編輯 |
| 還原作品 | 作品內容與階段 | 解除封存限制，不自動改階段 |
| 永久刪除作品 | 卡片、探索、實驗、奇珍與收益 | 作品本體、作品關聯及應清除的本機稿；沒有回收桶 |
| 解除奇珍關聯 | 作品與奇珍全部內容 | 雙向對應關係 |
| 刪除奇珍 | 作品與正文 | 已失效奇珍對應，可重新入藏 |
| Demo 重設／到期 | 其他 owner 資料 | 該 Demo owner 的作品、來源、分享、關聯及應清理的本機稿 |

永久刪除須有獨立確認；提示需包含將失去的正文與關聯，以及仍保留的來源和奇珍。不以刪除保護為由自行加入回收桶或改成保留全部歷史。

| 流程 | 主要規劃 |
| --- | --- |
| 建立作品／用於作品 | 新建與加入已有作品分開；來源摘要唯讀；成功進作品工作區 |
| 編輯作品資訊 | 名稱、簡述、主要實驗及編輯位置；模式切換明示保留原內容 |

| 加入參考素材 | 卡片／探索分區、搜尋、跨頁多選與已選摘要 |
| 閱讀來源全文 | 唯讀全文、複製及返回，不清掉編輯中的正文 |
| 階段 | 五階段手動選擇，必要時處理首次完成日期 |
| 分享／交付 | 最近一筆資訊，替換提示，不更動發表標記 |
| 發表標記 | 獨立手動操作，不要求分享 URL |
| 收入奇珍 | 新建／選既有；既有奇珍清楚提示內容不覆寫 |
| 封存／永久刪除 | 各自說明後果，永久刪除獨立確認 |
| 衝突／復原 | 保留可複製／下載的本機稿，明確確認重新載入；基準相同才可選擇復原，不自動覆寫伺服器 |

沿用 AppDialog 的 busy、draft、draftReady 及 requestClose 語意。×、Esc、取消與程式離開共用草稿保護；提交失敗保留輸入，提交中停用離開及重複送出。來源選擇優先在同一外殼切換，返回保留父層草稿。實際尺寸、焦點、閱讀區及重新載入確認待 UI 設計確認，不另造彈窗外殼。

### 13.1 UI/UX 設計規劃與低保真稿

本節依 [設計系統](./DESIGN_SYSTEM.md) 與 [文案規範](./UI_COPYWRITING_GUIDE.md) 補齊操作細節，承接本輪設計審查。功能與資料規則仍以第 2～12 節為準；本節及低保真稿是待實作的設計，不是產品程式或人工驗收完成證明。

低保真稿已於本輪設計審查使用。所有作品、日期、統計與儲存狀態均為虛構示意；只切換畫面及狀態，不呼叫 API、不保存輸入、不代表功能已完成。設計稿的畫面選擇工具不屬於產品 UI。

設計約束：

- 作品庫使用集合模式，作品使用詳情＋編輯工作區，來源使用選擇器；不新增另一套 page shell、配色或彈窗元件。
- 依既有 token 組織字級、內距與表面。低保真稿以中性色檢查資訊及層級，正式畫面再套用既有 primary 與明暗主題。
- 每一容器只負責一層內距，不把統計、標籤或每個欄位重複包成卡片。
- 正文自動儲存不鎖住輸入或來源閱讀；只有明確提交的表單／選擇器才鎖定該流程。AppDialog 的 busy 不直接套用整個正文頁。
- 全頁草稿與彈窗草稿分開。彈窗只比較本次可編輯欄位，不比較正文、revision、查詢資料或背景更新的時間。
- 已保存的操作沒有「取消還原」語意；已保存正文離頁不問放棄。未同步內容依第 7 節保護。

作品卡片以名稱為主，階段、主要實驗與編輯時間分層。發表與封存為獨立文字狀態，不把所有狀態都做成同強度徽章。名稱可換行；列表摘要可截斷，但需有全文入口。單純閱讀不改排序。

作品庫篩選設計：桌面將左側的封存範圍與右側的搜尋／條件／操作群組拉開距離；窄螢幕改為上下排列。封存範圍提供未封存／已封存／全部，預設未封存，切換即刻查詢。搜尋、主要實驗、階段及發表狀態是同一組暫存條件，只有按「套用篩選」才寫入查詢並回到第一頁；「清除」清空該組條件。主要實驗與階段可多選，同一欄位內採 OR，不同欄位及封存範圍同時存在時採 AND。結果筆數只描述已套用的條件，不把尚未套用的輸入誤當成查詢結果。

頁首建議操作依階段為「標記初版完成」「開始編修」「標記編修完成」「標記可分享」「收入奇珍／查看奇珍」；屬於可選捷徑，不是進度關卡。五階段仍可從「更改階段」直接選擇。已封存或保存衝突時，不執行需要一致正文的階段與入藏提交；提示先還原或處理未同步內容。

### 13.4 彈窗分類與提交表

所有流程使用既有 AppDialog 或適合的 MessageBox。以下寬度僅為內容密度參考，沿用 520／620／760／900～980px 等既有幾何範圍，窄螢幕由外殼保留 12px 外側空間，不新增 token。短內容自然高度；長內容由一層 body 主捲動。

| 流程 | 模式／初始與草稿 | footer 與成功結果 | 返回、取消與封存 |
| --- | --- | --- | --- |
| 建立作品 | 一般表單；名稱與編輯位置先呈現，簡述及主要實驗選填；從來源進入顯示唯讀來源摘要 | 取消／建立作品；成功進工作區，不另加成功彈窗 | 未送出可取消；非同步初始值完成才比較草稿；不複製來源全文 |
| 用於作品 | 從探索紀錄進入時預選該筆，仍可追加其他探索紀錄；從卡片進入時直接帶入該卡片，略過探索紀錄選擇。兩種入口皆可切換「建立新作品／加入已有作品」，並保留未送草稿 | 新建為建立作品；已有為加入素材；成功進對應工作區 | 返回上一步保留分支輸入；父層探索歷程以替換顯示避免疊加，取消後回原紀錄位置；卡片入口取消則回卡片詳情 |
| 編輯作品資訊 | 一般表單；只含名稱、簡述、主要實驗與編輯模式／網址等本次欄位 | 取消／儲存變更；成功關閉並保留工作區位置 | 封存不開放；更換模式提交前先處理未存正文，保存失敗保留原模式與表單 |
| 下次接著做 | 簡短表單；多行選填，可清空 | 取消／儲存；成功更新摘要，回到原編輯脈絡 | 不改階段；封存唯讀，不開編輯表單 |

來源候選的選取與全文閱讀分開設控制項；整列選取的按鈕不能再包另一個互動按鈕。已加入的來源顯示「已加入」且不再新增；純粹重複選擇不得回報為一般儲存失敗。已選摘要包含種類及完整名稱，探索無標題時以所屬實驗、日期及摘要識別，不強加必填標題。

手機素材選擇器在提交列鄰近操作處保留「已選素材 · N 筆」，與已選摘要使用同一數量；即使摘要位於捲動區下方，也能理解此次提交範圍，不把總候選筆數當成已選數量。

## 14. 程式現況與預計受影響範圍

### 14.1 已核對現況

- Router 尚無新作品路由；LeftSidebar 由同一選單資料供桌面及手機使用。
- 目前沒有新作品 Entity，也沒有可直接沿用的 Markdown 編輯／解析套件。
- ExperimentExplorationRecord 已有獨立 ID；discovery 是該紀錄的文字欄位，不是另一個 Discovery Entity。
- exploration_record_cards 是探索整理成卡片的產出關聯，不能改當作品來源或探索引用來源。
- 探索 API 目前按實驗讀取，尚無跨實驗的來源搜尋與分頁能力。
- Treasure 尚無來源作品關聯；現有來源仍為一張卡片、一個實驗及多件奇珍。
- AppDialog 已有草稿離開與 busy 保護，但不具備正文自動儲存、本機復原或並行衝突能力。
- API 請求層的 401／403 會導向登入，需要與正文保護協調；本輪不擴大成整份帳號安全強化計畫。
- Demo 現有重設與到期清理順序須擴充，避免新增作品外鍵阻止清理。
- 前端已有 Vitest，後端整合測試使用 Testcontainers PostgreSQL；舊文件「前端沒有測試指令」不能作現況依據。

以上為來源碼與相關測試盤點，不代表已核對本機／遠端 schema、已執行完整測試或已完成瀏覽器驗收。

### 19.3 API 與相容性

新增根路徑為 `/api/creative-works`；沒有改名或移除既有 endpoint，也沒有改變既有 Card、Experiment、Issue、Treasure DTO 的必填欄位。

| 方法／子路徑 | 用途 |
| --- | --- |
| GET／POST 根路徑 | 篩選分頁／建立作品；建立可帶選填 `sources`，與作品同交易保存 |
| GET／PUT／DELETE `/{id}` | 詳情／作品資訊／永久刪除 |
| PUT `/{id}/body` | `{ body, expectedVersion }`；成功回傳正文與新版本，版本不符 409，未改內容不加版 |
| PUT `/{id}/next-step`、`/stage`、`/share` | 下一步／階段及首次完成日期／發表標記與最近分享 |
| PUT `/{id}/archive`、`/restore` | 封存、還原；封存作品所有內容與關聯修改均拒絕 |
| GET／POST `/{id}/sources`、DELETE `/{id}/sources/{sourceId}` | 閱讀最新版來源、批次引用、解除來源 |
| GET `/candidates`、`/usages`、`/experiments` | 素材分頁搜尋、批次反向作品連結、owner 的實驗選項 |
| PUT／POST／DELETE `/{id}/treasure` | 連已有奇珍／原子建立並連結奇珍／解除 |
| GET `/treasure/{id}` | 取得已連結作品；無連結回空內容，供奇珍顯示最新版閱讀入口 |

資料表為 `creative_works` 與 `creative_work_sources`。作品 owner 刪除連帶清理作品；主要實驗或奇珍刪除只清除對應 FK；來源卡片／探索刪除只清除來源列。來源設真實外鍵、二擇一約束與每作品去重；奇珍 FK 唯一。寫入核對 owner，作品保存、新增與關聯操作共用 owner 鎖，與 Demo 清理一致。

### 19.4 資料庫與啟動前置

已唯讀核對本機 `echogallery-db / echogallery / public`：既有 users、cards、experiments、experiment_exploration_records、treasures 主鍵皆為 bigint，兩張作品表尚不存在。工作區提供 `creative-work-schema.local-draft.sql`，**未執行、維持 untracked、禁止暫存或提交**；正式／其他環境仍需獨立核對 schema。

實際使用前由使用者確認目標、完成備份、審閱並決定 SQL 執行時機。現有 `application.yml` 仍有 `ddl-auto: update`，不要藉啟動應用程式讓 ORM 自動建表；手動完成 schema 後，建議以 `--spring.jpa.hibernate.ddl-auto=validate` 啟動檢查。此輪未變更 .env 或既有資料庫。

Demo 樣本「雨天的修理店」為虛構文字，只隨展示帳號 seed 建立；owner 為該展示使用者。重設與到期走既有 `DemoSessionService → TreasureLifecycle → WorkLifecycle` 清理，先移除作品來源及作品，再清理其餘既有資料。整合測試驗證建立、讀取、編輯、來源、入藏、重設與到期；沒有把個人創作內容加入樣本。
