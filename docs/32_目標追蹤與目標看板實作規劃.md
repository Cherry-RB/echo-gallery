本文件補齊需求文件第 28 節的設計細節，將既有決策轉成畫面、資料責任、API 與開發批次。不重新討論是否建立目標系統，也不要求使用者逐項重複核准已採用方案。

本文件先完成規劃，使用者其後授權實作批次 A。以下仍包含 B／C 的後續方案，實際交付範圍見第 15 節；不能把整份規劃視為全部已完成。資料庫僅唯讀查核，改表草稿未執行，也未使用 ORM 修改本機 schema。

第 15 節為先前交付當時的操作與驗收紀錄，不代表使用者其後的本機資料庫狀態。第 16 節承接最新已採用的 UI／UX 討論；若與前文的畫面、預選或查詢方式不同，以第 16 節為本輪實作基準。其餘歷史保存、權限及 B／C 批次邊界維持原規劃。本輪未連線查核或修改資料庫。

## 1. 交付順序與完成定義

| 批次 | 使用者可實際完成的事情 | 必須同步處理的底層工作 |
| --- | --- | --- |
| A：方向與閱讀 | 建立目標、選既有來源、固定總覽、翻閱相關卡片、查看目標關聯 | 歷史保存起點、必要事實、每日修改摘要、owner 與清理 |
| B：期間觀測 | 查看期間指標、追查數字與來源、區分目前資源與過去活動 | 聚合、證據分頁、歷史涵蓋說明、更正及排除 |
| C：復盤與調整 | 補記站外進展、接收提醒、保存復盤、調整目標與接續原功能 | 快照、復盤修訂、草稿、提醒、重要變更與並行保護 |

每批須同時完成前後端、必要測試與可操作入口。A 不是只有空的目標 CRUD；B 不是只加無法查證的數字；C 不只是一份評分表。

**必要歷史捕捉在 A 啟用。**B 才開始保存會漏掉 A 上線至 B 上線之間的活動。C 的復盤與補記資料表可到 C 才建立；不能因一次設計全部能力，就要求第一批一次建完全部畫面。

## 3. 補齊的功能決策

### 3.1 預設指標：少量預選，逐項可關閉

建立目標時，站內追蹤預設不啟用。使用者啟用來源並選好對象後，預選該來源的少量指標；提交前可取消。取消所有指標仍可保留來源，供看板取用。

| 啟用來源 | 預選 | 可另外啟用 |
| --- | --- | --- |
| 卡片 | M01 目前相關卡片、M02 本期新增、M03 本期修改過的卡片 | M04 修改日、M05 今日回顧、M06 再次運用 |
| 實驗／探索線 | M07 相關脈絡、M10 本期新增發現 | M08 方法存量、M09 發現存量、M11 新方法、M12 整理次數、清除發現數 |
| 作品 | M13 目前階段、M14 本期初版完成 | 不增加虛構寫作次數 |
| 展品 | M15 目前展品、M18 本期價值產出 | M16 入藏、M17 試煉嘗試／通過 |
| 無站內追蹤 | 無自動指標 | M19 站外量與 M20 自評由使用者選用 |

總覽每個目標最多預覽 3 項，由使用者排序；詳情顯示全部已啟用項目。更多指標不等於總覽新增更多列。

M06 的「再次運用」具體限定為：已存在的卡片被加入所追蹤探索線的材料／成果，或所追蹤作品的來源。按卡片去重；移除後再加不變成另一張。單純看過、修改標籤、放進目標來源都不算再次運用。

來源設定、歷史保存、畫面顯示分開。關閉某項指標只影響呈現，不刪既有事實；只要來源仍受追蹤，就持續保存本功能已定義的必要事實，日後重新打開可讀原已捕捉資料。完全移除來源則停止未來匹配，既有歷史保留。

### 3.2 期間、啟用起點與舊資料

- UI 起訖日期包含當天，時區沿用 `Asia/Taipei`；後端以起日 00:00 至迄日次日 00:00 的半開區間查詢。
- 分開保存目標期間、功能可記錄起點、各版追蹤規則生效時間與結束時間。
- 目前資源立即包含既有內容；加入一件舊作品不增加本期新作品。
- 原生日期可證明且原資料仍在時，可顯示「依目前保留資料回算」，例如卡片建立、試煉及收益日期；不宣稱是當時完整歸屬。
- 功能啟用前的內容修改、已清除發現、所有作品階段，不補造歷史。顯示「自某日開始記錄」，不是 0。
- 歷史精確指標與舊資料回算分開列出涵蓋說明，不混成一個聲稱完整的數字。
- 新增追蹤來源以保存成功後生效，不自動將舊活動追溯歸入。舊資源仍立即可讀；此版不提供整期自動重算歸屬。

### 3.3 暫停、到期、完成與重啟

- 暫停停止一般提醒，也退出「所有進行中」預設看板範圍；自選仍可閱讀。
- 暫停期間若仍在目標日期區間內，且來源仍追蹤，活動照常記錄並標註當時目標暫停，不暗中遺失；復盤可選擇是否視為重要進展。
- 到期只顯示待回顧；不自動完成、失敗或刪來源。期間後的資料不計入本期。
- 完成／結束保存 `closedAt`，關閉一般提醒；關閉之後的站內操作不再新增該段目標活動歸屬。
- 若想繼續追求，提供「建立後續目標」，可複用來源與期望但重新選期間；不默默重新打開已結算期間。
- 誤按完成可撤回為進行中，必填原因、留下重要變更；沒有捕捉的關閉期間活動不自動補回。
- 延長已到期目標保留原期限變更紀錄。延長後從當下繼續捕捉；空窗列為涵蓋缺口，不假裝中途都有記錄。

### 3.4 個別補入、排除與更正

- 卡片來源支援個別補入與排除；對此目標的排除優先於標籤、實驗與作品帶入。
- 實驗／探索線／作品／展品可直接選取或移除；整個實驗可另排除指定探索線。
- 期間證據支援「不計入本目標此次證據」，保留理由與更正資訊，不刪原事實、不卡住其他目標。
- 「未來不再追蹤這張卡片」與「排除這次證據」提供不同操作及確認文字。
- B 提供更正；A 保證歸屬與規則版本先保存。不能等 B 才決定過去的歸屬。
- 已保存復盤維持原快照；更正後只影響新查詢，另顯示「此區間後有資料更正」。使用者明確修訂復盤才建立新版本。

## 4. 目標材料範圍與看板演算法

### 4.1 明確的卡片來源

候選為下列卡片的聯集，再套用 owner、封存／暫停篩選與個別排除：

1. 符合所選標籤的卡片；同一標籤條件群可選任一／全部符合。
2. 指定探索線已關聯的 MATERIAL 及 RESULT 卡片；追蹤整個實驗則包含其未被個別排除的探索線。
3. 指定作品的既有卡片來源。
4. 個別補入的卡片。

不從作品正文、展品文字或歷次整理長文解析新來源；只追蹤展品不自動把全庫卡片納入。未設卡片來源的目標顯示「尚無卡片來源」。

規則保存前預覽數量與原因；取消不改設定。看板的範圍修改只影響取用材料，不能把全部候選寫入目標的永久關聯。

### 4.2 五張、輪替、去重與資料量

- 看板查詢固定每批 5 張摘要；上一批只保存 ID，回看時取最新內容與權限結果。
- 每輪有前端生成的 seed、選定目標 ID 集合、篩選、查詢游標及已展示 ID；全部為裝置內工作階段資料。
- 伺服器以 seed 建立可重現順序，採 keyset 游標續查，不使用每頁重新 `random()`。
- 同卡符合多目標時，以 seed 與選定目標集合決定唯一的分組歸屬；其他符合原因仍可展開。
- 不同目標分組輪流取 1 張，湊滿 5 張；某分組用盡由其他分組補上。這能給小目標出現機會，同時保證同一候選只占一個位置。
- 分組內使用穩定排序鍵及 ID 作平手判斷。游標帶各組位置與下一組起點，限制為目前 owner、seed 與篩選指紋，不接受任意跨帳號游標。
- 使用者切換目標／篩選後明確開始新輪；上一輪暫存不混入新範圍。
- 看板不要求整個材料池永久凍結。資料新增或標籤變更可能改變可用範圍；本輪可看見的資料仍以讀取時權限為準，重新洗牌取得最新完整範圍。
- 目標集合在一輪開始時確定；動態全選遇新啟動／暫停目標時提示「目標範圍已變更」，刷新後開始新輪，不偷偷在第三批插入另一套範圍。
- 卡片刪除、封存或來源失效時跳過，不呈現死連結；不為湊滿 5 張重複已展示內容。
- 因並行變更仍重複取得 ID 時，前端防重並使用回傳游標繼續；需限制單次補查工作量，不能在一個請求掃完整庫。補查未滿可先呈現現有張數，不誤報整輪已結束。
- 只有所有分組確定無後續才顯示「本輪已展示完」，提供洗牌與調整目標。

不將全帳號正文或整個卡片池下載至前端。排序雜湊的效能需實測；若候選很大，先評估查詢與索引，不能因為需要穩定順序就預先增加永久閱讀輪次表。

### 4.3 裝置內接續與帳號偏好

| 資料 | 保存方案 | 失效／衝突 |
| --- | --- | --- |
| 全選／自選、目標 ID、暫停與封存篩選 | 伺服器帳號偏好，明確套用後保存 | 帶版本；衝突顯示重新載入或覆蓋確認，不默默丟掉另一裝置設定 |
| seed、游標、已展示 ID、目前批與上一批 | owner 隔離的 `sessionStorage` | 同分頁刷新可接續，24 小時過期；關閉分頁後可開始新輪 |
| 卡片內容 | 原有伺服器與查詢快取 | 不在 sessionStorage 保存正文或筆記 |

不同裝置及新分頁不承諾同一輪。再次進入時先讀帳號偏好；若偏好指紋與本地輪次不同，重開一輪。卡片內容、來源可用性須重新確認，舊暫存不代表永久存取權。

選單保存自選中暫停／完成目標並繼續使用。刪除的目標提示並移除無效 ID；變成封存則從本版可選範圍移除並提示，不能靜默退回全選。自選變成空集合保持空狀態。

頁面正在閱讀時另一裝置改偏好，不自動跳換眼前卡片；重新進入、使用者刷新或主動套用時取回新設定。登出、切帳號清理本地輪次與帳號查詢快取。

## 5. 各畫面的具體操作與回饋

| 畫面／流程 | 使用者行為 | 保存與回饋 | 空白、失敗及手機處理 |
| --- | --- | --- | --- |
| 總覽目標區 | 看固定目標、進看板、接續、復盤 | 每目標最多 3 項預覽；點數字到明細 | 無固定目標顯示簡短入口，不插入空作品；錯誤保留原區塊並重試 |
| 管理目標列表 | 搜尋、依狀態篩選、建立、固定、排序 | 顯示符合數量；局部操作完成後更新摘要 | 無目標與無搜尋結果不同；不強迫建立作品 |
| 建立／編輯目標 | 必填名稱與期間，選填期待、動機、圖片、提醒 | 一次提交；成功顯示剛建立的目標與設定 | 驗證失敗保留輸入；離開未存草稿需攔截 |
| 來源設定 | 分類搜尋既有對象，選取、預覽、補入與排除 | 顯示已選摘要與符合數量；確認才生效 | 不同類型分頁切換不丟已選；失效來源列原因 |
| 目標詳情 | 看目前期待、期間證據、歷程與接續 | 現況與期間區塊分開；數字帶涵蓋起點 | 未啟用面向完全不呈現；站外目標仍可正常使用 |
| 獨立目標看板 | 選目標、套用、上／下一批、洗牌、開卡片 | 顯示候選總數、本批實際數；展示不當閱讀完成 | 0 來源、0 選取、0 符合與查詢失敗分開，不退回全庫 |
| 全站目標徽章 | 點旗幟與數量 | 彈層列目標名稱、狀態、符合原因與詳情連結 | 0 隱藏；鍵盤可開、手機點擊；阻止外層卡片導航 |
| 期間證據 | 點指標、看分頁明細、開原內容、排除 | 顯示活動發生日、來源狀態、捕捉方式與原因 | 原文已刪仍可呈現必要事實，不給假查看連結 |
| 復盤工作區 | 回看、選填自評、收穫、做決定、保存 | 保存當時快照；成功進已保存復盤，可接續下一步 | 有草稿可恢復；不要求逐筆看完，手機採單欄步驟 |
| 重要變更／完成 | 看前後差異、填原因、確認 | 目標演變保留當時設定；完成與收穫分開 | 取消不改資料；並行衝突先取新版，不覆蓋他人／另一裝置改動 |

### 5.1 總覽密度與目標詳情

- 固定目標區放在總覽頁首主要內容之前，預設展開最多 3 個目標，更多由「查看全部」進管理；數量上限只是首頁預覽，不限制建立。
- 每筆使用名稱、期間／狀態、最多 3 項數字與一列主要操作。不把全部追蹤來源與證據塞進摘要。
- 顯示上一項決策或接續對象；沒有則不保留空列。依視窗寬度換行，不壓縮原實驗十筆的摘要能力。
- 詳情採既有 DetailShell 主內容／側欄組合；手機單欄。歷史全文按需開啟，初次不載入所有復盤。

### 5.2 圖示與識別色

使用既有套件 `Flag`，業務元件暫名 `GoalBadge`。樣式參照 RecordCount，互動參照 RecordHistoryTrigger，不能直接讓所有純統計都變成按鈕。

色彩使用專用 token `--goal-color`、`--goal-bg`、`--goal-border`，分明暗主題；具體色值在實作時參照目前 token 選柔和紫色並驗證對比，不在需求文件硬塞未驗證的色碼。一般藍色主按鈕與錯誤／警告不改色。

徽章計數為未封存相關目標，按目標去重；關聯原因可能多個。列表先批次取得 count，展開時再取名稱與原因，避免每張卡片一個請求。

## 6. 資料結構方案

### 6.1 建議拆分：完整能力共 10 張新表

以下選擇關聯明確且表數可控制的方案，不再把「六類責任」說成必然六張表。完整版本建議 10 張新表，A 建立其中 8 張，C 再加 2 張。實體名稱為規劃，正式 SQL 須依實際 schema 核對。

| 表 | 儲存資訊 | 建立批次 |
| --- | --- | --- |
| `goals` | owner、名稱、期間、期待、動機、圖片、狀態、封存、固定順序、提醒設定、closedAt、version、前一目標 ID | A |
| `goal_rule_revisions` | 目標的追蹤設定版本、生效起訖、來源／指標選項、變更前後設定及原因；期待／日期的重要變更也記於此演變 | A |
| `goal_tracking_sources` | 所屬設定版本、納入／排除、對象種類與具體對象外鍵、必要的最小辨識資料 | A |
| `goal_activity_facts` | owner、事件種類、來源識別、操作防重鍵、發生時間／日期、登錄時間、必要數量、最小去向、有效／更正狀態 | A |
| `goal_fact_links` | 事實與目標／規則版本的歷史歸屬、納入原因、歸屬明細／數量、是否排除與更正理由 | A |
| `card_content_days` | owner、卡片歷史識別、Taipei 日期；唯一鍵為 owner＋卡片識別＋日期，不存儲存次數或正文 | A |
| `goal_card_day_links` | 每日摘要與目標／設定版本的關係、必要納入原因 | A |
| `goal_board_preferences` | 每 owner 一筆，全選／自選、目標 ID 集合、卡片篩選、version | A |
| `goal_logs` | 站外補記、自訂量、變更更正理由等使用者主動內容，發生日期／登錄時間、version；各類型分別驗證 | C |
| `goal_reviews` | 目標、區間、快照、評分、心得、決策、草稿／已保存、修訂序號與前一修訂、version | C |

`goals` 的提醒排程狀態與看板偏好不同；提醒可用欄位保存下次時間、稍後時間、最後復盤截止，不需為每次提示建永久曝光表。

### 6.2 關聯與資料完整性

- `goal_tracking_sources` 使用 tag／experiment／thread／work／treasure／card 六個可空的具體外鍵欄位，限制每列恰好有一個有效種類，並檢查種類與欄位一致；不採沒有約束的任意 `type + id` 當即時關聯。
- 來源的活連結可在原對象刪除時失效；原始識別與設定版本仍可保留最小歷史參考。失效列不能靠錯誤 ID 繼續提供連結；外鍵置空與來源狀態轉失效須一致處理。
- 上述「恰好一個外鍵」適用有效來源；失效來源允許所有活外鍵為空，但須有失效標記及最小歷史識別，資料庫約束須涵蓋兩種狀態。
- 每個關聯新增與讀取都檢查 owner；來源 owner 不直接由傳入 ID 推定。
- 歷史事實中的來源 ID 是歷史識別，不能因原對象刪除就級聯抹掉事實；活連結另經 owner 查核。
- 設定版本生效後不可就地重寫；新設定關閉舊版生效範圍。一般名稱錯字修正不改追蹤版本。
- 事實只保存一次，多目標用 links 歸屬，不複製完整事實。
- 一次整理可同時涵蓋多條探索線；事實保留各線實際清除明細，link 只計入該目標追蹤部分。同時選實驗與其探索線不能重複累加；不能因目標只追蹤其中一線，就把整個整理的清除總數灌入。
- 每日摘要每卡每日一份；同日每次實際修改仍重新評估當下目標歸屬，必要時新增 link。不能因上午已有摘要，就漏掉下午新啟用目標的關係。
- link 可按目標／每日摘要／設定版本唯一；跨版本統計必須依卡片或日期去重，不將多版 link 算多次加工。
- 快照使用有版本的結構化 JSON 保存指標定義與當時值，非任意原文備份；關聯查詢仍走明確欄位與表，不用 JSON 全表掃描。

### 6.3 現有表與回應的異動

- `cards` 新增可空 `content_updated_at`；不回填 `updatedAt`，新卡片先 null。
- 不加 `is_goal_tracked`，不加卡片閱讀批次、目標已看時間或每目標回流日期。
- 回應可增加 `contentUpdatedAt` 與衍生 `goalCount`；大量清單優先由關聯摘要批次 API 回傳，避免所有領域 DTO 一開始全部膨脹。
- 個別領域若需持久事件防重鍵，可新增精準欄位／約束；不能拿通用 updatedAt 當事件 ID。
- A 前須列出原始資料表的實際欄位、索引、外鍵與刪除路徑。未核對前，本文件不提供可直接執行的 SQL。

## 7. 歷史事實、每日摘要與時間口徑

### 7.1 必須接入的成功操作

| 操作 | 保存方式 | 防重／歸期 |
| --- | --- | --- |
| 卡片建立 | 建立事實 | 原卡片 ID 唯一；新增追蹤不製造另一建立事實 |
| 筆記／正文修改 | 更新內容時間、每日摘要與當下 links | 同卡同日唯一；比較實際保存值，正文與筆記同次只處理一次 |
| 今日完成回顧 | 回顧事實 | 一次真正成功操作一個識別；非每次詳情 GET |
| 探索方法／發現新增 | 建立事實 | 原建立對象識別；規劃與實際行動不同 |
| 探索整理 | 整理事實與各探索線清除明細 | 已有 requestId 防重，長期事實另保存；一次整理不因涵蓋兩條線算兩次 |
| 卡片加入追蹤探索線／作品來源 | 再次運用事實 | 加入關係的成功操作；主指標仍按卡片去重 |
| 作品階段／初版日期更改 | 階段事實及完成事實的修訂 | 同一作品首次完成不因反覆切階段增加作品數 |
| 展品入藏 | 入藏事實 | 展品 ID 去重，與作品完成分開 |
| 試煉／收益 | 既有逐筆紀錄＋必要的歷史歸屬與最小事實 | 實際發生日與 createdAt 分開；修改日期明確更正 |

只在有相應目標追蹤且符合期間時保存必要歸屬；不是建立全帳號所有操作的通用稽核平台。沒有被任何目標追蹤時，卡片仍更新 `content_updated_at`，但不要求永久保存每日摘要或其他目標事實；日後啟用顯示真正涵蓋起點。

### 7.2 交易與防重

- 原操作與事實／摘要在同一資料庫交易中成功或回滾；第一版不引入訊息佇列或非同步事件最終一致性。
- 已有交易的 service 可呼叫專責 `GoalActivityRecorder`，避免在 Controller 複製規則。
- 記錄器失敗不能吞掉導致原操作成功卻漏計；以交易失敗與既有錯誤回饋處理，需評估鎖競爭。
- 沒有 requestId 的可重試寫入，規劃增加可選的客戶端請求識別並持久防重；舊客戶端相容，仍以 domain ID／狀態版本提供最低防重，不把十秒內所有操作合併。
- 目標來源變更與事件同時發生時，以每 owner 的共同設定／歸屬鎖或等價一致性策略排序；同一 owner 的寫入遵守固定鎖順序，避免讀到半套來源。
- 未開始目標到日啟動須由同一狀態規則統一處理，讓列表、動態全選、事實匹配及提醒一致；不能只靠使用者先開過目標詳情才啟用。具體以既有排程搭配查詢／寫入前狀態核對實現，並涵蓋停機跨日後恢復。
- 記錄器只需追加當下歸屬，不同步重算所有目標面板；事實與 links 索引、鎖等待及交易時間須在 A 驗證。若共同鎖造成瓶頸，再以可證明一致的設定版本讀取方案替代，不直接移除並行保護。
- 同日摘要採資料庫唯一約束與原子 upsert；不能先查沒有再各自 insert。
- 不保存逐次卡片儲存事件；若有重要突破，由復盤選取內容與自行解讀。

### 7.3 證據刪除與修訂

目前內容刪除會改存量；已捕捉的發生事實與使用者復盤可保留，不複製原文全文。來源標題等最小摘要在刪除時清為「已刪除來源」，保留 ID、日期、事件類型及必要數量供統計，不繼續揭露已刪正文。

個別「刪除原內容」與「清除目標歷史」明確分開。使用者刪除目標，刪其 links、設定版本、來源、補記與復盤；共享事實仍供其他目標使用，無任何引用者可一併清除。owner 刪除則新資料全部清除。

試煉／收益在原領域刪除屬紀錄更正，預設使未保存復盤的現行查詢排除該筆，但保留最小修訂標記，避免把更正誤當永久有效進展。已保存復盤不自動重算；如使用者明確要求清除相關歷史，另清快照中的對應參考／辨識資料，不能承諾刪來源就還原所有過去全文。

## 8. 復盤、提醒與重要變更

### 8.1 草稿與保存

- C 新增伺服器草稿：首次開始復盤時建立，後續文字／評分變更防抖保存，顯示保存中、已保存、失敗重試。
- 草稿與正式快照不同。草稿的指標可手動刷新；正式提交以伺服器重算截止時資料並固定快照，不以舊前端數字直接入庫。
- 保存時回傳統計截止點、規則版本及資料涵蓋；提交期間如有設定並行變更，回傳衝突並保留輸入，重新確認後再提交。
- 一份草稿帶 version；手機電腦可以接續復盤草稿，但不是接續目標看板輪次。遇其他裝置改稿不自動覆蓋。
- 已保存內容修訂以 `previousRevisionId` 串下一筆，使用者看到最新修訂及歷史；同一區間不因此算成兩次完成復盤。

### 8.2 評分、補記與重要變更

- 自評各題可略過或選不適用，不把空值轉為 0。採 1～5 並顯示文字端點；至少選一項本次決定，可維持原安排。
- 資訊幫助：1 幾乎無幫助、3 部分有幫助、5 明顯支持判斷；行動有效性及結果推進依同樣有意義端點呈現。
- 方向認同為獨立選項：認同／想調整／不確定／不再追求，不混成達成分數。
- 手動量定義名稱及單位，原始登錄與增減更正分開；更正需理由，不直接改系統卡片／發現筆數。
- 期望、期間、狀態、來源範圍變更列為重要變更；理由可選常見原因加選填文字。完成撤回、已保存復盤修訂與手動量更正必填理由。
- 名稱錯字、圖片、動機文字一般修正直接保存，不自動截完整統計快照；編輯期望欄位不依 AI 判斷是不是錯字，確認時顯示前後差異。
- 復盤先保存策略，變更原實驗／作品下一步仍開原表單確認；取消該表單不影響已保存復盤，也不偷偷修改原資料。

### 8.3 提醒排程

- 預設 7 天，提供 14／30 天與自訂 1～365 天，可關閉；沿用 Taipei 日期。
- 當日 09:00 起可提醒；使用者下次進站才呈現，不建 Email 或關站推播。
- 未開始不提醒；暫停停止一般提醒。恢復後若已到期顯示期末回顧，否則已逾復盤日則下一次進站提供一次合併提醒。
- 首次區間起於目標開始日；後續起於上次正式復盤截止。提前復盤後重新排下次，不建立重疊的正式區間。
- 漏期合併為上次截止至本次；不補出多份欠交表單。不同區間天數在比較時一併顯示。
- 稍後提醒預設明日 09:00；使用者可選 1 小時後，存於伺服器，避免每次換頁再跳。
- 多目標到期合併成單一入口，正在編輯不搶焦點；以站內提醒元件呈現，不為每個目標依序開 modal。
- 到期顯示期末回顧，固定本期期限；如需要納入期限後活動，必須先明確延長並顯示涵蓋缺口。

### 9.2 Contract 必要欄位與錯誤

- 所有目標寫入帶 version；可重試建立／提交帶 requestId。409 代表版本或提交衝突，表單保留使用者輸入。
- 指標回應至少包含 metricKey、value、unit、mode、period、coverageStart、coverageStatus、definitionVersion；`UNKNOWN` 不用 0 代替。
- 證據有來源是否可用、發生日期／登錄時間、納入原因、規則版本、排除與更正資訊。
- 看板回傳卡片摘要、相關目標原因摘要、候選去重總數、nextCursor、hasMore、當次範圍指紋；不寫卡片時間或計數。
- 游標失效回傳可辨識錯誤及重開一輪動作，不能默默換成全部卡片。
- 權限錯誤不透露其他 owner 對象名稱；查無來源與查詢失敗分開。
- 未開始、無來源、未啟用、無歷史涵蓋與真正零值有明確 enum，不只靠前端文案猜測。

## 11. 查詢、效能與可觀察性

- 總覽只取固定目標及選定指標，不在登入後一次載入全部事實、正文與復盤。
- 各領域先分組聚合再合併，不把卡片、發現、試煉、收益一口氣 JOIN 造成乘積。
- 事實索引以 owner／目標歸屬／種類／日期為主，sources 需可反查對象；每日摘要唯一鍵需包含 owner、歷史卡片識別及日期。
- 過去精確歸屬讀 links，不為每次查詢重新對目前標籤做歷史推定。
- 目前存量與歷史總量分開端點／查詢，來源加入／移除使當前資源更新，但不回寫過去快照。
- A 檢查 owner 鎖與記錄器的額外寫入成本；B 再量測多目標、長期間、大材料池的聚合及看板排序。
- 使用既有測試或隔離測試資料，比較 SQL 次數、查詢計畫與 API 耗時；報告實測 p50／p95 及資料規模，不預先承諾未測的延遲。
- 若穩定排序需要額外索引／快取，以量測決定；快取須帶 owner、規則版本與來源更新失效，不能先引入物化檢視再處理一致性。
- 交易失敗、重試衝突、無效游標等使用既有日誌記錄必要識別，不輸出使用者全文與 token。

### 16.3 目標看板

- 頁首左側保留標題及說明；右側為目標範圍、範圍設定與管理目標。窄螢幕換行，不縮字硬塞。
- 範圍選單表達「所有進行中目標／自行選擇」。選擇自行選擇，或點範圍設定，開啟同一個約 680px 的設定彈窗；簡單範圍切換也須確認後才改寫偏好與閱讀範圍，不留下混用草稿與舊結果的狀態。
- 彈窗包含目標搜尋、狀態多選、多目標選取、包含暫停回流卡片、包含封存卡片。預設仍包含暫停卡、不包含封存卡。
- 候選搜尋使用查詢／Enter；已選集合跨頁及狀態篩選保留。自行選取未開始、暫停、完成、結束的未封存目標仍可閱讀；動態全選仍只取進行中。
- 取消不保存偏好、不開始新一輪、不改原批次。確認後以既有 version 保存偏好，成功取得新資料才切換已套用範圍與摘要。
- 偏好保存成功但卡片查詢失敗，保留原批次，提示新設定已保存但材料未載入，提供重試；不可將兩個 API 假裝為原子交易。重新開啟設定以最新偏好 version 為準。
- 集合上方灰底外只顯示「已選 N 個目標 · 相關卡片 M 張」，不顯示本批五張。N 由本次伺服器實際納入範圍取得；M 為同範圍、相同卡片篩選後的去重總數。
- 灰底集合僅呈現卡片、載入、空狀態或失敗回饋；上一批／下一批／重新洗牌放集合下方，不塞回灰底內。五張分批、去重、原排程不變與同分頁接續規則維持。
- 沒有可用目標、未選目標、無卡片來源、來源無符合卡片分開說明；不回退全卡片池。

### 16.4 管理目標、手動查詢與排序

- 條件分為搜尋文字、狀態多選、封存範圍（未封存／已封存／全部）；同類狀態採任一符合，空狀態集合表示全部狀態。
- 初次開頁以預設條件查詢一次。編輯條件只更新 draft；查詢／搜尋欄 Enter 才複製為 applied 並回第一頁。條件未變時按查詢可重新取得目前資料，不產生兩次請求。
- 重設只還原 draft，不立即查詢。分頁使用 applied；更新中保留原結果與原範圍說明，成功後才更新筆數，失敗保留原結果並提示重試。
- 卡片保留名稱、狀態／期間、期望摘要及已開放的已選數據；編輯、固定／取消固定、封存／還原與刪除依操作層級呈現。
- 主表單不再提供 `pinOrder` 數字輸入。管理頁另提供「排列固定目標」入口，以目前全部未封存固定目標的緊湊列表上移／下移，不依一般列表當頁或草稿篩選推算全局相鄰目標。
- 排序每次由伺服器單一交易調整，使用 owner 鎖、選中目標與相鄰目標的預期版本／ID 核對。必要時正規化為連續非負順序，只更新異動資料，並透過既有保存責任同步 version 與 revision。衝突回傳 409，保留畫面並重新取得排序，不靜默覆蓋。
- 排列入口讀取全部固定目標時按既有分頁載入，未載入完整集合前不開放移動；一般列表仍維持伺服器分頁。

### 16.5 主表單與來源子流程

- 主表單寬度 `min(680px, calc(100vw - 32px))`，來源子畫面為 `min(760px, calc(100vw - 32px))`。沿用 AppDialog 單一外殼，不疊加第二個大型彈窗，不使用強制建立精靈。
- 主表單順序：名稱、期間、期望結果；背景與封面（收合）；追蹤內容摘要／管理入口；想顯示的數據；其他設定；編輯原因。移除重複「目標內容」大標題。
- 新建開始日取 Asia/Taipei 今天，結束日取今天加 7 個日曆日。變更開始日期不默默覆寫結束日期；結束早於開始時提供欄位錯誤。編輯保留原日期。
- 期望結果提供例子，例如「完成三次人物衝突練習」，保留原上限。名稱、日期、字數與封面沿用既有控制及語意 token。
- 狀態仍單選；固定於總覽仍可設定。封存／還原與刪除移到目標操作，不在建立表單詢問封存。提醒及復盤偏好集中在「尚未開放，目前僅保存偏好」區，保持既有值，不開始發送提醒。
- 來源子畫面使用分類、明確查詢、單欄候選與可展開的已選摘要，選取跨分類／分頁保留。來源預覽只驗證來源、owner 與比對方式，不要求先填目標名稱或期間。
- 正常納入來源與例外分組顯示、分開計數；來源摘要計數不把例外冒充納入數量。已刪除／不可用來源明示並提供移除，不建立假連結或靜默丟掉原設定。
- 子流程有獨立來源草稿。確認來源只帶回父草稿；取消變更／返回／子畫面的 ×／Esc 放棄本次未確認來源並回父表單，保留父內容。此行為沿用 DESIGN_SYSTEM 9.2 的來源管理限定例外；不修改全域 AppDialog 關閉語意。
- 父表單 ×／Esc／取消檢查整份已確認草稿；路由離開若子畫面有未確認選取，也須納入放棄確認。確認來源、切換子畫面與動態寬度不得重設父層初始比較基準。
- 返回恢復主表單原捲動位置及來源入口焦點。真正儲存仍透過現有 POST／PUT 一次提交完整目標、來源、例外及指標偏好，保留開啟時基準 version；失敗不清空草稿。

### 16.6 來源例外與指標偏好

**來源例外：**一般已選來源拿掉「排除這個來源」checkbox，另設預設收合的「例外設定」。

- 不納入的卡片：對這個目標的卡片範圍優先扣除，即使經標籤、探索或作品匹配也不納入。
- 實驗中不追蹤的探索線：置於對應已選實驗下，僅影響該實驗帶入的範圍；其中卡片仍可經其他標籤或作品納入。透過所屬實驗辨識，不把它描述為全局卡片封鎖。
- 「移除來源」只停止該規則自動納入；「取消排除」只移除例外。兩者均不刪原資料，不改其他目標，不抹除歷史。
- 同一種類／ID 不同時納入與排除。移除實驗但仍有其探索線例外時，提示調整或明確確認一併移除；不得靜默刪除。既有沒有對應實驗的探索線例外保留並標示未作用，供使用者取消，不自動擴大效力。
- 兩個以上納入標籤時才顯示「符合任一／符合全部所選標籤」選項。此設定只控制標籤分支，其他來源仍採聯集。
- 來源規則變更必須使預覽失效，含取消排除、標籤比對方式與子流程返回；過期回應不能覆寫新草稿的預覽。

**指標偏好：**區塊改名「想在目標中看見哪些數據」，保留 M01～M20 與 metrics 陣列，不新增資料表。

- 按卡片、實驗／探索線、作品、展品、自行補充分組；每項附說明、單位、來源條件與目前可用性。M04 明示為「有內容修改的日期」，M05 為「本期完成今日回顧的卡片」，不使人誤認為單一時間戳或只有今天。
- 依來源提出少量建議，使用者按「採用建議」才更新勾選，取消過的項目不在新增來源時偷偷恢復；不再由 choose() 自動追加指標。
- 目前可用區只呈現已實作的 M01；其餘原有選項可於清楚標示「尚未開放，目前僅保存顯示偏好」的區域展開調整。保留既有勾選與順序，不刪能力或顯示假零值。
- 與所選來源無關的未選指標不預設攤開；既有已選但失去來源的指標仍可見並提示，由使用者取消或補來源。M19／M20 在無站內來源時仍可保留偏好，實際手動填寫仍待 C。
- 首頁最多三項是顯示上限，不代表現在實作完整聚合；關閉顯示不停止已追蹤來源的必要事實保存、不清除既有歷史。

### 16.7 詳情與總覽

**目標詳情：**保留 DetailShell／DetailHeading 與共用面板，桌面主內容＋補充側欄，900px 附近依可用寬度重排，手機按 DOM 閱讀順序堆疊。

- 頂部為返回、編輯及更多操作；封存／還原、刪除收在更多操作，破壞性動作沿用確認。
- 名稱、狀態、期間成組；有期望／動機才顯示閱讀區。沒有期望時使用主題附近的一行中性提示與編輯入口，不保留大型空卡。

- 總覽順序維持固定目標、全部既有實驗摘要、接著創作、成果／待留意、全站積累。實驗仍保留最多十筆及既有記錄／歷程／快捷操作，無作品／展品不出現空成果區。

### 16.8 API 與資料相容計畫

| API | 預計變更 | 相容與驗證 |
