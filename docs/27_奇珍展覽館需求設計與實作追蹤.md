建立：2026-10-14；現行規則核對：2026-10-16。程式已完成自動測試與建置；瀏覽器人工驗收及遠端資料庫部署仍須分別確認。

第 1 至 7 節整理目前規則與交付邊界；第 8 至 23 節保留各時點的驗證及需求演進，不代表現行規格。第 24 節記錄本輪核對結果。產品初衷見 [MVP 第 14 項決策](ECHO_GALLERY_MVP.md#14-20261016-奇珍展覽館與成果持續產生價值)，跨功能的視覺與互動規則見 [設計系統](DESIGN_SYSTEM.md)。目前行為仍以原始碼與測試為查核依據，文件不替代資料庫部署與人工驗收。

## 1. 需求與邊界

奇珍是使用者主動收錄的已完成作品、專案或成果。Card 保存值得回流的內容；Experiment 承接自主探索、試法與發現；Treasure 承接已完成成果、現實考驗及持續產生的價值。三者可獨立存在，來源關聯為選填，不強迫經過固定轉化流程，也不消耗原內容。

四階成長提供方向，由使用者設定具體檢定與確認結果，不以資料量兌換等級。沒有自動合成、人生評分、AI 判定、公開作品頁或配方系統；奇珍也不共用 Card 的回流排程。價值不等於金錢，保持原級珍藏亦是有效使用方式。

本文件追蹤奇珍的業務規則、交付及歷史；MVP 說明產品定位與取捨，README 提供入口與啟動資訊，設計系統維護可跨功能使用的介面原則。

## 2. 已確認的操作規則

### 館藏與封存

- 新收錄成果一律從石級開始；保存名稱、說明、完成日期，作品網址與封面來源連結為選填。
- 提供館藏／已封存列表、名稱搜尋、等級篩選、分頁、詳情、編輯、封存／還原與確認後永久刪除。
- 封存後仍可編輯成果內容及新增價值產出，列表、詳情與產出歷程均提供入口；新增產出不會自動還原成果。
- 封存期間不能新增／修改檢定、記錄嘗試，亦不能修改／刪除既有價值產出。這與允許新增產出的規則分開處理。

### 檢定與嘗試

- 石級是完成成果並入藏的起點；銅、銀、金各最多一份檢定定義，可預先設定未來階段。
- 只有目前下一階可記錄嘗試，必須依序晉級，不可跳級；已通過的定義不可再修改。
- 定義狀態為準備中、已嘗試、未通過、已通過；每次嘗試新增獨立紀錄，結果為待確認、尚未達成或已達成，並保存當時的檢定名稱與通過條件快照。
- 未通過不降級，可調整尚未通過的定義後重試；新嘗試不覆蓋先前經驗與條件。確認通過須由使用者主動操作，後端於交易中核對 owner、下一階及既有通過狀態。
- 金級後不再新增更高階或無目標等級的檢定，仍可記錄價值產出。歷史章節中的「金級後試煉」「同階多筆檢定」「取消狀態」屬已取代方案。

### 價值產出與成果脈絡

- 產出保存名稱、發生日期、選填的過程與價值，以及最多一張相關卡片；沒有必選分類或獨立外部網址欄位。程式沿用 `Yield` 命名，畫面使用「價值產出」。
- 一段整理、發表、分享與後續回應可記成同一筆，不要求每個步驟拆開；尚無回應也可記錄。發生日期與登錄日期分開，不可填未來日期。
- 詳情只預覽最近 3 筆，超過範圍時明示「最近 3 筆」；「產出紀錄」顯示全部總數並開啟完整歷程。名稱與描述可截斷，但保留相關卡片入口；完整歷程可閱讀全文並新增紀錄。
- 來源維持一張卡片、一個實驗及最多 20 件既有奇珍；本輪沒有擴大成卡片或實驗多選。來源須同 owner，不可自指、重複或形成循環；新成果不繼承來源等級。
- 來源與衍生方向須明確；刪除來源只解除連結，不刪除已完成成果或其價值產出。

## 3. 資料與權限設計

`treasure` 套件沿用 Java 21、Spring Boot、JPA、目前登入者與可測試 Clock。

| 實體／資料表 | 職責 |
|---|---|
| `Treasure`／`treasures` | owner、成果內容、目前等級、完成日期、封存、選填卡片與實驗來源 |
| `TreasureTrial`／`treasure_trials` | 所屬成果、銅／銀／金目標、每階單一定義、條件與目前狀態 |
| `TreasureTrialAttempt`／`treasure_trial_attempts` | 每次嘗試的經過、結果、時間、佐證連結及檢定條件快照 |
| `TreasureYield`／`treasure_yields` | 產出名稱、說明、發生日期及選填相關卡片；不再包含舊分類與外部網址欄位 |
| `TreasureRelation`／`treasure_relations` | 奇珍來源至衍生成果的有向關聯，不記錄合成配方或數量 |

所有查詢均依登入 owner；巢狀資源也須核對所屬成果，不得靠猜測 ID 取得其他人的資料。owner 鎖序列化晉級、關聯變更及來源刪除，避免並行繞過條件或循環檢查。

Card／Experiment 永久刪除先解除來源；Treasure 永久刪除清理自己的嘗試、檢定、產出與關聯，不刪除其他成果或原卡片。Demo 清理先清奇珍，再清實驗、議事廳、卡片、標籤與帳號，避免外鍵殘留。

## 4. 現行 API 邊界

所有介面沿用目前認證與錯誤格式；下列路徑皆以 `/api/treasures` 起始。

| 方法／相對路徑 | 用途 |
|---|---|
| GET、POST `/` | 查詢列表／收錄成果 |
| GET `/stats` | 未封存館藏的等級數量 |
| GET、PUT、DELETE `/{id}` | 詳情／更新內容／永久刪除 |
| PUT `/{id}/archive`、`/{id}/restore` | 封存／還原 |
| GET `/{id}/relations` | 分頁查詢來源或衍生關聯 |
| GET、POST `/{id}/trials` | 查詢歷史／建立某階檢定 |
| GET `/{id}/challenge-route` | 讀取各階檢定路線 |
| PUT `/{id}/trials/{trialId}` | 修改尚未通過的定義 |
| GET、POST `/{id}/trials/{trialId}/attempts` | 查詢／新增獨立嘗試 |
| POST `/{id}/trials/{trialId}/pass` | 保留的通過入口；同樣檢查順序與權限，不能繞過嘗試規則 |
| GET、POST `/{id}/yields` | 分頁查詢／新增價值產出 |
| PUT、DELETE `/{id}/yields/{yieldId}` | 修改／刪除既有產出 |

欄位契約以 [TreasureRequests](../echo-gallery-backend/src/main/java/com/echogallery/treasure/TreasureRequests.java)、[TreasureResponses](../echo-gallery-backend/src/main/java/com/echogallery/treasure/TreasureResponses.java) 與 [前端型別](../echo-gallery-frontend/src/types/treasure.ts) 為準。名稱上限 255 字、長文 50,000 字、網址 2,048 字且僅接受 HTTP／HTTPS；清單單頁最多 20 筆。檢定定義的目標必須是銅、銀或金；建立請求省略目標時以目前下一階補入，金級因無下一階而拒絕建立。`CANCELLED` 仍保留在相容用 enum 中，但新增嘗試只接受 `ATTEMPTED`、`NOT_PASSED`、`PASSED`。

Overview 保留 `/current`、`/recent`、`/card-return` 路徑；前兩者 DTO 與畫面同步納入奇珍，Card Return contract 保持原責任。前後端相關變更須一起部署。

## 5. UI 與跨功能整合

- 主導覽使用 Trophy 識別奇珍；實驗場與奇珍列表共用頁首、集合邊界、操作密度、查詢與分頁節奏。兩者保留相同的微幅上浮與淡陰影；減少動態效果偏好下取消位移。業務內容仍可有不同欄位與排列。
- 清單卡片保留完整名稱、截斷說明、等級、產出入口／數量及更多操作；挑戰摘要分開呈現等級、狀態與名稱，避免擠成一串。無逐卡追加詳情查詢。
- 實驗與奇珍詳情沿用 `DetailShell`、`DetailHeading`。目前等級使用較淺等級底色；正在查看的階段以等級框線提示，不能與目前等級混淆。設定、記錄按鈕不觸發區塊展開／收合，操作後也不改變正在查看的階段。
- 記錄表單、來源選擇器、歷程與彈窗離開行為遵循 [設計系統](DESIGN_SYSTEM.md)。新增嘗試與價值產出使用一致的欄位層級、字數提示、唯讀背景及底部操作；不要求所有彈窗同寬。
- `AppDialog` 統一離開入口與提交狀態；有草稿時在實際關閉前確認，提交期間防止重複操作或離開。唯讀歷程支援關閉按鈕、×、遮罩與 Esc；設定／記錄流程依是否有草稿保護。
- 成果來源在同一彈窗切換管理模式，避免疊加彈窗。取消或返回保留主表單草稿；確認來源只更新草稿，儲存成果才生效。候選與已選摘要沿用既有選擇器模式，各來源類型摘要一致，數量靠近群組標題。
- 卡片與奇珍共用圖片連結檢核／封面呈現；載入失敗不能顯示破圖或保留大片空間。圖片預覽失敗與網址格式錯誤分開處理，不因遠端暫時不可讀而阻止保存其他合法內容。
- 總覽呈現館藏、目前挑戰與近期轉化；封存成果不列入目前館藏與精選，但可列入期間歷史統計。產出件數與產生產出的成果件數不可混稱。統計依目前保留資料計算，並非不可變事件日誌。
- 議事廳退出主導覽及總覽；舊路由、API、資料與編輯功能仍存在，不能宣稱已完整移除。卡片／實驗可作奇珍來源，但不複製來源或改變 Card 回流規則。

## 6. 資料庫與 Demo 安全

截至本輪，使用者已回報執行本機 `20261016_treasure_local_reconcile_draft.sql`；遠端尚未建立奇珍表，整合草稿 `treasure_remote_bootstrap_20261016_draft.sql` 尚待使用者執行。這是本機與遠端各自的狀態，不能推論兩邊已同步，也不能推論測試建表已完成正式部署。

SQL 草稿保存在 repository 工作區、維持 untracked，不納入暫存、commit 或推版。歷史章節中的分段 SQL 名稱僅供追溯，不再作為逐份執行清單；部署時應先核對目標 schema 與備份，再由使用者審閱整合草稿並決定執行時機。禁止啟動應用程式讓 ORM 自動改表代替確認；完成手動建表後可用部署設定中的 `ddl-auto=validate` 檢查，不修改 `.env`。

整合測試使用 Testcontainers PostgreSQL 與隔離 owner，驗證建立、顯示、刪除來源及 Demo 清理生命週期。這些測試不代表本機或遠端 SQL 已被執行。本輪只修改樣式與文件，沒有建立本機、Demo 或正式測試資料。
