# 實驗場探索紀錄切換與人工驗收清單

本清單配合探索紀錄 T1～T12 交付使用。SQL 草稿均預設不寫入；不得由應用程式啟動自動改表。

## 已由程式驗證

- 後端完整測試：192 項通過，0 失敗、0 錯誤、0 跳過。
- 前端：`npm run build` 通過。
- 探索紀錄：新增、重送、版本衝突、主題 ANY／ALL 篩選、卡片原子建立、URL 參考、卡片刪除後只清除參考。
- 目標：M21 僅在成功建立紀錄時計一次，事件時間為建立當下；舊 `THREAD` 來源被拒絕。
- 退場：舊 exploration/activity/thread URL 回覆 410；後端不再含舊探索 Entity、Repository 或正常流程 SQL。
- Demo：探索紀錄、主題、常駐做法、作品來源與卡片參考的建立、讀取、reset、到期清理已驗證。

## 資料庫操作者的執行順序

1. 先完整備份測試或正式資料庫，並確認舊應用程式、背景工作已停止寫入。
2. 只有在全新、尚未有探索紀錄結構的資料庫才執行 `實驗場探索紀錄結構_SQL草稿.sql`。目前本機結構已建立時不可重跑。
3. 若所有環境皆確定不保留目標資料：先完整閱讀並在測試環境演練 `實驗場目標資料清理_SQL草稿.sql`。預設安全門檻會中止；確認備份與筆數後才依檔案註解改為確認值與 `COMMIT`。
4. 在隔離的還原備份／匿名資料庫執行 `實驗場探索紀錄資料轉換演練_SQL草稿.sql`。先保持 `ROLLBACK`，核對來源分類、筆數、日期、序列與殘留表；成功演練後才決定正式窗口是否改為 `COMMIT`。
5. 確認 T10 轉換結果及備份可回復後，演練 `實驗場探索線退場_SQL草稿.sql`。它會調整卡片參考外鍵、移除舊目標 THREAD 欄位並刪除舊探索表；遇到未知相依會失敗並回滾。
6. 正式切換後，以新版本啟動後端。若任一 SQL 出錯，保留原始錯誤、執行 `ROLLBACK`，由備份回復，不要挑選中間片段重跑。

## 人工驗收

### 實驗詳情與紀錄

- 在 1280px、768px、390px 檢查「起點 → 終點」方向面板、長文五行展開、探索紀錄卡片與列表切換；不可水平溢位。
- 新增標題-only、內容-only、做法-only 紀錄；檢查內容取得初始焦點、補充資訊初始收合、草稿關閉確認及儲存失敗後保留輸入。
- 編輯紀錄後檢查左右欄版面、日期、亮點、標記、主題與做法沒有遺失；刪除時版本衝突須能提示而不靜默覆寫。
- 卡片 hover、focus、pressed 後互動與既有 `CardTextMode` 一致；卡片更多選單、標籤及刪除不可誤開閱讀彈窗。
- 主題新增、改名、釘選、刪除後確認紀錄仍保留且篩選結果正確；搜尋的待套用／已套用與 ANY／ALL 結果可辨識。

### 參考、作品、首頁與目標

- 從收藏卡片建立探索紀錄，取消不應寫入；卡片詳情可看見反向參考。
- 建立作品時分別選卡片與探索紀錄來源；同一來源不可重複，紀錄被作品引用時應受保護，解除來源後才能刪除。
- 首頁最新紀錄、素材去重及實驗列表摘要正確；舊探索線入口應顯示功能已退場。
- 建立以實驗為來源、選 M21 的目標；新增一筆探索紀錄後數值加一，編輯、重送與刪除不再加計。

## 回復原則

- SQL 草稿執行前及維護窗口開始前都必須有可驗證的備份。
- 在任何草稿尚為 `ROLLBACK` 的演練中，不調整為 `COMMIT` 即不會寫入。
- 正式轉換或退場提交後，回復方式是停止新寫入、由切換前備份還原；不可用舊表 ID 與新紀錄 ID 猜測手工反轉。
