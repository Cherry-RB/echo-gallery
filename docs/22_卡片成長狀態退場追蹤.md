# Card 全域成長狀態退場追蹤

> 狀態：進行中。第一階段 UI 退場已完成並由獨立 commit 保存；資料庫與後端相容層尚未移除。

## 目的

Echo Gallery 已將「成長」的主要語意移至 Card 在特定 Experiment 中的
`ExperimentCard.stage`（種子／茁壯／成熟）。舊有的
`Card.growthStatus` 是全域、單一卡片層級的歷史模型；它無法表達同一張卡在
不同實驗中可能承擔不同角色，也容易把 Experiment 的探索過程誤讀為 Card 的
唯一成熟度。

本追蹤文件記錄舊模型的安全退場，而非重新定義 Experiment 的三個階段。

## 第一階段：停止在前端使用舊全域狀態

已完成並獨立提交的範圍：

1. 卡片詳情、卡片文字模式、議題素材與卡片查詢，不再顯示、設定或篩選
   `Card.growthStatus`。
2. 前端不再提供「標記種子」或更新全域成長狀態的操作。
3. 桌機右側統計欄與手機統計抽屜已移除；系統狀態改由資訊轉化觀測台承接。
4. Experiment 中的 `ExperimentCard.stage`、Experiment 統計膠囊與三塊土壤不受
   影響，仍是目前唯一對使用者可見的成長階段語意。

第一階段刻意**沒有**做下列事情：

- 未刪除 `cards.growth_status` 欄位或 `CardGrowthStatus` 型別。
- 未刪除既有 growth status API、Repository 查詢或相容 DTO 欄位。
- 未自動將歷史 `SEED`／`GROWING`／`MATURE` 轉換為 `needsProcessing` 或
  `ExperimentCard.stage`。
- 未以 ExperimentCard 數量替代舊全域統計；同一張 Card 可存在多個
  Experiment，直接相加會重複計數。

這是有意保留的相容期，不代表舊欄位仍是目前產品介面的一部分。

## 接續順序

在本輪「全站 Shell 與 spacing 統一重構」完成前，不將版型變更與資料模型清理
混在同一個任務或 commit。

版型重構完成後，啟動第二階段的盤點與清理規劃；但真正刪除資料庫欄位前，仍須先
讓正式使用累積一段觀察期，以確認沒有流程依賴舊資料。

```text
全站版型重構完成
        ↓
第二階段 A：程式與正式使用盤點
        ↓
確認無相依、完成備份與 migration 設計
        ↓
第二階段 B：獨立部署資料庫清理
```

## 第二階段 A：相依盤點與使用驗證

### 進入條件

- 全站 Shell／spacing 重構已完成並部署。
- 使用者已以實驗場、議事廳、卡片建立、查詢、觀測台完成一段正常使用。
- 沒有需要恢復舊全域成長狀態 UI 的產品需求。

### 必須確認的項目

| 類別 | 確認內容 |
| --- | --- |
| 前端 | 不再有頁面、Dialog、搜尋條件、型別或快取流程讀寫 `growthStatus`。 |
| 後端 | Controller、Service、Repository、DTO、測試及 demo 初始化資料沒有正式流程依賴舊欄位。 |
| API 使用者 | 沒有其他前端版本、腳本或外部使用者呼叫 growth status endpoint。 |
| 資料 | 正式資料庫中舊值只作歷史資料，且不再需要由產品 UI 讀取。 |
| 回退 | 已備份 production DB，並清楚知道若發現相依時如何回退應用與 migration。 |

盤點結果應以當時程式碼、production schema 與正式使用證據為準，不能只依本文件
或歷史設計推測。

## 第二階段 B：資料庫與相容程式清理

通過第二階段 A 後，另開獨立任務與 migration；不與功能開發或視覺調整混合。

預期處理順序：

1. 備份正式資料庫，記錄 `cards` 總筆數與舊狀態分布，並確認部署回退版本。
2. 移除後端 growth status endpoint、DTO 欄位、Service／Repository 方法、型別與
   不再成立的測試、demo seed 資料。
3. 以獨立 migration 移除 `cards.growth_status` 的預設值、約束、索引（若存在）與
   欄位。
4. 在 production 執行 migration 後，核對應用啟動、Card／Experiment／Work／Search
   路徑及觀測台 aggregate 查詢。
5. 更新產品與技術文件，將相容期描述改為已完成的歷史紀錄。

### 不是第二階段目標的事項

- 不自動替舊 Card 建立 Experiment。
- 不將舊 status 強制轉為 ExperimentCard.stage。
- 不將舊 `SEED` 自動轉為 `needsProcessing`。
- 不建立新的 Card 成熟度、健康分數或績效統計。

## 驗收標準

第二階段完成時，系統應符合：

1. 使用者只能在 Experiment 情境中看見並調整 Card 的探索階段。
2. Card 的待整理、回流、封存、暫停、Experiment membership、Work material 與
   CardRelation 的語意維持獨立。
3. 前後端、測試、demo 與 production schema 都不存在已失效的
   `growthStatus` 相依。
4. 移除後不造成既有 Card、Experiment、Work 或觀測台資料遺失或查詢失敗。
