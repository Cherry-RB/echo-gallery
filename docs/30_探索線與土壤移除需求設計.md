- 日期：2026-10-26

- 本次範圍：產品需求、資料模型、API／UI 實作、相容切換、驗證、遷移草稿與階段性任務追蹤

## 1. 文件目的

本文件完整承接「移除實驗場土壤、建立探索線」的需求討論，並納入現行前後端程式盤點結果，作為後續開發、資料遷移、驗收及任務追蹤的共同依據。

文件中的內容分為四類：

- **已確認需求**：使用者已明確決定的產品方向。
- **目前設計結論**：依已確認需求形成的產品設計，後續開發應優先以此方向評估。
- **建議實作**：依現行程式與資料模型形成的技術方案；若開發時需要改變，應回到本文件記錄理由。
- **待產品確認**：目前仍有多種合理行為，不能由技術實作自行決定。

本文件同時記錄設計基線與實作進度，但不授權執行資料庫異動。schema migration 草稿必須保持可見且 untracked；執行前仍須核對本機實際資料表、外鍵及既有資料，由使用者完成備份、審閱並決定執行時機。

## 2. 背景與問題

目前實驗場同時承擔以下行為：

1. 保存實驗主題、目前想弄懂的問題、主題說明、狀態與識別色。
2. 設定目前試法，記錄每次試法與發現，並查看依時間排列的探索歷程。
3. 將探索紀錄整理至新卡片或既有卡片。
4. 以種子／茁壯／成熟三塊土壤關聯卡片，形成「材料與線索」區塊。
5. 顯示與實驗相關的作品，讓探索內容進一步進入長篇編排與撰寫。

實際使用後，土壤階段與卡片關聯雖然能聚集材料，卻無法清楚回答：

- 不同材料正在支持哪一個探索方向？
- 同一個方向經歷了哪些反覆試法？
- 每次試法產生了哪些發現？
- 目前形成了什麼小結論或成果？
- 同一份材料如何在不同探索方向中被重新理解？

種子／茁壯／成熟也容易被理解為必須逐步升級的成熟流程，與自由探索的產品定位產生摩擦。新需求因此不再維護三塊土壤，而是在實驗內新增選填的「探索線」整理層。

## 3. 產品定位

### 3.1 探索線是整理層

探索線用來將分散於不同日期的卡片材料、試法與發現，依照一個值得持續追蹤的方向重新聚合、比較並形成目前理解。

一條探索線可能是：

- 主動出門是否讓生活更充實？
- 如何用行動減少內耗？
- 五分鐘慢跑能否改善精神狀態？
- 《三國演義》如何塑造諸葛亮？
- 某個故事設定如何形成可持續發展的衝突？

探索線不是固定階段，也不是另一份按時間排列的探索歷程。它可以跨越多次試法與多筆探索紀錄，並持續修改目前的小結論。

### 3.2 一列表達一條探索方向

桌面版探索線表格中的一列，代表一條可長期追蹤的探索方向，不代表：

- 一張卡片。
- 一筆探索紀錄。
- 一次單獨行動。
- 一個固定成長階段。

這項定義避免探索線與現有探索歷程重複。探索歷程負責忠實保存「當時做了什麼、發現什麼」；探索線負責整理「這些經驗共同說明了什麼」。

### 3.3 探索線是選填能力

使用者可以完全不建立探索線，仍然使用：

- 實驗目的與目前試法。
- 探索紀錄。
- 整理成卡片。
- 用於作品。
- 實驗結論。

成功日記、簡短練習或一次性嘗試不應被強迫進入探索線。探索線適合需要整合、比較、反覆驗證或逐漸形成理解的實驗。

## 4. 實驗詳情的目標結構

實驗物件與詳情頁在產品語意上分成四個主要部分。

### 4.1 實驗整體說明

| 項目 | 目標語意 | 已確認行為 |
| --- | --- | --- |
| 實驗主題 | 這個實驗在探索什麼 | 保留 |
| 實驗目的 | 為什麼進行這個實驗、希望理解什麼 | 由目前畫面的「目前想弄懂」改名；既有內容保留 |
| 實驗結論 | 整個實驗目前累積出的整體理解 | 新增獨立欄位；不搬移原主題說明內容 |
| 實驗狀態 | 實驗目前是否仍在進行 | 保留，實際 enum 與操作待程式盤點 |
| 識別色 | 區分不同實驗的視覺提示 | 保留 |
| 主題說明 | 實驗的背景、範圍與補充脈絡 | 原有欄位、資料、位置與收合方式先維持原狀 |

#### 實驗結論的顯示規則

- 實驗結論與主題說明是不同欄位。
- 不將既有主題說明資料遷移或複製成實驗結論。
- 實驗結論有值時才顯示；空值時不渲染標籤、內容或預留空白。
- 顯示在實驗頁首的整體資訊區，緊接實驗目的之後。
- 與實驗目的使用相同的標籤、正文、寬度、行高與間距語言。
- 不為實驗結論建立額外白色卡片、邊框、陰影或收合元件。
- 原有主題說明仍維持原本的收合區塊，不因新增實驗結論而改變。
- 實驗結論透過既有或調整後的「編輯實驗資訊」入口新增與修改。

頁首閱讀順序示意：

```text
實驗主題                         狀態／識別色／頁級操作

實驗目的
想確認主動出門是否能增加生活的充實感。

實驗結論（有值才出現）
外出通常能帶來新經驗，但滿足感也受到體力與活動類型影響。
```

### 4.2 當前專注的探索

此區保留低摩擦、適合當下行動的探索循環：

- 自由輸入目前試法。
- 從探索線選擇一個既有試法作為目前試法。
- 編輯試法與發現。
- 記錄探索紀錄。
- 查看與編輯探索歷程。
- 將探索紀錄整理至卡片、作品或探索線。

「自由輸入目前試法」必須保留。使用者不需要先建立探索線，才能開始一次簡單嘗試。

當目前試法來自探索線時，設計方向為同時保留：

- 來源探索線。
- 來源試法。
- 選取當下的試法文字，使當前專注不會因探索線之後改字而靜默改變。

確切欄位與保存位置須在下一輪讀取現有 Experiment、目前試法及探索紀錄程式後定案。

### 4.3 作品製作

作品工作區繼續保留，負責將內容轉向較深入、長篇且可持續返回的編排、整理與撰寫。

- 作品不是探索線的必經終點。
- 使用者可以直接從卡片或探索紀錄建立作品或加入已有作品。
- 探索線整理出的內容也可以成為作品素材。
- 探索線狀態不改變作品階段，作品階段也不反向改變探索線狀態。
- 加入作品時預設成為參考素材，不直接覆寫作品正文。

### 4.4 探索線

每個實驗可以有零至多條探索線。探索線用來整理不同方向的材料、試法、發現、小結論與成果。

探索線區塊規劃放在「當前專注」之後、「作品製作」之前，讓頁面閱讀順序對應即時探索 → 整理理解 → 深入製作。

桌面版維持三個主要欄位：

| 左欄 | 中欄 | 右欄 |
| --- | --- | --- |
| 材料與線索 | 試法與發現 | 狀態、目前結論與成果 |

探索線名稱不放進左欄。每列使用跨越三欄的列首：左側為拖曳把手及名稱，右側為狀態與更多選單；下方才是三欄內容。此結構讓名稱代表整條探索線，不會被誤認為材料欄標題。

探索線另外保存：

- `sort_order`：使用者可拖曳或透過替代操作調整順序。
- `last_activity_at`：新增或修改內容時更新；單純重排不更新。

手機版不強迫使用橫向表格；每條探索線改為直向內容卡片，依序顯示材料與線索、試法與發現、狀態與成果。

## 5. 移除土壤功能

### 5.1 已確認的移除範圍

- 移除實驗場的種子／茁壯／成熟三塊土壤概念。
- 移除實驗詳情中以土壤分類顯示的「材料與線索」區塊。
- 移除將卡片種入指定土壤、在土壤間移動及依土壤篩選的操作。
- 舊卡片關聯中的種子／茁壯／成熟階段資訊可以捨棄，不需要在新模型中保存或顯示。
- 移除的是實驗內的土壤與卡片關聯功能；卡片本體、卡片回流、標籤、卡片查詢及其他非實驗土壤功能不因此刪除。

現行程式已確認土壤及衍生卡語意分布於實驗列表與詳情、總覽、卡片詳情、ExperimentService、OverviewService、CardRepository、相關 request／response、測試及清理流程。正式移除時仍需以全域搜尋建立逐檔清單，避免只刪畫面而留下執行期查詢。

### 5.2 舊資料遷移

舊土壤卡片關聯不得直接遺失。已確認的遷移方向為：

1. 對每個存在舊土壤卡片關聯的實驗建立一條探索線。
2. 探索線固定命名為「既有材料與線索」。
3. 將該實驗原有的全部關聯卡片連到這條探索線的左欄。
4. 不遷移種子／茁壯／成熟階段。
5. 同一實驗、同一張卡片只建立一次探索線卡片關聯。
6. 卡片本體及其非土壤資料不變。
7. 沒有舊土壤卡片的實驗不因 migration 被迫建立空探索線。

正式遷移補充規則：

- 預設探索線狀態為 `NOT_STARTED`。
- 使用 nullable `migration_key = LEGACY_SOIL_V1` 確保重跑時不重複建立；此欄位不顯示於 UI。
- 舊 `ExperimentCard.note` 遷移至探索線卡片關聯的 note。
- stage 完全捨棄，不轉成狀態、標籤或排序群組。
- 依舊 `added_at` 與 ID 建立穩定順序。
- 同一探索線、卡片、角色只建立一次關聯。

### 5.3 `CardRelation` 退場

現行 `CardRelation` 保存「來源卡片 → 長出的卡片」譜系，並被卡片詳情、總覽統計、最近活動及部分回流查詢使用；它不等同於 `ExperimentCard` 的土壤歸屬。

本次依「移除長出新卡及其連結功能」規劃：

- 來源卡與衍生卡本體都保留。
- 兩者若存在 `experiment_cards`，皆遷移成「既有材料與線索」中的材料卡片。
- 舊來源卡 → 衍生卡譜系不轉成探索線成果，也不為此建立 result source 表。
- 必須先改寫卡片詳情、總覽、回流與 repository 查詢，再移除 `CardRelation` entity、API 及資料表。
- 最終刪表仍需使用者在備份及資料確認後決定執行。

#### 實作前仍需核對的遷移資料

- 本機各 stage 的實際筆數、重複資料、孤兒關聯及 owner 一致性。
- `ExperimentCard.note`、`added_at` 的 null／異常狀況。
- 由探索紀錄整理成卡片所建立的 GROWING 關聯數量。
- `CardRelation` 在卡片詳情、總覽與回流查詢的實際資料量。
- Demo／測試資料的 owner、外鍵與清理順序。
- migration 中途失敗的 transaction 範圍及回復步驟。

## 6. 探索線的內容模型

### 6.1 左欄：材料與線索

- 一條探索線可以不關聯任何卡片。
- 一條探索線可以關聯一張或多張卡片。
- 同一張卡片可以出現在同一實驗的不同探索線。
- 關聯不複製、不移動、不消耗卡片，也不改變卡片回流排程。
- 解除關聯只移除探索線與卡片的關係，不刪除卡片。
- 刪除卡片後如何清理探索線關聯，須依既有卡片刪除規則及外鍵盤點定案。

探索線左欄雖然延續「材料與線索」的文字語意，但它不是舊土壤區塊：

- 不再分種子／茁壯／成熟。
- 卡片只對某一條探索線提供材料，不再直接隸屬整個實驗的某塊土壤。
- 沒有卡片也能建立、記錄及收束探索線。

### 6.2 中欄：試法與發現

現有探索紀錄支援以下行為：

- 一筆紀錄可保存試法與發現。
- 使用者記錄發現時，可以取消預設勾選的「將試法也寫入當筆探索紀錄中」。
- 因此，一筆探索紀錄可以只有發現而沒有試法文字。
- 多筆探索紀錄可能是在重複執行同一個試法，不應要求每次重複保存相同試法文字。

原始探索紀錄繼續使用同列 `tryText + discovery`，代表一次真實發生的探索事件。探索線則是整理層，需要讓試法成為可反覆採用、可被目前專注選取的穩定實體，因此正式模型拆分為：

- `exploration_thread_methods`：一筆可重複採用的試法。
- `exploration_thread_records`：一筆整理後的發現，可選擇歸屬一個試法。

兩張表形成一對多關係：

```text
試法 A
├─ 發現 1
├─ 發現 2
└─ 發現 3

試法 B
├─ 發現 4
└─ 發現 5

未指定試法
└─ 發現 6
```

這項拆分不會改變原始探索歷程的閱讀或編輯方式。將一筆同時具有試法與發現的原始紀錄加入探索線時，系統在同一交易中建立一個 method 與一個指向該 method 的 record；後續同一試法的發現只新增 record，不重複保存試法文字。

目前產品設計需要支援：

- 直接在探索線建立一個試法。
- 一個試法累積零至多筆發現。
- 發現可以關聯至一個試法，也可以暫時放在「未指定試法」。
- 從探索紀錄匯入試法。
- 從探索紀錄匯入發現。
- 同時匯入一筆紀錄中的試法與發現。
- 只匯入試法或只匯入發現。
- 將多筆相同試法的發現整理到同一試法下。
- 各筆發現保留自己的記錄或整理日期，避免合併成無法分選的大段文字。

「未指定試法」是降低整理摩擦的暫存分類，不代表資料錯誤。使用者之後可以將發現移到既有試法，或以它建立新試法。

### 6.3 右欄：狀態、結論與成果

右欄預計承接三種不同資訊：

1. 探索線本身是否仍在進行。
2. 這條探索線目前形成的小結論。
3. 從這條探索線形成的卡片、作品或其他成果關聯。

探索線小結論與實驗結論不同：

- 探索線小結論回答某一個探索方向目前得到什麼。
- 實驗結論回答整個實驗目前累積出的整體理解。
- 探索線不必收束才能填寫小結論。
- 多條探索線的小結論不應自動拼接成實驗結論。

探索線狀態定案為「未開始／進行中／暫放／已收束」，對應 `NOT_STARTED / IN_PROGRESS / PAUSED / CONCLUDED`。新探索線預設未開始，新增內容不自動切換狀態，由使用者明確決定。

成果第一版包含卡片與作品，不直接關聯奇珍。卡片材料與成果共用 `exploration_thread_cards` 並以角色區分；作品使用獨立關聯表。反向入口的畫面位置仍待 UI 階段確認。

## 7. 從探索線選擇目前試法

### 7.1 必須同時保留自由輸入

目前試法有兩種合法來源：

1. 使用者直接輸入任意文字。
2. 從某條探索線選取既有試法。

自由輸入不能被探索線取代，否則簡單實驗會被迫先建立整理結構，增加開始探索的成本。

### 7.2 選自探索線時的保存方向

當使用者從探索線選取目前試法，系統需記住：

- 來源探索線。
- 來源試法。
- 當下採用的文字。

來源關聯用來提供後續整理預設；文字保存則避免探索線日後修改時，改變當時正在執行的試法語意。

### 7.3 記錄發現時不重複保存試法

使用者仍可以取消「將試法也寫入當筆探索紀錄中」。若目前試法來自探索線，即使該筆探索紀錄沒有保存試法文字，系統仍應能知道它原本執行哪個探索線試法。

概念示意：

```text
目前試法
├─ 顯示文字：下班後主動安排一次外出
├─ 來源探索線：主動出門是否讓生活更充實？
└─ 來源試法：下班後主動安排一次外出

新探索紀錄
├─ 試法文字：空白（使用者取消寫入）
├─ 發現文字：騎車回家時感到自由與成就感
└─ 來源試法：仍能識別原探索線試法
```

若目前試法為自由輸入，而且記錄時又不保存試法文字，系統無法可靠推斷該發現屬於哪個探索線試法。之後加入探索線時，由使用者選擇既有試法、建立新試法，或暫時歸入未指定試法。

## 8. 從探索紀錄輸出至探索線

### 8.1 與現行整理成卡片並存

現行「整理探索紀錄」能將多筆紀錄格式化成以下文字，再建立新卡片或追加至既有卡片：

```text
【探索紀錄｜日期範圍｜實驗名稱】

日期一
試：……
發現：……

日期二
發現：……
```

此功能維持。新增探索線後，探索紀錄的輸出目標多一個「探索線」。

兩種輸出的儲存語意不同：

| 輸出目標 | 儲存方式 |
| --- | --- |
| 卡片 | 將選取紀錄依現行格式整理成一段可回流閱讀的文字 |
| 探索線 | 將所選試法與發現逐項保存，維持可分組、分選及重新整理的結構 |
| 作品 | 預設加入作品參考素材；不直接覆寫作品正文 |

探索線輸出不應將多筆紀錄先格式化成一個大型文字區塊，否則無法將發現歸入同一試法、單獨選取發現或比較不同試法。

### 8.2 操作入口

目前設計方向為共用現有探索歷程與整理流程：

- 探索歷程彈窗提供「加入探索線」。
- 單筆探索紀錄的更多選單提供「加入探索線」，並預先選取該筆紀錄。
- 批次整理可選一筆或多筆探索紀錄。
- 原有「整理成卡片」與「用於作品」保留，不強迫改走探索線。

按鈕名稱、位置及是否整併為一個「整理／輸出」流程，需在下一輪讀取現有元件後依操作密度評估。

### 8.3 建議流程

1. 選取一筆或多筆探索紀錄。
2. 選擇新增探索線或加入既有探索線。
3. 選擇每筆內容要輸出試法、發現或兩者。
4. 對試法選擇建立新試法或對應既有試法。
5. 對只有發現的紀錄選擇既有試法，或放入未指定試法。
6. 系統以所選文字預填探索線內容編輯框。
7. 使用者可直接保留原文，也可先精簡、改寫或提煉。
8. 確認後保存探索線自己的內容，並在原始紀錄仍存在時保留來源入口。

### 8.4 試法原本來自探索線時

若一筆探索紀錄是在執行某個探索線試法時建立，開啟輸出流程後預設：

- 目標為原本的探索線。
- 目標試法為原本選取的試法。
- 本次發現加入該試法之下。

這是預設值，不是不可修改的限制。使用者仍可改選其他探索線或試法。

系統不在保存探索紀錄時無聲地將所有內容加入探索線。原始探索可以保持零碎與自由；只有使用者執行加入或整理時，內容才進入探索線的整理層。

## 9. 探索線內容的保存與來源關聯

### 9.1 不只保存來源連結

若探索線只保存原始探索紀錄 ID，清除原始紀錄後，探索線就沒有文字可顯示。因此輸出時必須建立一份由探索線自己擁有的內容。

目前設計方向為：

1. 使用者選取原始試法或發現。
2. 系統將文字預填到探索線內容編輯框。
3. 使用者可以直接保存或先修改。
4. 探索線只保存編輯框最後的文字。
5. 另外保留一個可為空的原始探索紀錄關聯，供原始紀錄存在時返回查看。

### 9.2 不保存兩套永久文字版本

目前不建議同時永久保存「當時選取的完整原文」與「提煉後文字」兩套版本。這會增加重複資料、版本理解與刪除語意的負擔。

本文件所稱的「文字快照」是指：以選取當下的文字初始化一份探索線自己的內容，之後由探索線獨立編輯；不是另外建立不可變的原始文字版本。

每個探索線試法或發現只有一份目前文字。若未來實際使用證明需要比較原文與提煉版本，再另行設計版本或引用能力。

### 9.3 原始探索紀錄被刪除時

目前建議行為：

- 探索線已保存的文字繼續存在。
- 原始探索紀錄關聯解除。
- 「查看原始探索紀錄」入口直接消失。
- 不顯示大量「連結失效」或不可點擊的來源標籤。
- 不因刪除原始紀錄而刪除探索線、卡片或作品。

來源關聯是原始紀錄仍存在時的額外脈絡，不是探索線內容存在的前提。技術上採 nullable FK、關聯表刪除或其他方式，須在資料表盤點後決定。

## 10. 清除探索紀錄

### 10.1 批次清除能力保留

新增探索線後，使用者仍然可以一次清除實驗中的原始探索紀錄。探索線不應讓既有清除能力完全失效。

為避免「探索資料」被誤解為會刪除探索線、卡片及作品，建議將操作名稱調整為「清除探索紀錄」。

### 10.2 目前建議的清除範圍

| 資料 | 清除後行為 |
| --- | --- |
| 原始探索紀錄 | 刪除 |
| 當前專注中的暫存試法／發現 | 依現行清除語意處理，待程式盤點 |
| 探索線自己的試法、發現與小結論 | 保留 |
| 探索線至原始紀錄的來源關聯 | 解除 |
| 已整理建立或追加的卡片 | 保留 |
| 已加入的作品與作品正文 | 保留 |
| 探索線左欄的材料卡片 | 保留 |
| 實驗目的、實驗結論與主題說明 | 保留 |

確認視窗應明確說明：

```text
將永久刪除這個實驗的原始探索紀錄。
已整理至探索線、卡片或作品的內容會保留。
```

若能以合理成本取得影響數量，可進一步顯示將刪除的紀錄數，以及會保留的探索線、卡片與作品數；是否納入第一版待技術評估。

### 10.3 尚待最終確認

上述「保留探索線內容並解除來源連結」是目前討論形成的設計方向，仍須在程式盤點後確認：

- 現行清除操作究竟刪除哪些狀態與紀錄。
- 卡片、作品來源與探索紀錄的既有外鍵刪除行為。
- 是否存在必須阻止刪除的資料完整性限制。
- 使用者是否需要另一個明確的「連衍生整理內容一併刪除」流程；目前不納入一般清除操作。

## 11. 從探索線整理與輸出

### 11.1 閱讀模式與整理模式分開

一般瀏覽時不在所有內容旁顯示核取方塊。探索線以閱讀、比較及掌握目前理解為主。

使用者啟動「整理內容」後才進入選取模式，支援三種顆粒度：

| 選取層級 | 行為 |
| --- | --- |
| 整條探索線 | 選取該線目前可輸出的全部試法與發現 |
| 指定試法或多筆發現 | 只整理所選項目 |
| 試法／發現個別選取 | 可以只輸出試法，或只輸出發現 |

第一版不支援任意字元範圍選取。使用者可先修改探索線中的文字，再選取需要輸出的完整試法或發現。

### 11.2 輸出前提供預覽

使用者完成選取後，先產生可編輯的整理草稿，再確認輸出，避免將大量尚未整理的文字直接加入卡片或作品。

預計支援：

- 建立新卡片。
- 追加至既有卡片。
- 建立新作品。
- 加入既有作品。

輸出至卡片時，延續可回流閱讀的整理語意。輸出至作品時，預設成為作品參考素材，不直接插入或覆寫正文。

探索線本身是否需要保存每次輸出的歷程、成果反向關聯及輸出草稿，仍待產品與技術盤點後定案。

## 12. 探索線的主要操作

### 12.1 探索線區塊

預計提供：

- 建立探索線。
- 編輯探索線名稱。
- 更改狀態。
- 編輯目前小結論。
- 加入或移除材料卡片。
- 加入既有探索紀錄。
- 建立試法。
- 記下發現。
- 整理與輸出內容。
- 刪除探索線。

刪除探索線時不得刪除原始卡片、原始探索紀錄、已建立卡片或作品。是否同時刪除探索線自己的試法、發現與成果關聯，以及需要何種確認文案，待後續定案。

### 12.2 直接從探索線記下發現

從探索線點擊「記下發現」時，應沿用現有探索紀錄的建立機制，而不是建立一種只有探索線看得到的第二套原始紀錄。

目標行為：

1. 預設目前探索線與試法。
2. 使用既有探索紀錄編輯規則記錄本次發現。
3. 建立正式的原始探索紀錄。
4. 使用者確認整理後，再將內容加入探索線；或依最後定案的低摩擦流程完成關聯。

第 4 步是否在此入口中自動完成，尚待確認。設計需避免同時出現兩份內容、重複提交或使用者不知道資料存在哪裡。

## 13. 正式概念資料模型

以下為實作基線。實際 Java 類別、constraint 名稱與 SQL 可依相鄰程式慣例調整，但不得改變資料語意。

### 13.1 `experiments` 擴充

新增 `conclusion TEXT NULL`。既有 `hypothesis` 沿用為實驗目的；既有 `description` 繼續作為主題說明，不搬移舊資料。

### 13.2 `exploration_threads`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `experiment_id` | 必填；刪除實驗時連帶刪除探索線 |
| `name` | 必填；同一實驗可有同名探索線 |
| `status` | `NOT_STARTED / IN_PROGRESS / PAUSED / CONCLUDED`；預設未開始 |
| `conclusion` | nullable；該方向的目前小結論 |
| `sort_order` | 必填；使用者自訂順序 |
| `last_activity_at` | 必填；內容活動時間，不因拖曳排序更新 |
| `migration_key` | nullable；只供系統遷移冪等性，不顯示於 UI |
| `created_at / updated_at` | 建立與修改時間 |

建議索引及約束：

- `(experiment_id, sort_order)`。
- `(experiment_id, last_activity_at)`。
- `(experiment_id, migration_key)` 在 migration key 非空時唯一。

### 13.3 `exploration_thread_methods`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線時連帶刪除 |
| `content` | 必填；trim 後不得空白 |
| `sort_order` | 必填；試法顯示順序 |
| `source_record_id` | nullable；原始紀錄刪除時設為 null |
| `created_at / updated_at` | 建立與修改時間 |

試法可以獨立存在而沒有任何發現。

### 13.4 `exploration_thread_records`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線時連帶刪除 |
| `method_id` | nullable；空值顯示於「未指定試法」 |
| `discovery` | 必填；trim 後不得空白 |
| `source_record_id` | nullable；原始紀錄刪除時設為 null |
| `occurred_at` | nullable；原始事件時間，沒有時以建立時間顯示 |
| `sort_order` | 必填；群組內顯示順序 |
| `created_at / updated_at` | 建立與修改時間 |

`method_id` 必須指向同一 `thread_id` 的試法。後端必須驗證；若 migration 可合理使用複合唯一鍵與複合外鍵，資料庫也應同時保護。

### 13.5 `exploration_thread_cards`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線只刪除關聯 |
| `card_id` | 必填；刪除卡片時刪除關聯 |
| `role` | `MATERIAL / RESULT` |
| `note` | nullable；保留舊實驗卡片備註及未來脈絡 |
| `sort_order` | 必填；角色內順序 |
| `created_at` | 建立關聯時間 |

唯一約束為 `(thread_id, card_id, role)`。同一卡片可同時作為材料及成果。

### 13.6 `exploration_thread_works`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線只刪除關聯 |
| `work_id` | 必填；刪除作品時刪除關聯 |
| `created_at` | 建立關聯時間 |

唯一約束為 `(thread_id, work_id)`。

卡片與作品在資料庫分表以保持非空外鍵及清楚的刪除規則；Service／API 合併成統一成果清單，前端不建立兩套管理介面。

### 13.7 現有探索資料擴充

`experiment_explorations` 新增 nullable `current_try_source_method_id`：

- `current_try` 保存選取當下的文字快照。
- 來源試法 ID 提供返回來源及後續整理預設。
- 使用者直接修改文字時清空來源 ID。
- 來源試法刪除時設為 null，current try 文字保留。

`experiment_exploration_records` 建議新增 nullable `source_thread_method_id`：

- 表示這次原始探索當時採用哪個探索線試法。
- 不表示這筆發現已整理進探索線。
- 即使使用者取消「把試法一起留下」，來源仍可保存。
- 來源試法刪除時設為 null，原始紀錄保留。

### 13.8 第一版不建立的資料表

第一版不建立 `exploration_thread_results` 或 `exploration_thread_result_sources`。目前只需知道探索線關聯了哪些成果，不永久追蹤每項成果精確使用哪些試法與發現。若後續確有逐項追溯需求，再新增聚焦的輸出來源關聯。

## 14. 主要資料生命週期

| 操作 | 原始資料 | 探索線資料 | 衍生卡片／作品 |
| --- | --- | --- | --- |
| 卡片加入探索線 | 卡片不變 | 新增卡片關聯 | 不變 |
| 卡片移出探索線 | 卡片不變 | 刪除卡片關聯 | 不變 |
| 探索紀錄加入探索線 | 紀錄不變 | 建立可獨立編輯的試法／發現，並可保留來源 | 不變 |
| 修改原始探索紀錄 | 修改原始紀錄 | 不自動覆寫已整理文字 | 不變 |
| 刪除原始探索紀錄 | 刪除紀錄 | 保留文字、解除來源 | 已建立內容保留 |
| 清除全部探索紀錄 | 刪除該實驗原始紀錄 | 保留探索線整理內容 | 保留 |
| 探索線輸出至卡片 | 不變 | 可選擇保留成果關聯 | 建立或追加卡片 |
| 探索線輸出至作品 | 不變 | 可選擇保留成果關聯 | 建立作品或加入參考素材 |
| 刪除探索線 | 原始卡片與紀錄保留 | 刪除該探索線自己擁有的資料 | 已建立卡片與作品保留 |
| 刪除 Experiment | 待既有刪除規則盤點 | 原則上連帶刪除探索線及其關聯 | 卡片與作品本體不得因此刪除 |

## 15. 介面資訊密度原則

- 表格每列只顯示足以辨識探索線的材料摘要、少量最近發現、總數、狀態與小結論。
- 長篇探索紀錄不在主表格完整展開。
- 點擊「查看全部」或展開單列後，再閱讀完整試法與發現。
- 一般模式不顯示大量核取方塊。
- 整理模式才提供選取、批次輸出與選取數量。
- 左欄沒有卡片時使用簡短空狀態，不把卡片變成必填步驟。
- 中欄同一試法下的多筆發現應清楚分隔日期與內容。
- 右欄的狀態、小結論與成果不能擠成一段無層級文字。
- 桌面表格與手機直向卡片使用相同資料與操作語意，不建立兩套功能。
- 彈窗、選擇器、按鈕及文字層級應沿用專案既有共用元件與 `DESIGN_SYSTEM.md`，不另造一套視覺系統。

## 16. 階段性任務切分

每一階段應能獨立 code review、驗證與提交。採「先增加新結構、再遷移及切換、最後移除舊功能」的順序，避免把大量前後端與破壞性 schema 變更塞進同一批。

## 17. 現行程式影響盤點

### 17.1 前端

- `ExperimentDetail.vue` 同時承擔頁首、當前專注、歷程、土壤、長卡、作品及多個 Dialog 狀態；探索線應拆成聚焦元件，避免繼續膨脹。
- `ExperimentExplorationEditor.vue` 的勾選控制是否複製目前試法，且現行複製後會清空目前試法。
- `ExperimentExplorationHistoryDialog.vue` 已具有試法／發現閱讀結構與整理成卡片入口。
- `WorkSourcePicker`、`WorkUseFlow` 與來源閱讀 Dialog 提供可共用的選取與閱讀模式。
- 實驗列表、總覽、卡片詳情及整理 Dialog 仍含土壤或衍生卡語意，需在刪除舊 API 前完成切換。

### 17.2 後端

- `Experiment` 尚無 conclusion。
- `ExperimentCard` 保存 experiment、card、stage、note、addedAt，是土壤主關聯。
- `ExperimentExploration` 保存 currentTry 與三筆常用試法。
- `ExperimentExplorationRecord` 同列保存 nullable tryText 與 discovery。
- `ExplorationRecordCard` 保存原始探索紀錄整理至卡片的關聯。
- `CardRelation` 只有 `DERIVED_FROM`，由長出新卡建立來源與衍生譜系。
- 建立探索卡片目前會自動加入 GROWING；追加既有卡片要求卡片已在同一實驗土壤。
- 清除探索目前會刪除原始紀錄及 `ExperimentExploration`。
- Overview、CardRepository、卡片脈絡與回流查詢仍依賴 `ExperimentCard`／`CardRelation`。
- WorkSource 目前支援卡片或原始探索紀錄，探索線輸出需整合既有作品來源契約。

### 17.3 資料庫與發布限制

- 本機設定使用 Hibernate 自動更新，正式環境使用 validate，專案目前沒有 Flyway／Liquibase。
- 不得以啟動應用程式代替 migration 確認與手動執行。
- SQL 草稿需留在工作區、保持 untracked，且不得加入 commit。
- 正式切換採先加新表、再遷移與讀寫切換、最後移除舊表的順序。

### 17.4 API 能力規劃

以下描述能力範圍，不先鎖死 URL；真正修改 endpoint 前需再次核對現有 controller 與 request／response 慣例。

- 探索線：清單、單筆詳情、建立、編輯、刪除及批次排序。
- 試法：建立、編輯、排序及刪除；有發現時 request 必須指定移至未指定或連同刪除。
- 發現：建立、編輯、改派、排序及刪除。
- 卡片：批次加入／移除材料，加入／移除成果。
- 作品：加入／移除成果關聯。
- 整理：批次將原始探索紀錄加入一條探索線，在單一 transaction 建立試法與發現。
- 當前專注：自由文字或來源試法更新，保存文字快照與 nullable 來源 ID。
- 輸出：將選定探索線內容整理至卡片或作品。

所有能力都要驗證 user owner、experiment、thread、method、card／work 的一致性。批次排序不得接受跨實驗、重複或不完整的非法 ID。是否加入版本欄位與 409 衝突控制，待第一階段 API contract 審查，不預設所有子資料都使用同一全域版本鎖。

## 19. 初步驗收情境

後續技術設計至少需要覆蓋以下情境：

1. 沒有任何卡片也能建立探索線、試法與發現。
2. 同一張卡片可被兩條探索線使用，解除其中一條關聯不影響另一條或卡片本體。
3. 舊土壤中有多張卡片的實驗，遷移後出現一條「既有材料與線索」，卡片不重複且 stage 不再顯示。
4. 沒有舊土壤卡片的實驗不會多出空的遷移探索線。
5. 使用者可自由輸入目前試法，不必建立探索線。
6. 使用者可從探索線選取目前試法，之後修改探索線文字不會靜默改變當次已採用文字。
7. 記錄發現時不保存試法文字，仍能在來源存在時預設回原探索線試法。
8. 自由輸入試法且紀錄未保存試法時，可將發現加入既有試法、新試法或未指定試法。
9. 多筆相同試法的探索紀錄可以整理成一個試法下的多筆發現。
10. 單筆紀錄可只輸出試法、只輸出發現或兩者皆輸出。
11. 探索線內容保存後，修改原始探索紀錄不會自動覆寫整理結果。
12. 刪除或批次清除原始探索紀錄後，探索線文字保留，查看原始紀錄入口消失且沒有失效連結。
13. 原有整理成卡片流程仍能產生既有格式，不因探索線而被迫改變。
14. 探索線整理至作品時只加入參考素材，不覆寫正文。
15. 實驗結論空白時不顯示，有值時以實驗目的相同版型直接呈現，不新增白色卡片。
16. 原有主題說明的資料、位置與收合方式維持原狀。
17. 手機可完成建立探索線、閱讀內容、選擇目前試法及基本整理操作。
18. 刪除 Experiment、Card、ExplorationRecord 或使用者時，不產生外鍵錯誤或遺留跨 owner 資料。
19. 新探索線預設未開始，新增內容不自動切換狀態。
20. 拖曳排序後重新載入仍保留順序，且不改變最近活動時間。
21. 一個試法可沒有發現；多筆發現可歸入同一試法而不重複保存試法文字。
22. 發現可留在未指定試法，之後改派。
23. 刪除有發現的試法時，可將發現保留至未指定分類。
24. 同一卡片可依操作成為材料或成果，解除關聯不刪除卡片。
25. migration 重跑不建立重複探索線或卡片關聯。
26. 移除 `CardRelation` 前，總覽、卡片詳情及 repository 已無執行期依賴。

## 20. 本輪結論

本輪確立的核心方向如下：

- 探索線取代實驗場的種子／茁壯／成熟土壤整理方式。
- 舊土壤卡片移入一條名為「既有材料與線索」的探索線，舊 stage 捨棄。
- 探索線的一列代表可長期追蹤的探索方向，卡片材料完全選填。
- 探索線中間欄採 `exploration_thread_methods` 一對多 `exploration_thread_records`，不強迫每筆發現重複保存試法。
- 探索線狀態為未開始、進行中、暫放、已收束；順序與活動時間分開保存。
- 當前試法保留自由輸入，也能從探索線選取。
- 探索紀錄仍是原始經驗；探索線保存使用者選取並整理後的獨立內容。
- 原始紀錄存在時可查看來源；刪除後解除來源，不留下大量失效連結。
- 批次清除探索紀錄的能力保留，已整理的探索線、卡片與作品不應被一般清除操作連帶刪除。
- 實驗目的由目前「目前想弄懂」改名；新增獨立實驗結論；主題說明先維持原狀。
- 作品工作區繼續承接長篇編排與撰寫，不被探索線取代，也不強迫所有作品先經過探索線。
- 材料卡片與成果卡片共用具有角色的關聯表；成果作品使用獨立關聯表，前端呈現為統一成果清單。
- 第一版不建立抽象的 result／result source 輸出歷程。
- 舊 `CardRelation` 隨長出新卡功能退場，不錯誤轉換成探索線成果。

目前已完成資料盤點、新領域模型、第一版前端切換、使用者執行的資料遷移與舊後端相容層移除；實體舊表仍依第 22 節限制保留至獨立退場作業。

- 探索歷程的單筆選單與底部操作可開啟同一個「加入探索線」流程；支援多筆選取、試法／發現分選、文字預覽修改及既有試法歸類。
- 多筆探索紀錄透過單一後端 transaction 保存；同一來源的同一內容重複加入時回傳 409，不留下部分寫入。
- 同一探索線與來源紀錄的試法、發現分別設有資料庫唯一約束；直接新增、編輯或批次匯入皆套用相同的重複防護。
- 實驗列表與詳情不再顯示土壤；卡片原本「放入實驗場」的流程改為選擇實驗場及探索線。
- 探索紀錄建立／追加卡片不再建立新的土壤關聯。
- 已產出 repository 根目錄下 `exploration_threads_migration_draft.sql`，保持 untracked 且未執行。

### 22.2 實際 API

探索線 API 使用 `/api/experiments/{experimentId}/threads`：

- `GET /`、`GET /{threadId}`、`POST /`、`PUT /{threadId}`、`DELETE /{threadId}`。
- `GET /summaries?page={zeroBasedPage}&size={size}` 只回傳清單所需的計數與近期摘要；單次 `size` 最多 20。
- `PUT /order` 調整同一實驗內的完整探索線順序。
- `PUT /{threadId}/position` 以目標探索線及前後位置調整順序，供分頁清單使用；排序範圍仍是同一實驗的完整探索線集合。
- `POST／PUT／DELETE /{threadId}/methods...` 管理試法。
- `POST／PUT／DELETE /{threadId}/records...` 管理整理後發現。
- `POST /{threadId}/imports` 批次將原始探索紀錄整理成探索線自己的試法與發現。
- `POST／DELETE /{threadId}/cards...` 管理材料或成果卡片。
- `POST／DELETE /{threadId}/works...` 管理成果作品。

### 22.5 後續迭代：摘要載入、選取流程與作品反向入口

- 實驗詳情初始只取得每頁最多 20 條探索線的摘要資料；摘要包含總數、最近材料、最近發現與第一筆試法，不載入整條探索線的完整子集合。
- 每頁前 5 條探索線預設展開摘要，其餘維持收合。收合時保留名稱、狀態、最近整理時間、查看詳情、排序與更多操作；使用者自行展開後才閱讀既有三欄摘要。此調整不改變探索線詳情彈窗的內容與排版。
- 分頁只限制取得與呈現的資料量；使用者調整順序時仍以同一實驗的完整探索線排序保存，重新載入後維持順序。
- 卡片加入探索線改為與「加入既有作品」相同的單選候選列表：整列選取、選中淺底與明確停用狀態；候選範圍、加入材料的業務規則及保存時機不因此改變。
- 作品詳情右側顯示關聯探索線；點選後開啟探索線詳情彈窗，不導向實驗詳情頁。卡片詳情的關聯探索線亦採相同閱讀方式。
- 摘要 API 曾因 PostgreSQL／Hibernate 原生查詢回傳 `Instant` 時間型別而造成 500。服務層時間轉換已支援 `Instant`、`OffsetDateTime`、`Timestamp`、`LocalDateTime` 與 `Date`；此修正不改變 API 欄位格式。
