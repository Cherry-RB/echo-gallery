## 1. 文件目的

本文件完整承接「移除實驗場土壤、建立探索線」的需求討論，並納入現行前後端程式盤點結果，作為後續開發、資料遷移、驗收及任務追蹤的共同依據。

文件中的內容分為四類：

- **已確認需求**：使用者已明確決定的產品方向。
- **目前設計結論**：依已確認需求形成的產品設計，後續開發應優先以此方向評估。
- **建議實作**：依現行程式與資料模型形成的技術方案；若開發時需要改變，應回到本文件記錄理由。
- **待產品確認**：目前仍有多種合理行為，不能由技術實作自行決定。

v0.6 整合活動資料與歷次整理設計；v0.7 收斂「下一步／行動／行動備選」用語及共用表單流程。第 3、4、6～12、14、15、18～20 節描述新版目標，第 13 節區分第一版資料模型與新版調整，第 16、21 節分開追蹤第一版成果與新版待辦，第 22、23 節保留既有實作紀錄，第 24 節記錄本輪介面及契約調整。程式完成、隔離驗證與環境切換分開追蹤。

介面用語依角色區分：目前採用的是「下一步」，可重複選用的既有資料稱「行動備選」，探索線中的單筆內容與統計稱「行動」。歷史章節及資料模型中的「試法」保留其原始設計語意；`method`、`currentTry` 等既有程式及資料表識別不因 UI 改名而遷移。對外畫面、提示及新產生的整理文字使用新用語。

本文件同時記錄設計基線與實作進度，但不授權執行資料庫異動。schema migration 草稿必須保持可見且 untracked；執行前仍須核對本機實際資料表、外鍵及既有資料，由使用者完成備份、審閱並決定執行時機。

## 2. 背景與問題

本需求提出時，實驗場同時承擔以下行為（舊土壤目前已於應用程式退場）：

1. 保存實驗主題、目前想弄懂的問題、主題說明、狀態與識別色。
2. 設定目前試法，記錄每次試法與發現，並查看依時間排列的探索歷程。
3. 將探索紀錄整理至新卡片或既有卡片。
4. 以種子／茁壯／成熟三塊土壤關聯卡片，形成「材料與線索」區塊。
5. 顯示與實驗相關的作品，讓探索內容進一步進入長篇編排與撰寫。

實際使用後，土壤階段與卡片關聯雖然能聚集材料，卻無法清楚回答：

- 不同材料正在支持哪一個探索方向？
- 同一個方向經歷了哪些反覆試法？
- 每次試法產生了哪些發現？
- 目前形成了什麼小結論或成果？
- 同一份材料如何在不同探索方向中被重新理解？

種子／茁壯／成熟也容易被理解為必須逐步升級的成熟流程，與自由探索的產品定位產生摩擦。新需求因此不再維護三塊土壤，而是在實驗內新增選填的「探索線」整理層。

## 3. 產品定位

### 3.1 探索線是整理層

探索線用來將分散於不同日期的卡片材料、試法與發現，依照一個值得持續追蹤的方向重新聚合、比較並形成目前理解。

一條探索線可能是：

- 主動出門是否讓生活更充實？
- 如何用行動減少內耗？
- 五分鐘慢跑能否改善精神狀態？
- 《三國演義》如何塑造諸葛亮？
- 某個故事設定如何形成可持續發展的衝突？

探索線不是固定階段，也不是另一份按時間排列的探索歷程。它可以跨越多次試法與多筆探索紀錄，並持續修改目前的小結論。

### 3.2 一列表達一條探索方向

桌面版探索線表格中的一列，代表一條可長期追蹤的探索方向，不代表：

- 一張卡片。
- 一筆探索紀錄。
- 一次單獨行動。
- 一個固定成長階段。

上方探索紀錄呈現近期行動與待整理發現；探索線依方向與試法組織同一份活動資料，並保存歷次整理文字及目前結論。探索紀錄不是必須永久保留的原始證據庫，可由使用者整理後清除或直接刪除。

### 3.3 自訂探索線是選填能力

使用者不必先建立自訂探索線，仍能自由輸入試法、記錄發現、整理成卡片及撰寫實驗結論。

每個實驗具有唯一、由系統管理的「未設定」探索線，承接未指定方向的試法與發現。它與舊資料遷移建立的「既有材料與線索」不同，不以名稱比對識別系統用途。實際建立時機與既有實驗補建方式須在 migration 盤點後決定。

- 未選探索線時，新增內容預設進入「未設定」。
- 使用者已明確選定探索線，或從該探索線內新增時，尊重該目標。
- 「未設定」是探索方向未分類；「未指定試法」是某條探索線內的發現尚無試法，兩者不同。
- 快速記錄不強迫先完成分類；之後可調整發現歸屬。

## 4. 實驗詳情的目標結構

實驗物件與詳情頁在產品語意上分成四個主要部分。

### 4.1 實驗整體說明

| 項目 | 目標語意 | 已確認行為 |
| --- | --- | --- |
| 實驗主題 | 這個實驗在探索什麼 | 保留 |
| 實驗目的 | 為什麼進行這個實驗、希望理解什麼 | 由目前畫面的「目前想弄懂」改名；既有內容保留 |
| 實驗結論 | 整個實驗目前累積出的整體理解 | 新增獨立欄位；不搬移原主題說明內容 |
| 實驗狀態 | 實驗目前是否仍在進行 | 保留，實際 enum 與操作待程式盤點 |
| 識別色 | 區分不同實驗的視覺提示 | 保留 |
| 主題說明 | 實驗的背景、範圍與補充脈絡 | 原有欄位、資料、位置與收合方式先維持原狀 |

#### 實驗結論的顯示規則

- 實驗結論與主題說明是不同欄位。
- 不將既有主題說明資料遷移或複製成實驗結論。
- 實驗結論有值時才顯示；空值時不渲染標籤、內容或預留空白。
- 顯示在實驗頁首的整體資訊區，緊接實驗目的之後。
- 與實驗目的使用相同的標籤、正文、寬度、行高與間距語言。
- 不為實驗結論建立額外白色卡片、邊框、陰影或收合元件。
- 原有主題說明仍維持原本的收合區塊，不因新增實驗結論而改變。
- 實驗結論透過既有或調整後的「編輯實驗資訊」入口新增與修改。

頁首閱讀順序示意：

```text
實驗主題                         狀態／識別色／頁級操作

實驗目的
想確認主動出門是否能增加生活的充實感。

實驗結論（有值才出現）
外出通常能帶來新經驗，但滿足感也受到體力與活動類型影響。
```

### 4.2 當前專注的探索

「下一步與發現」區塊負責快速設定、記錄與強調目前實驗優先重視的行動，也是待整理紀錄的工作區。

- 「設定下一步」只保留探索線及可輸入的下一步行動欄位，底部使用「取消／儲存」。
- 下拉選單呈現所選探索線的行動備選，最近使用及常用各最多 3 筆；同一 ID 只列一次，可同時標示最近與常用。
- 自由輸入先形成新行動草稿；確認儲存才建立並設定下一步，選取既有項目則採用該對象。
- 選到既有行動後提供「更新／複製」藍色文字操作，在同一彈窗內編輯，不以 radio 或另一個選取彈窗切換意圖。
- 新增發現預設連結目前行動，但可清空；發現內容與探索線、對應行動共用同一表單及儲存交易。
- 可查看、編輯、調整歸屬、整理及清除待整理紀錄。
- 上方區塊與探索線顯示同一份活動資料，修改、歸類與刪除同步反映；不再為兩個入口各存一份可獨立修改的發現。
- 「暫存」代表可整理、清理的生命週期；已儲存資料仍須可靠持久化，不因關閉畫面或重新登入而遺失。

### 4.3 作品製作

作品工作區負責長篇編排與撰寫，不是探索線的必經終點。

- 作品保留與實驗場的背景關聯，以及與探索線的脈絡／成果關聯。
- 只需要返回探索方向查看時，關聯探索線，不搬移文字。
- 要保留具體內容供作品參考時，由使用者明確整理成卡片，再透過「用於作品」加入參考素材。
- 停止新增作品對暫存探索紀錄的直接引用。
- 不新增作品專用文字素材類型；不在關聯作品時暗中建立卡片。
- 不因關聯或加入素材而插入、覆寫作品正文；探索線狀態與作品階段互不連動。
- 本次切換經使用者確認：本機既有作品對探索紀錄的引用為可重建測資，正式環境沒有此類引用，直接移除這些來源列，不自動建立保存卡片；作品正文、卡片來源及原探索紀錄保留。此為本次資料退場決定，不是日後任意清理使用者素材的通用規則。

### 4.4 探索線

每個實驗可有零至多條自訂探索線，另由系統「未設定」探索線承接未分類內容。探索線肩負中長期規劃、分析與紀錄，整理不同方向的材料、目前試法、待整理發現、歷次整理、小結論與成果。

探索線區塊規劃放在「當前專注」之後、「作品製作」之前，讓頁面閱讀順序對應即時探索 → 整理理解 → 深入製作。

桌面版維持三個主要欄位：

| 左欄 | 中欄 | 右欄 |
| --- | --- | --- |
| 材料與線索 | 行動與發現 | 狀態、目前結論與成果 |

探索線名稱不放進左欄。每列使用跨越三欄的列首：左側為拖曳把手及名稱，右側為狀態與更多選單；下方才是三欄內容。此結構讓名稱代表整條探索線，不會被誤認為材料欄標題。

探索線另外保存：

- `sort_order`：使用者可拖曳或透過替代操作調整順序。
- `last_activity_at`：新增或修改內容時更新；單純重排不更新。

手機版不強迫使用橫向表格；每條探索線改為直向內容卡片，依序顯示材料與線索、行動與發現、狀態與成果。

## 5. 移除土壤功能

### 5.1 已確認的移除範圍

- 移除實驗場的種子／茁壯／成熟三塊土壤概念。
- 移除實驗詳情中以土壤分類顯示的「材料與線索」區塊。
- 移除將卡片種入指定土壤、在土壤間移動及依土壤篩選的操作。
- 舊卡片關聯中的種子／茁壯／成熟階段資訊可以捨棄，不需要在新模型中保存或顯示。
- 移除的是實驗內的土壤與卡片關聯功能；卡片本體、卡片回流、標籤、卡片查詢及其他非實驗土壤功能不因此刪除。

現行程式已確認土壤及衍生卡語意分布於實驗列表與詳情、總覽、卡片詳情、ExperimentService、OverviewService、CardRepository、相關 request／response、測試及清理流程。正式移除時仍需以全域搜尋建立逐檔清單，避免只刪畫面而留下執行期查詢。

### 5.2 舊資料遷移

舊土壤卡片關聯不得直接遺失。已確認的遷移方向為：

1. 對每個存在舊土壤卡片關聯的實驗建立一條探索線。
2. 探索線固定命名為「既有材料與線索」。
3. 將該實驗原有的全部關聯卡片連到這條探索線的左欄。
4. 不遷移種子／茁壯／成熟階段。
5. 同一實驗、同一張卡片只建立一次探索線卡片關聯。
6. 卡片本體及其非土壤資料不變。
7. 沒有舊土壤卡片的實驗不因 migration 被迫建立空探索線。

正式遷移補充規則：

- 預設探索線狀態為 `NOT_STARTED`。
- 使用 nullable `migration_key = LEGACY_SOIL_V1` 確保重跑時不重複建立；此欄位不顯示於 UI。
- 舊 `ExperimentCard.note` 遷移至探索線卡片關聯的 note。
- stage 完全捨棄，不轉成狀態、標籤或排序群組。
- 依舊 `added_at` 與 ID 建立穩定順序。
- 同一探索線、卡片、角色只建立一次關聯。

### 5.3 `CardRelation` 退場

現行 `CardRelation` 保存「來源卡片 → 長出的卡片」譜系，並被卡片詳情、總覽統計、最近活動及部分回流查詢使用；它不等同於 `ExperimentCard` 的土壤歸屬。

本次依「移除長出新卡及其連結功能」規劃：

- 來源卡與衍生卡本體都保留。
- 兩者若存在 `experiment_cards`，皆遷移成「既有材料與線索」中的材料卡片。
- 舊來源卡 → 衍生卡譜系不轉成探索線成果，也不為此建立 result source 表。
- 必須先改寫卡片詳情、總覽、回流與 repository 查詢，再移除 `CardRelation` entity、API 及資料表。
- 最終刪表仍需使用者在備份及資料確認後決定執行。

#### 實作前仍需核對的遷移資料

- 本機各 stage 的實際筆數、重複資料、孤兒關聯及 owner 一致性。
- `ExperimentCard.note`、`added_at` 的 null／異常狀況。
- 由探索紀錄整理成卡片所建立的 GROWING 關聯數量。
- `CardRelation` 在卡片詳情、總覽與回流查詢的實際資料量。
- Demo／測試資料的 owner、外鍵與清理順序。
- migration 中途失敗的 transaction 範圍及回復步驟。

## 6. 探索線的內容模型

### 6.1 左欄：材料與線索

- 一條探索線可以不關聯任何卡片。
- 一條探索線可以關聯一張或多張卡片。
- 同一張卡片可以出現在同一實驗的不同探索線。
- 關聯不複製、不移動、不消耗卡片，也不改變卡片回流排程。
- 解除關聯只移除探索線與卡片的關係，不刪除卡片。
- 刪除卡片後如何清理探索線關聯，須依既有卡片刪除規則及外鍵盤點定案。

探索線左欄雖然延續「材料與線索」的文字語意，但它不是舊土壤區塊：

- 不再分種子／茁壯／成熟。
- 卡片只對某一條探索線提供材料，不再直接隸屬整個實驗的某塊土壤。
- 沒有卡片也能建立、記錄及收束探索線。

### 6.2 中欄：行動與發現

一筆試法歸屬一條探索線，具有目前可採用的文字、零至多筆活動發現，以及該試法自己的歷次整理文字。討論中的「活試法／活發現」在 UI 使用目前試法與發現等用語；「死試法與發現」使用「歷次整理」。

中欄必須按每個試法完整分組，不將全部目前資料放在前面、全部歷史放在最後：

```text
試法 A：目前文字
├─ 發現 a、b、c
└─ 歷次整理（長文可展開）

試法 B：目前文字
├─ 發現 d、e
└─ 歷次整理（長文可展開）

未指定試法
├─ 尚未指定試法的發現
└─ 未指定試法歷次整理（長文可展開）
```

- 試法可單獨存在；發現可選擇連結一個試法。
- 上方探索歷程與此處活動發現使用同一筆資料，不再以「匯入後獨立副本」作為新流程。
- 同一試法可有多次整理，每次文字追加至該試法歷次整理欄位。
- 每次整理保留當時試法文字、紀錄期間與整理時間；日後改名不改寫舊段落標頭。
- 「未指定行動」只是每條探索線中的分組，不建立空白行動、不計入行動數，也不出現在選單中。
- 無行動的發現整理後，文字保存於該探索線層級的「未指定行動歷次整理」。
- 歷次整理只在探索線中欄呈現，不混入上方待整理紀錄，也不計為活動發現筆數。
- 已清除的活動紀錄只留下使用者確認的整理文字，不保證逐筆還原；整理前仍可選擇保留原紀錄。

### 6.2.1 調整發現歸屬

「調整歸屬」與「編輯發現」開啟同一份可編輯表單，支援未指定 → 指定行動、行動 A → 行動 B，以及已指定 → 未指定。

- 可只調整關聯，也可同時編輯發現文字；發生時間保留，不建立副本，不改變實驗的下一步。
- 調整歸屬入口初始聚焦探索線，編輯入口聚焦發現內容；兩者都能修改全部欄位。
- 跨線調整先選目標探索線，再選其行動；切換探索線清除舊行動選取並保留發現草稿。
- 儲存時一併驗證 owner、實驗、目標探索線、行動及版本，內容與歸屬一起成功或一起回滾。
- 清空對應行動後，留在已選探索線的「未指定行動」，不自動退回系統「未設定」。
- 已整理為文字且清除原紀錄的內容不適用改派；若要重新探索，須明確建立新紀錄。

### 6.3 右欄：狀態、結論與成果

右欄預計承接三種不同資訊：

1. 探索線本身是否仍在進行。
2. 這條探索線目前形成的小結論。
3. 從這條探索線形成的卡片、作品或其他成果關聯。

探索線小結論與實驗結論不同：

- 探索線小結論回答某一個探索方向目前得到什麼。
- 實驗結論回答整個實驗目前累積出的整體理解。
- 探索線不必收束才能填寫小結論。
- 多條探索線的小結論不應自動拼接成實驗結論。

探索線狀態定案為「未開始／進行中／暫放／已收束」，對應 `NOT_STARTED / IN_PROGRESS / PAUSED / CONCLUDED`。新探索線預設未開始，新增內容不自動切換狀態，由使用者明確決定。

成果包含卡片與作品，不直接關聯奇珍。卡片材料與成果共用 `exploration_thread_cards` 並以角色區分；作品使用獨立關聯表。第一版已於卡片與作品詳情提供反查探索線的彈窗入口，新版沿用。

## 7. 下一步與行動備選的選取、複製與更新

### 7.1 自由文字與選單的分工

「設定下一步」以同一個可輸入的下拉元件完成搜尋、選取及新行動草稿。空白或只有空格時仍可展開候選；輸入時搜尋符合內容，提供「新增：輸入文字」。相似文字不自動選取或合併，只有點選候選才採用其 ID。

選到既有行動後直接改打文字，代表重新搜尋或準備新行動，不會修改原資料；只有明確按「更新」才進入更新模式。「更新／複製」在原彈窗內顯示編輯欄位與狀態，所有草稿由最後一次儲存提交。取消不留下已建立或改寫的行動。

| 選項 | 已確認規則 |
| --- | --- |
| 最近使用 | 最多 3 筆，依實際採用時間排列；同一行動不重複計入 |
| 常用行動 | 使用者指定，最多 3 筆；指向既有行動，不是固定文字模板 |
| 行動備選 | 限於所選探索線，分頁搜尋；不同探索線允許同名 |
| 自行輸入 | 確認後建立並設定下一步；未明確選目標時歸入「未設定」探索線 |

候選依 ID 去重，最近與常用以同一列的標記呈現，不增加資料副本。更新後常用選單顯示新文字；複製不改變原常用指向，新行動不自動加入常用。設定下一步中的常用變更也先保留草稿，最後一併儲存。

清空下一步行動只清除目前行動，保留探索線。切換探索線時清除不相容的既有行動選取，保留尚未建立的新文字。長內容提供展開閱讀／編輯，不縮短既有 2000 字上限，也不以 tooltip 作為唯一全文入口。

### 7.2 同名試法限制

- 同一探索線內，新增或更新後不得與另一筆試法的目前文字完全相同。
- 比較時忽略頭尾空白；不靠語意推測自動合併意思相近的試法。
- 不同探索線允許同名，選單以所屬探索線區分。
- 輸入已存在名稱時，提供「使用既有試法」與「繼續修改文字」，不暗中合併發現與歷史。
- 更新同一筆試法時，不論是否已有發現，新舊值都必須不同；只整理本輪紀錄而不改文字時，使用獨立整理流程。
- 複製則必須不同於來源文字，也不能與目標探索線的其他試法同名。

### 7.3 複製為新試法

1. 將來源試法目前文字帶入新草稿，讓使用者修改。
2. 確認目標探索線與新文字，通過第 7.2 節檢查後建立新 ID。
3. 不複製發現、歷次整理或常用標記。
4. 原試法與發現、歷史全部保留；取消不產生任何資料。

### 7.4 更新目前試法

沒有連結發現時可直接修改。已有發現時，必須先進入整理流程：

1. 載入該試法目前全部發現與當時試法文字。
2. 顯示整理預覽與新試法欄位，可編輯整理文字；進入整理前及最後確認時都須驗證新舊試法值不同，前後端一致拒絕同值更新。
3. 明確警告本次將保存歷次整理、清除哪些待整理紀錄及更新哪筆試法。
4. 確認後於單一交易追加歷次整理、清除本次全部舊發現並更新目前文字。

為更新試法而整理時，不允許只清除部分舊發現後把其餘發現留在新文字下面。歷史段落保存舊試法文字，不動態讀取目前名稱，避免「閱讀 20 分鐘的發現」被解讀為「閱讀 30 分鐘的結果」。

整理期間若試法、選取紀錄或完整發現集合有變動，須阻止提交並要求重新確認，不能刪除未出現在預覽中的新紀錄。失敗或取消保留草稿，資料不得部分更新。

### 7.5 記錄發現

有目前試法時預設連結該試法，並提供取消連結的選擇。取消後按無試法發現保存，不留下隱藏的來源試法關聯；仍保留明確選定的探索線。沒有探索線時進入系統「未設定」。

## 8. 將探索紀錄整理為歷次文字

### 8.1 整理與分類分開

分類是調整同一筆發現的探索線／試法歸屬；整理是將使用者選取的內容轉成可回顧的文字。整理不再逐項複製成另一組活動試法與發現。

| 目的 | 保存結果 |
| --- | --- |
| 調整歸屬 | 更新同一筆活動發現的關聯 |
| 整理至探索線 | 追加到所屬試法的歷次整理，無試法者放探索線的未指定試法歷次整理 |
| 整理成卡片 | 建立新卡片或追加既有卡片，供回流閱讀及作品參考 |
| 用於作品 | 關聯探索線，或先明確整理成卡片再加入作品；不直接引用暫存紀錄 |

### 8.2 操作入口與流程

上方探索歷程、單筆／試法操作與探索線中欄使用同一個整理流程，入口僅預填不同上下文。

1. 選取整個試法群組、部分發現，或目前探索線的可整理內容。
2. 可只選試法、只選完整發現或兩者；第一版不支援任意字元範圍勾選。
3. 依試法分組預填整理草稿；跨試法選取分別保存至各自歷次整理，未指定者另分組。
4. 使用者保留原文、精簡或改寫，並可補充整理心得。
5. 一般整理可選擇是否清除本次已輸出的活動紀錄；更新試法模式依第 7.4 節強制處理全部舊發現。
6. 顯示保存位置與清除紀錄範圍，確認才保存；失敗保留草稿。

若只輸出一筆發現的部分意思，不能自動認定整筆原文已完整保存。刪除仍以明確列出的整筆紀錄為單位，不清除未選取內容。

### 8.3 整理文字格式

預覽預設區分觀察與歸納，最後可保存成同一個文字欄位：

```text
當時試法：睡前閱讀 20 分鐘（無試法時標示未指定試法）
紀錄期間：……
整理時間：……

發現／觀察：
日期一：……
日期二：……

整理心得：
……
```

使用者可編輯內容；保留當時試法與時間脈絡。若原觀察被改寫且原紀錄被清除，保存的是使用者確認的整理敘述，不宣稱是完整原始證據或可逐筆還原的版本。

### 8.4 一般整理與更新試法的差異

| 行為 | 一般整理 | 更新試法前整理 |
| --- | --- | --- |
| 選取範圍 | 可選部分或全部 | 該試法目前全部發現 |
| 可編輯預覽 | 是 | 是 |
| 保留原發現 | 可選 | 否，確認後清除本輪舊發現 |
| 更新目前試法 | 否 | 是 |
| 保存結果 | 追加歷次整理 | 追加歷次整理、清除舊發現、更新試法 |

一般整理保留原紀錄時，允許日後再次整理，但應顯示最近整理時間及本次為追加內容的提示；此提示不代表精確的逐筆輸出歷程。第一版不建立完整 result source 追蹤系統。

## 9. 活動資料與歷次整理的保存

### 9.1 兩個區塊共用活動資料

上方試法與發現、探索線中欄呈現同一份活動試法與發現。改字、改派與刪除需同步反映；不再沿用第一版「原始紀錄匯入後形成獨立活動副本」的寫入語意。

既有原始紀錄與探索線副本可能已各自被編輯，不能只憑文字或來源 ID 自動合併並丟棄其中一份；切換前須盤點並制定保留內容的遷移方案。

### 9.2 歷次整理是獨立文字

- 每個試法保存自己的歷次整理文字；無試法內容由探索線層級欄位承接。
- 依時間追加分段，保留當時試法名稱、紀錄期間與整理時間，不因目前文字更新而重寫歷史。
- 整理只保存最後確認的文字，不額外建立不可變原文與整理稿兩套永久副本。
- 原活動紀錄清除後，歷史文字仍可閱讀，但不能保證還原為原本逐筆資料。
- 整理草稿保護與返回流程沿用共用彈窗；本輪不增加永久輸出草稿庫。

### 9.3 效能與寫入邊界

資料列數或重複外鍵值本身不代表效能問題。先檢查索引、N+1 查詢、一次載入量與真正重複的內容；整理後清理首先是產品生命週期選擇，不以筆數減少保證效能改善。

- 歷次整理先採每試法一個文字欄位，無試法者每探索線一個欄位。
- 主清單維持摘要分頁，不傳輸全部歷史；長文按需載入與展開。
- 追加由伺服器端處理，需衝突保護，避免兩個分頁互相覆寫。
- 歷史文字不作逐筆發現統計；活動計數與歷史閱讀分開。
- 若未來需要按整理批次獨立查詢或管理，再評估每輪一筆文字，不預先建立完整版本系統。

## 10. 清除探索紀錄

### 10.1 清理目的與範圍

活動紀錄可由使用者直接刪除，或在整理後清除。清除前需明確顯示目前實驗、試法及實際紀錄範圍，不能因上方是工作區而無聲清空資料。

| 資料 | 清除後行為 |
| --- | --- |
| 明確選定的活動發現 | 刪除，上方與探索線同步移除 |
| 未選取的活動發現 | 保留；更新試法模式不允許留下舊發現再改字 |
| 歷次整理、小結論 | 保留 |
| 目前試法、常用設定 | 不應隱含刪除；既有整批清除是否另含重設設定，須依第 18 節定案 |
| 已建立或追加的卡片 | 保留 |
| 作品與正文、卡片參考素材 | 保留 |
| 探索線與材料／成果關聯 | 保留 |
| 實驗目的、實驗結論與主題說明 | 保留 |

整理後清除以文字追加成功為前提；與清除、更新試法相關的保存須具備交易一致性及提交期間變更檢查。

### 10.2 既有作品引用的退場

新版停止新增作品對暫存探索紀錄的直接引用，也不新增作品專用文字素材。原先規劃先轉成保存卡片；使用者在 SQL 尚未於本機執行前確認，本機引用可直接刪除、正式環境沒有此類引用，因此取消這項轉卡遷移。

本次 SQL 只刪除 `creative_work_sources.record_id IS NOT NULL` 的來源列，再移除 `record_id` 欄位。既有卡片來源與作品正文保留，不新增卡片或回流排程，也不為這些被移除的引用建立成果關聯。原探索紀錄仍依第 13.10、23.1 節整合；本次授權不等於刪除所有探索紀錄或作品。

### 10.3 刪除與保留的提示

一般整理可選保留原紀錄；選擇清除時顯示會刪除的完整紀錄與保留位置。更新試法的確認需同時說明舊試法文字、全部舊發現數量與新試法文字。

不提供「一般清除時連歷次整理、卡片及作品一併刪除」的隱含行為；若未來需要此能力，另行設計。

## 11. 從探索線整理與輸出

### 11.1 閱讀模式與整理模式分開

一般瀏覽時不在所有內容旁顯示核取方塊。探索線以閱讀、比較及掌握目前理解為主。

使用者啟動「整理內容」後才進入選取模式，支援三種顆粒度：

| 選取層級 | 行為 |
| --- | --- |
| 整條探索線 | 選取該線目前可輸出的全部試法與發現；輸出卡片時亦包含歷次整理 |
| 指定試法或多筆發現 | 只整理所選項目 |
| 試法／發現個別選取 | 可以只輸出試法，或只輸出發現 |

第一版不支援任意字元範圍勾選；選取完整項目後可編輯輸出草稿，不要求先修改來源內容。

輸出卡片時，可另選各試法或未指定試法分組的歷次整理文字；這些文字不是活動發現，不納入清除紀錄的範圍。第 8 節整理活動紀錄的流程不重複將既有歷史追加回自身。

### 11.2 輸出前提供預覽

選取內容後產生可編輯草稿，再確認建立新卡片或追加既有卡片。歷次整理可作卡片整理的內容來源，但不還原或偽造已清除的活動紀錄。

- 卡片輸出延續可回流閱讀的語意，成功後建立探索線成果卡片關聯。
- 已存在同一成果關聯時不重複建立；追加內容與關聯保存應保持一致。
- 輸出草稿的編輯不回寫試法、發現或歷次整理；清除活動紀錄須另依第 8、10 節明確選擇。
- 不建立 result／result source 逐項輸出歷程。

### 11.3 作品關聯與用於作品

作品輸出改為兩條明確流程：

1. **關聯作品**：關聯新／既有作品與探索線，提供探索背景及返回入口，不搬移文字。
2. **整理成卡片後用於作品**：使用者明確建立或選擇整理卡片，再透過既有作品流程加入參考素材。

不再提供暫存探索紀錄直接加入作品，也不新增作品專用文字素材。作品正文不因關聯或加入素材而被插入、覆寫。具體卡片建立與作品選擇可銜接，但不得隱藏建立卡片的事實或跳過確認。

## 12. 共用操作與呈現

### 12.1 探索線主要操作

保留建立、編輯名稱、狀態、小結論、排序、材料與成果關聯；增加／調整選取試法、複製試法、更新前整理、記下發現、調整發現歸屬及歷次整理操作。

刪除探索線與系統「未設定」的操作限制須依第 18 節補完；不能直接沿用第一版刪除整組子資料的行為而無視新版的共用活動資料與歷史。

### 12.2 共用彈窗與上下文

上方與探索線共用三套業務介面：探索行動表單、發現表單、整理介面。入口決定預填資料、欄位狀態、初始焦點及儲存目的；同一份表單內可以完成的操作留在原畫面，不因新增／編輯／調整歸屬而另開相似彈窗。共用業務驗證與保存規則，但不因介面相同而改變各入口是否設定下一步或需要整理的差異。

- 探索行動表單：設定下一步含輸入、下拉選擇、更新與複製；從探索線新增／更新／複製行動備選時，只保存行動，不自動改下一步。
- 發現表單：記下發現、編輯發現與調整歸屬使用相同的探索線、對應行動及發現欄位；主要發現輸入與補充歸屬設定分區，依操作目的決定歸屬設定的初始展開狀態，具體規則見第 24.1 節。只允許選既有行動，不因搜尋文字建立新行動。
- 整理介面：保留既有選取、預覽、歷史與卡片輸出；更新已有發現的行動時，才從行動表單銜接必要的完整整理流程。

| 入口 | 預設上下文 |
| --- | --- |
| 上方快速記錄 | 目前試法與選定探索線；未指定時使用系統「未設定」 |
| 探索線內 | 該探索線 |
| 試法內 | 該探索線與試法 |
| 未指定試法區 | 該探索線，試法留空 |

預填後建立的發現立即顯示在兩個區塊，不需再執行一次匯入。一般整理與更新前整理共用流程，但各自遵守第 8.4 節限制。

### 12.3 共用顯示元件

| 共用呈現 | 職責 |
| --- | --- |
| 行動標頭 | 目前文字、必要探索線名稱、操作選單 |
| 發現紀錄 | 文字、發生時間、編輯與整理操作 |
| 行動與發現群組 | 行動及其活動發現 |
| 歷次整理 | 文字、展開／收合 |
| 整理選取清單 | 沿用紀錄呈現，增加勾選與選取狀態 |

上方外層強調目前行動與近期紀錄；探索線外層依試法顯示目前文字、發現及歷次整理。外層可控制範圍、排序與密度，但不得各自複製內容呈現及業務操作。既有三欄摘要、詳情布局保持，僅為新版分組與操作加入必要呈現。

## 13. 正式概念資料模型

第 13.1～13.8 節記錄第一版資料模型基線，包含現行原始紀錄與整理副本的分離設計，不代表 v0.6 已完成 schema 切換。新版必須依第 13.9 節調整，不能直接繼續使用舊來源快照與複製規則。實際表名、欄位與 SQL 須經資料盤點及契約設計後確認。

### 13.1 `experiments` 擴充

新增 `conclusion TEXT NULL`。既有 `hypothesis` 沿用為實驗目的；既有 `description` 繼續作為主題說明，不搬移舊資料。

### 13.2 `exploration_threads`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `experiment_id` | 必填；刪除實驗時連帶刪除探索線 |
| `name` | 必填；同一實驗可有同名探索線 |
| `status` | `NOT_STARTED / IN_PROGRESS / PAUSED / CONCLUDED`；預設未開始 |
| `conclusion` | nullable；該方向的目前小結論 |
| `sort_order` | 必填；使用者自訂順序 |
| `last_activity_at` | 必填；內容活動時間，不因拖曳排序更新 |
| `migration_key` | nullable；只供系統遷移冪等性，不顯示於 UI |
| `created_at / updated_at` | 建立與修改時間 |

建議索引及約束：

- `(experiment_id, sort_order)`。
- `(experiment_id, last_activity_at)`。
- `(experiment_id, migration_key)` 在 migration key 非空時唯一。

### 13.3 `exploration_thread_methods`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線時連帶刪除 |
| `content` | 必填；trim 後不得空白 |
| `sort_order` | 必填；試法顯示順序 |
| `source_record_id` | nullable；原始紀錄刪除時設為 null |
| `created_at / updated_at` | 建立與修改時間 |

試法可以獨立存在而沒有任何發現。

### 13.4 `exploration_thread_records`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線時連帶刪除 |
| `method_id` | nullable；空值顯示於「未指定試法」 |
| `discovery` | 必填；trim 後不得空白 |
| `source_record_id` | nullable；原始紀錄刪除時設為 null |
| `occurred_at` | nullable；原始事件時間，沒有時以建立時間顯示 |
| `sort_order` | 必填；群組內顯示順序 |
| `created_at / updated_at` | 建立與修改時間 |

`method_id` 必須指向同一 `thread_id` 的試法。後端必須驗證；若 migration 可合理使用複合唯一鍵與複合外鍵，資料庫也應同時保護。

### 13.5 `exploration_thread_cards`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線只刪除關聯 |
| `card_id` | 必填；刪除卡片時刪除關聯 |
| `role` | `MATERIAL / RESULT` |
| `note` | nullable；保留舊實驗卡片備註及未來脈絡 |
| `sort_order` | 必填；角色內順序 |
| `created_at` | 建立關聯時間 |

唯一約束為 `(thread_id, card_id, role)`。同一卡片可同時作為材料及成果。

### 13.6 `exploration_thread_works`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線只刪除關聯 |
| `work_id` | 必填；刪除作品時刪除關聯 |
| `created_at` | 建立關聯時間 |

唯一約束為 `(thread_id, work_id)`。

卡片與作品在資料庫分表以保持非空外鍵及清楚的刪除規則；Service／API 合併成統一成果清單，前端不建立兩套管理介面。

### 13.7 現有探索資料擴充

`experiment_explorations` 新增 nullable `current_try_source_method_id`：

- `current_try` 保存選取當下的文字快照。
- 來源試法 ID 提供返回來源及後續整理預設。
- 使用者直接修改文字時清空來源 ID。
- 來源試法刪除時設為 null，current try 文字保留。

`experiment_exploration_records` 建議新增 nullable `source_thread_method_id`：

- 表示這次原始探索當時採用哪個探索線試法。
- 不表示這筆發現已整理進探索線。
- 即使使用者取消「把試法一起留下」，來源仍可保存。
- 來源試法刪除時設為 null，原始紀錄保留。

### 13.8 第一版不建立的資料表

第一版不建立 `exploration_thread_results` 或 `exploration_thread_result_sources`。目前只需知道探索線關聯了哪些成果，不永久追蹤每項成果精確使用哪些試法與發現。若後續確有逐項追溯需求，再新增聚焦的輸出來源關聯。

### 13.9 v0.6 已確認的模型調整方向

| 對象 | 新版必要資料與限制 |
| --- | --- |
| 探索線 | 系統「未設定」識別及每實驗唯一性；未指定試法歷次整理文字 |
| 試法 | 所屬探索線、目前文字、歷次整理文字、最近整理時間；同線目前文字去除頭尾空白後唯一 |
| 活動發現 | 單一正式資料來源；所屬探索線、nullable 試法、文字、發生／修改時間 |
| 目前採用與選單 | 指向既有試法的採用紀錄、常用標記；最近與常用各最多顯示 3 筆，不複製試法 |
| 衝突保護 | 歷史追加與整理清除需檢查相關試法／紀錄版本及完整集合；版本、鎖及完整集合檢查依第 13.10、23.2 節 |
| 作品參考素材 | 新流程只透過卡片承接具體內容；本次經確認直接移除舊紀錄引用測資，不自動轉卡 |

- 試法與發現活動資料採一對多，一筆發現最多對應一個目前試法；兩個畫面不另建立副本。
- 第 13.3、13.4、13.7 節屬第一版基線；本輪保留原活動紀錄表、搬入獨立探索線紀錄，舊來源欄位及副本表於核對保存後退場，不依名稱直接合併有分歧的副本。
- 不新增作品文字素材欄位或類型；先前為直接輸出作品提出的文字素材方案已撤回。
- SQL 草稿已依本機實際 schema 與資料盤點編寫，只在隔離容器驗證；本機及正式環境的執行仍由使用者決定。

### 13.10 階段 7 實際資料模型

活動資料採「一條探索線 → 多筆試法；一筆試法 → 多筆發現」，發現也可不指定試法。作品、卡片及探索線仍保有各自的生命週期。

| 資料表 | 保留／新增欄位與責任 | 關聯與約束 |
| --- | --- | --- |
| `experiments` | 實驗主題、目的、說明與結論；保留原表 | owner 為 user；刪除實驗清理其活動資料 |
| `exploration_threads` | 保留名稱、狀態、結論、排序及時間；新增 `system_key`、`unassigned_history_text`、`unassigned_last_organized_at`、`unassigned_version`、`version` | `(experiment_id, system_key)` 唯一；未指定試法的歷史存在本層，不建立空白試法 |
| `exploration_thread_methods` | `experiment_id`、`thread_id`、目前 `content`、`content_key`、`history_text`、`last_organized_at`、`sort_order`、`version` 及時間 | 同線 `content_key` 唯一；key 為去除頭尾空白後文字的 SHA-256，仍比較原文辨識雜湊碰撞；跨線同名允許 |
| `experiment_exploration_records` | 保留既有表與有效發現 ID；新增必要 `thread_id`、nullable `method_id`、必要 `occurred_at`、`updated_at`、`version`；`discovery` 保存完整發現 | 每筆屬一個實驗及探索線；試法可空，但有值時必須與探索線一致；不再保存另一份試法文字快照 |
| `experiment_explorations` | 每實驗一列設定；`current_thread_id`、`current_method_id`、`version`、`order_version` 及原時間 | 目前試法屬所選探索線；設定版本與整體排序版本分開，不以排序更新活動時間 |
| `experiment_method_preferences` | 新表；`id`、`experiment_id`、`method_id`、`last_used_at`、nullable `favorite_slot` | 每實驗／試法一列；常用位置只能 1～3 且不可重複；最近依採用或新增發現時的實際使用時間取 3 筆，單純閱讀、改派舊發現不更新最近 |
| `exploration_operation_receipts` | 新表；`user_id`、`request_id`、`payload_hash`、`result_json`、`expires_at` | owner／請求識別唯一；與整理同交易保存結果，保留 24 小時並每小時清理；不保存永久輸出歷程 |
| `cards` | 新增 `content_version` | 正文條件更新；一般編輯與整理追加都檢查版本，非正文計數更新不覆寫正文 |
| `creative_work_sources` | 刪除 `record_id` 非空的來源列，`card_id` 改為必填，移除 `record_id` | 只引用卡片；依使用者確認移除舊紀錄引用，不自動轉卡，既有卡片來源保留 |
| `exploration_thread_cards / exploration_thread_works` | 沿用原材料／成果及作品脈絡關聯 | 同卡可兼具 MATERIAL／RESULT；解除關聯不刪本體 |

實際退場範圍：

- `exploration_thread_records`：獨立紀錄搬入活動表後刪除，不保留第二套可編輯發現。
- `exploration_record_cards`：既有輸出轉成果卡片關聯後刪除，不以逐筆輸出歷程阻礙紀錄清理。
- `experiment_exploration_records.try_text / source_thread_method_id`、試法的 `source_record_id`：完成保存及歸屬後移除。
- 設定表的 `current_try / current_try_source_method_id / favorite_try_1～3`：目前／常用改為對象指標後移除。
- `experiment_cards / card_relations` 不包含在本輪刪表範圍，仍依第 22.4 節另行維運。

`system_key = UNASSIGNED` 只用來辨識每實驗唯一的「未設定」，該線與一般探索線使用同一張表及相同內容模型；讀取不建立資料，首次未分類寫入時才建立，不能改名或刪除。`unassigned_version` 保護無試法群組，`version` 保護探索線及試法的相關編輯，兩者不因畫面顯示文字而替代彼此。

SQL 加入實驗／探索線、探索線／試法及目前設定的複合歸屬外鍵；跨線整批搬移的約束延後至交易結束檢查。API 仍檢查 owner 及所有輸入，不依賴外鍵取代權限驗證。

刪除試法時明確選擇保留發現並解除試法，或一併刪除活動發現；歷史均移入同線未指定試法歷史，常用與目前指標清理。刪除一般探索線時將試法、發現、歷史及小結論移入「未設定」，同名衝突則整筆停止；材料及成果只解除關聯。刪除實驗則清理其活動資料，卡片及作品本體保留。

## 14. 主要資料生命週期

以下為 v0.6 生命週期規則；程式與隔離驗證已完成，目標環境切換及人工驗收依第 23 節追蹤：

| 操作 | 活動資料 | 探索線／歷史 | 卡片／作品 |
| --- | --- | --- | --- |
| 新增發現 | 建立一筆，兩個區塊共用 | 立即顯示於指定試法或未指定分組 | 不變 |
| 調整發現歸屬 | 更新同一筆的關聯 | 更新所屬分組，不移動既有歷次文字 | 不變 |
| 編輯發現 | 更新同一筆，保留發生時間 | 已保存的歷次文字不跟著改寫 | 不變 |
| 複製試法 | 新 ID、修改後文字；不複製發現 | 原試法歷史保留，新試法無歷史 | 不變 |
| 更新有發現的試法 | 整理全部舊發現後清除，再更新文字 | 同交易追加帶有舊名稱的歷史 | 不變 |
| 一般整理 | 可選保留或清除所選紀錄 | 追加各分組歷史 | 不變 |
| 直接刪除活動紀錄 | 刪除選定紀錄，兩處同步 | 已整理文字保留 | 新版只引用卡片；本次舊紀錄引用依確認範圍先移除 |
| 整理成卡片 | 不隱含清除來源 | 建立成果卡片關聯 | 建立或追加卡片 |
| 關聯作品 | 不變 | 建立作品脈絡／成果關聯 | 不寫入正文或搬移文字 |
| 卡片用於作品 | 不變 | 不隱含建立額外卡片或成果 | 卡片成為作品參考素材 |
| 移除材料／成果關聯 | 不變 | 只刪除關聯 | 本體保留 |
| 刪除探索線／試法 | 子資料與歷史依第 13.10 節安置 | 明確提示保留位置、清除範圍與同名衝突 | 卡片與作品本體保留 |
| 刪除實驗／帳號或清理 Demo | 依 owner 與既有刪除政策 | 同步處理新欄位與關聯 | 驗證既有保留／清除政策及完整生命週期 |

## 15. 介面資訊密度原則

- 表格每列只顯示足以辨識探索線的材料摘要、少量最近發現、總數、狀態與小結論。
- 長篇探索紀錄不在主表格完整展開。
- 點擊「查看全部」或展開單列後，再閱讀完整試法與發現。
- 一般模式不顯示大量核取方塊。
- 整理模式才提供選取、批次輸出與選取數量。
- 左欄沒有卡片時使用簡短空狀態，不把卡片變成必填步驟。
- 中欄按每個試法依序顯示目前文字、活動發現、歷次整理；未指定試法另分組，長歷史可展開。
- 上方與中欄重用試法／紀錄呈現及操作，只由外層決定近期範圍、排序與歷史是否顯示。
- 右欄的狀態、小結論與成果不能擠成一段無層級文字。
- 桌面表格與手機直向卡片使用相同資料與操作語意，不建立兩套功能。
- 彈窗、選擇器、按鈕及文字層級應沿用專案既有共用元件與 `DESIGN_SYSTEM.md`，不另造一套視覺系統。

## 16. 階段性任務切分

每一階段應能獨立 code review、驗證與提交。採「先增加新結構、再遷移及切換、最後移除舊功能」的順序，避免把大量前後端與破壞性 schema 變更塞進同一批。

階段 0～6 的完成紀錄屬於第一版，不表示符合 v0.6。新版活動資料整合、目前試法與整理規則集中列於階段 7 的前置工作；原核取項不因設計更新而倒改為未曾完成，也不提前勾選新版待辦。

## 17. 程式影響盤點

第 17.1、17.2 節保留需求初期的盤點背景，包含已退場的土壤依賴，不應視為目前程式狀態。第一版交付見第 22 節；v0.6 需重新盤點的範圍見第 16 節階段 7。

### 17.1 前端

- `ExperimentDetail.vue` 同時承擔頁首、當前專注、歷程、土壤、長卡、作品及多個 Dialog 狀態；探索線應拆成聚焦元件，避免繼續膨脹。
- `ExperimentExplorationEditor.vue` 的勾選控制是否複製目前試法，且現行複製後會清空目前試法。
- `ExperimentExplorationHistoryDialog.vue` 已具有試法／發現閱讀結構與整理成卡片入口。
- `WorkSourcePicker`、`WorkUseFlow` 與來源閱讀 Dialog 提供可共用的選取與閱讀模式。
- 實驗列表、總覽、卡片詳情及整理 Dialog 仍含土壤或衍生卡語意，需在刪除舊 API 前完成切換。

### 17.2 後端

- `Experiment` 尚無 conclusion。
- `ExperimentCard` 保存 experiment、card、stage、note、addedAt，是土壤主關聯。
- `ExperimentExploration` 保存 currentTry 與三筆常用試法。
- `ExperimentExplorationRecord` 同列保存 nullable tryText 與 discovery。
- `ExplorationRecordCard` 保存原始探索紀錄整理至卡片的關聯。
- `CardRelation` 只有 `DERIVED_FROM`，由長出新卡建立來源與衍生譜系。
- 建立探索卡片目前會自動加入 GROWING；追加既有卡片要求卡片已在同一實驗土壤。
- 清除探索目前會刪除原始紀錄及 `ExperimentExploration`。
- Overview、CardRepository、卡片脈絡與回流查詢仍依賴 `ExperimentCard`／`CardRelation`。
- WorkSource 目前支援卡片或原始探索紀錄，探索線輸出需整合既有作品來源契約。

### 17.3 資料庫與發布限制

- 本機與正式環境均使用 Hibernate validate；整合測試僅在 Testcontainers 使用 create。專案目前沒有 Flyway／Liquibase。
- 不得以啟動應用程式代替 migration 確認與手動執行。
- SQL 草稿需留在工作區、保持 untracked，且不得加入 commit。
- 正式切換停寫並備份後，在單一 SQL 交易內新增結構、保存／搬移資料、檢查約束及移除本輪副本表，再同步部署前後端；不在新舊 schema 間混跑。

### 17.4 API 能力規劃

以下描述能力範圍，不先鎖死 URL；真正修改 endpoint 前需再次核對現有 controller 與 request／response 慣例。

- 探索線：清單、單筆詳情、建立、編輯、刪除及批次排序。
- 試法：建立、複製、編輯、排序及刪除；更新有發現的試法須遵守第 7.4 節。刪除時如何安置活動發現與歷次整理，須先完成第 18.2 節方案，不預先固定為移至未指定或連同刪除。
- 發現：建立、編輯、改派、排序及刪除。
- 卡片：批次加入／移除材料，加入／移除成果。
- 作品：加入／移除成果關聯。
- 整理：將選定活動內容追加為歷次文字；更新試法模式同交易保存歷史、清除全部舊發現與更新文字。
- 當前專注：採用既有試法、建立新試法、最近／常用與同名檢查，不默默解除來源。
- 歸屬：調整同一筆發現的探索線與 nullable 試法。
- 輸出：新建／追加卡片及成果關聯；作品只關聯脈絡或經卡片加入參考素材。
- 保護：驗證整理期間的文字及集合變動，歷史追加防止互相覆寫；實際 endpoint、版本與鎖策略依第 23.2 節。

所有能力都要驗證 user owner、experiment、thread、method、card／work 的一致性。批次排序不得接受跨實驗、重複或不完整的非法 ID。整理與清除的併發保護已列為必要行為，實際版本欄位、鎖與衝突回應依第 23.2 節，不預設所有子資料使用同一全域版本鎖。

## 18. 已確認邊界與待盤點事項

### 18.1 已確認設計

- 最近／常用／探索線選項指向既有試法；常用是捷徑，不是文字模板。
- 同線試法目前文字不得同名，跨線允許；複製不帶發現、歷史及常用標記。
- 上方與探索線共用活動資料；整理後可清除，歷史文字不保證逐筆還原。
- 無試法發現可補指定／改派／解除；未指定分組不建立空白試法。
- 更新有發現試法前必須整理全部舊發現；保存歷史、清除與更新需原子性及併發保護。
- 作品關聯探索線，具體素材經卡片承接；停止新增紀錄直接引用，不新增作品文字素材。
- 不建立 result source 輸出歷程；舊 CardRelation 譜系捨棄。
- 一般清理不連帶刪除歷史、卡片與作品。

### 18.2 本輪方案與執行邊界

1. 單一活動紀錄及兩張副本／輸出表的退場方式已依本機盤點確認，見第 13.10、23.1 節；來源副本若與盤點不同，SQL 中止，不自動合併。
2. 使用者確認本機舊作品紀錄引用可直接刪除，正式環境沒有此類引用；草稿移除自動轉卡，保留卡片來源、作品正文及原探索紀錄，實際環境尚未執行。
3. 最近／常用依既有試法 ID；舊自由文字於同實驗「未設定」建立相應試法，常用去重保留原順序；異常同名需人工處理。
4. 系統探索線、試法與探索線刪除後的保留位置，以及設定／紀錄清理的分工依第 13.10 節；舊「清除全部」入口不再重設目前與常用。
5. schema、索引、版本、鎖、長文及 API 已有實作與隔離驗證；累積歷史使用 PostgreSQL TEXT 按需讀取，未新增逐筆歷史還原或永久輸出來源表。
6. MVP 與 UI 索引同步本輪能力；備份、實際 SQL、目標環境核對與桌面／手機驗收仍待執行。

## 19. 驗收情境

以下為新版驗收要求，尚未代表已通過：

1. 沒有卡片或自訂探索線也可記錄；未指定方向時使用同實驗唯一的系統「未設定」。
2. 明確選探索線時尊重目標；取消試法連結仍留在該線的未指定試法分組。
3. 最近用過與常用各最多 3 筆，同一試法多組入口仍使用同一 ID；更新常用指向的試法後顯示新文字。
4. 同線同名建立／更新被拒絕，忽略頭尾空白；跨線同名可依探索線辨識。
5. 複製須改字，不帶發現、歷史或常用標記，取消不建立資料，原試法完整保留。
6. 沒有發現可直接更新；有發現必須先整理全部舊紀錄，舊名保存於歷史，更新同值也可完成一輪整理。
7. 整理期間新添、修改或移動紀錄會阻止過時提交，不清除預覽之外的資料；失敗不留下部分寫入。
8. 新增／編輯／刪除發現於上方與探索線同步呈現，不建立雙份活動資料。
9. 未指定發現可補指定、A 改 B、解除或明確跨線改派；文字與發生時間保留。
10. 每個試法依序呈現目前文字、活動發現、歷次整理，長文可展開；未指定分組不出現在試法選單或試法數量中。
11. 一般整理可選試法／完整發現與清除選項，跨群組分別追加歷史；未選取紀錄不被清除。
12. 整理格式區分觀察與心得；歷史保留當時名稱與時間，不因改名而重新解釋舊結果。
13. 清除後文字可閱讀，但不提供虛假的逐筆還原能力；保留紀錄後再次整理清楚提示為追加。
14. 整理草稿返回、取消、提交鎖定與失敗重試一致；兩入口共用彈窗及顯示元件。
15. 卡片新建／追加不覆寫來源，成果關聯不重複；用於作品需明確選擇卡片，不隱藏建立。
16. 作品關聯只提供脈絡，不寫入正文；新版拒絕新增暫存紀錄引用。本次切換只移除經確認可刪的舊紀錄引用來源列，既有卡片來源、作品正文與原探索紀錄保留，不自動轉卡。
17. 歷史按需載入、分頁摘要不傳全部子集合，活動計數不混入歷史文字筆數。
18. owner、跨實驗歸屬、同名併發及完整建立／讀取／清理生命週期通過；無外鍵錯誤與跨 owner 殘留。

19. 土壤資料保留材料與 note、捨棄 stage，migration 不重複；系統「未設定」與「既有材料與線索」不混用。

- 試法有目前文字、連結發現及歷次整理；複製與更新分成明確操作。

### 23.2 API 與衝突契約

新版以 `/api/experiments/{experimentId}/activity` 提供共用操作：

| 能力 | Endpoint／契約 |
| --- | --- |
| 目前與選單 | `GET /`、`PUT /focus`、`PUT /favorites`；設定寫入需 `expectedVersion` |
| 試法候選／單筆 | `GET /methods`、`GET /methods/{id}`；搜尋及分頁只讀取選單資料，不取歷史全文 |
| 建立／複製／更新／刪除試法 | `POST /methods`、`PUT／DELETE /methods/{id}`；複製帶來源與來源版本，更新／刪除需版本；已有發現禁止直接更新文字 |
| 發現 | `GET／POST /records`、`PUT／DELETE /records/{id}`；編輯／刪除需紀錄版本，指定試法時另檢查 `expectedMethodVersion` |
| 調整歸屬 | `PUT /records/{id}/assignment`；指定探索線及 nullable 試法，保留發現文字與發生時間 |
| 歷史 | `GET /history?threadId=...&methodId=...`；未指定 method 時讀探索線無試法歷史 |
| 整理預覽 | `POST /organizations/preview`；HISTORY／UPDATE_METHOD／CARD，共用選取、原文與草稿，回傳 30 分鐘有效的簽章預覽 |
| 整理提交 | `POST /organizations`；提交預覽 token、UUID 請求識別與分組草稿，原子保存歷史／卡片、清理與更新試法 |

- 試法候選及發現預設每頁 20 筆、上限 50；主探索線摘要每頁最多 20，前 5 筆預設展開不變。單條詳情的試法及發現分頁；歷史全文只在展開時取得。
- 一般整理最多選 100 筆發現／100 組；整線整理逐頁收集試法、最多 99 種並加無試法分組，超出時明示分組整理。更新試法須選該試法完整活動集合，不能只整理部分後改名。
- 確認提交重新驗證 owner、實驗／探索線／試法、群組及紀錄版本與完整集合。過時資料回傳 409，沒有部分保存或錯誤清除；輸入不合法 400，無權歸屬 404。
- 活動寫入先鎖所屬實驗；涉及整理／作品清理／卡片正文依 owner → experiment → card 的一致順序協調。版本仍各自管理，不以單一全域版本造成無關群組互相失效。
- 整理提交使用同一請求識別防重；同識別、同內容回傳原結果，不再追加，換內容則 409。斷線、逾時或 5xx 等結果不明時，前端凍結原請求及草稿，只允許重試；已成功但回應遺失也不建立第二張卡片。
- 卡片一般編輯需 `expectedContentVersion`；整理追加檢查預覽時正文版本，不覆蓋其他分頁的新正文。計數等非正文修改採部分欄位更新。
- 探索線 `/position` 及 `/order` 需 `expectedVersion`，來源為摘要 `orderVersion`。排序只讀完整 ID 順序並批次寫入，不取所有歷史，不更新活動時間；舊版本提交回傳 409。
- 新增 `GET /threads/options` 提供分頁探索線候選與卡片已加入狀態。舊原始紀錄寫入、整批清除、卡片輸出及副本匯入入口回傳 410，要求舊視窗重新載入；新版前端已移除這些呼叫。
- 作品新增來源只接受卡片；探索紀錄直接引用回傳 400，既有作品正文及主要實驗／探索線脈絡能力保留。
