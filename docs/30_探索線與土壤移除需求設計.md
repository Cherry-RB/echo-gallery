## 2. 背景與問題

本需求提出時，實驗場同時承擔以下行為（舊土壤目前已於應用程式退場）：

1. 保存實驗主題、目前想弄懂的問題、主題說明、狀態與識別色。
2. 設定目前試法，記錄每次試法與發現，並查看依時間排列的探索歷程。
3. 將探索紀錄整理至新卡片或既有卡片。
4. 以種子／茁壯／成熟三塊土壤關聯卡片，形成「材料與線索」區塊。
5. 顯示與實驗相關的作品，讓探索內容進一步進入長篇編排與撰寫。

實際使用後，土壤階段與卡片關聯雖然能聚集材料，卻無法清楚回答：

- 不同材料正在支持哪一個探索方向？
- 同一個方向經歷了哪些反覆試法？
- 每次試法產生了哪些發現？
- 目前形成了什麼小結論或成果？
- 同一份材料如何在不同探索方向中被重新理解？

種子／茁壯／成熟也容易被理解為必須逐步升級的成熟流程，與自由探索的產品定位產生摩擦。新需求因此不再維護三塊土壤，而是在實驗內新增選填的「探索線」整理層。

## 3. 產品定位

### 3.1 探索線是整理層

探索線用來將分散於不同日期的卡片材料、試法與發現，依照一個值得持續追蹤的方向重新聚合、比較並形成目前理解。

一條探索線可能是：

- 主動出門是否讓生活更充實？
- 如何用行動減少內耗？
- 五分鐘慢跑能否改善精神狀態？
- 《三國演義》如何塑造諸葛亮？
- 某個故事設定如何形成可持續發展的衝突？

探索線不是固定階段，也不是另一份按時間排列的探索歷程。它可以跨越多次試法與多筆探索紀錄，並持續修改目前的小結論。

### 3.2 一列表達一條探索方向

桌面版探索線表格中的一列，代表一條可長期追蹤的探索方向，不代表：

- 一張卡片。
- 一筆探索紀錄。
- 一次單獨行動。
- 一個固定成長階段。

上方探索紀錄呈現近期行動與待整理發現；探索線依方向與試法組織同一份活動資料，並保存歷次整理文字及目前結論。探索紀錄不是必須永久保留的原始證據庫，可由使用者整理後清除或直接刪除。

### 3.3 自訂探索線是選填能力

使用者不必先建立自訂探索線，仍能自由輸入試法、記錄發現、整理成卡片及撰寫實驗結論。

每個實驗具有唯一、由系統管理的「未設定」探索線，承接未指定方向的試法與發現。它與舊資料遷移建立的「既有材料與線索」不同，不以名稱比對識別系統用途。實際建立時機與既有實驗補建方式須在 migration 盤點後決定。

- 未選探索線時，新增內容預設進入「未設定」。
- 使用者已明確選定探索線，或從該探索線內新增時，尊重該目標。
- 「未設定」是探索方向未分類；「未指定試法」是某條探索線內的發現尚無試法，兩者不同。
- 快速記錄不強迫先完成分類；之後可調整發現歸屬。

## 4. 實驗詳情的目標結構

實驗物件與詳情頁在產品語意上分成四個主要部分。

### 4.1 實驗整體說明

| 項目 | 目標語意 | 已確認行為 |
| --- | --- | --- |
| 實驗主題 | 這個實驗在探索什麼 | 保留 |
| 實驗目的 | 為什麼進行這個實驗、希望理解什麼 | 由目前畫面的「目前想弄懂」改名；既有內容保留 |
| 實驗結論 | 整個實驗目前累積出的整體理解 | 新增獨立欄位；不搬移原主題說明內容 |
| 實驗狀態 | 實驗目前是否仍在進行 | 保留，實際 enum 與操作待程式盤點 |
| 識別色 | 區分不同實驗的視覺提示 | 保留 |
| 主題說明 | 實驗的背景、範圍與補充脈絡 | 原有欄位、資料、位置與收合方式先維持原狀 |

#### 實驗結論的顯示規則

- 實驗結論與主題說明是不同欄位。
- 不將既有主題說明資料遷移或複製成實驗結論。
- 實驗結論有值時才顯示；空值時不渲染標籤、內容或預留空白。
- 顯示在實驗頁首的整體資訊區，緊接實驗目的之後。
- 與實驗目的使用相同的標籤、正文、寬度、行高與間距語言。
- 不為實驗結論建立額外白色卡片、邊框、陰影或收合元件。
- 原有主題說明仍維持原本的收合區塊，不因新增實驗結論而改變。
- 實驗結論透過既有或調整後的「編輯實驗資訊」入口新增與修改。

頁首閱讀順序示意：

```text
實驗主題                         狀態／識別色／頁級操作

實驗目的
想確認主動出門是否能增加生活的充實感。

實驗結論（有值才出現）
外出通常能帶來新經驗，但滿足感也受到體力與活動類型影響。
```

### 4.2 當前專注的探索

「試法與發現」區塊負責快速編輯、記錄與強調目前實驗優先重視的行動，也是待整理紀錄的工作區。

- 試法選單提供最近用過（最多 3 筆）、我的常用試法（最多 3 筆）及探索線目前試法。
- 保留自由輸入；確認保存才建立正式試法，輸入中的文字不立即建立資料。
- 選取既有試法只是採用該對象，不複製文字、發現或歷史。
- 編輯已有試法須明確選擇「複製為新試法」或「更新目前試法」，規則見第 7 節。
- 新增發現預設連結目前試法，但可取消連結；取消後不保存隱藏的試法歸屬。
- 可查看、編輯、調整歸屬、整理及清除待整理紀錄。
- 上方區塊與探索線顯示同一份活動資料，修改、歸類與刪除同步反映；不再為兩個入口各存一份可獨立修改的發現。
- 「暫存」代表可整理、清理的生命週期；已儲存資料仍須可靠持久化，不因關閉畫面或重新登入而遺失。

### 4.3 作品製作

作品工作區負責長篇編排與撰寫，不是探索線的必經終點。

- 作品保留與實驗場的背景關聯，以及與探索線的脈絡／成果關聯。
- 只需要返回探索方向查看時，關聯探索線，不搬移文字。
- 要保留具體內容供作品參考時，由使用者明確整理成卡片，再透過「用於作品」加入參考素材。
- 停止新增作品對暫存探索紀錄的直接引用。
- 不新增作品專用文字素材類型；不在關聯作品時暗中建立卡片。
- 不因關聯或加入素材而插入、覆寫作品正文；探索線狀態與作品階段互不連動。
- 既有作品已引用的探索紀錄須先盤點與提出遷移方案，保留可閱讀內容；不得直接刪除引用，也不得僅換成探索線連結而遺失原本素材。

### 4.4 探索線

每個實驗可有零至多條自訂探索線，另由系統「未設定」探索線承接未分類內容。探索線肩負中長期規劃、分析與紀錄，整理不同方向的材料、目前試法、待整理發現、歷次整理、小結論與成果。

探索線區塊規劃放在「當前專注」之後、「作品製作」之前，讓頁面閱讀順序對應即時探索 → 整理理解 → 深入製作。

桌面版維持三個主要欄位：

| 左欄 | 中欄 | 右欄 |
| --- | --- | --- |
| 材料與線索 | 試法與發現 | 狀態、目前結論與成果 |

探索線名稱不放進左欄。每列使用跨越三欄的列首：左側為拖曳把手及名稱，右側為狀態與更多選單；下方才是三欄內容。此結構讓名稱代表整條探索線，不會被誤認為材料欄標題。

探索線另外保存：

- `sort_order`：使用者可拖曳或透過替代操作調整順序。
- `last_activity_at`：新增或修改內容時更新；單純重排不更新。

手機版不強迫使用橫向表格；每條探索線改為直向內容卡片，依序顯示材料與線索、試法與發現、狀態與成果。

## 5. 移除土壤功能

### 5.1 已確認的移除範圍

- 移除實驗場的種子／茁壯／成熟三塊土壤概念。
- 移除實驗詳情中以土壤分類顯示的「材料與線索」區塊。
- 移除將卡片種入指定土壤、在土壤間移動及依土壤篩選的操作。
- 舊卡片關聯中的種子／茁壯／成熟階段資訊可以捨棄，不需要在新模型中保存或顯示。
- 移除的是實驗內的土壤與卡片關聯功能；卡片本體、卡片回流、標籤、卡片查詢及其他非實驗土壤功能不因此刪除。

現行程式已確認土壤及衍生卡語意分布於實驗列表與詳情、總覽、卡片詳情、ExperimentService、OverviewService、CardRepository、相關 request／response、測試及清理流程。正式移除時仍需以全域搜尋建立逐檔清單，避免只刪畫面而留下執行期查詢。

### 5.2 舊資料遷移

舊土壤卡片關聯不得直接遺失。已確認的遷移方向為：

1. 對每個存在舊土壤卡片關聯的實驗建立一條探索線。
2. 探索線固定命名為「既有材料與線索」。
3. 將該實驗原有的全部關聯卡片連到這條探索線的左欄。
4. 不遷移種子／茁壯／成熟階段。
5. 同一實驗、同一張卡片只建立一次探索線卡片關聯。
6. 卡片本體及其非土壤資料不變。
7. 沒有舊土壤卡片的實驗不因 migration 被迫建立空探索線。

正式遷移補充規則：

- 預設探索線狀態為 `NOT_STARTED`。
- 使用 nullable `migration_key = LEGACY_SOIL_V1` 確保重跑時不重複建立；此欄位不顯示於 UI。
- 舊 `ExperimentCard.note` 遷移至探索線卡片關聯的 note。
- stage 完全捨棄，不轉成狀態、標籤或排序群組。
- 依舊 `added_at` 與 ID 建立穩定順序。
- 同一探索線、卡片、角色只建立一次關聯。

### 5.3 `CardRelation` 退場

現行 `CardRelation` 保存「來源卡片 → 長出的卡片」譜系，並被卡片詳情、總覽統計、最近活動及部分回流查詢使用；它不等同於 `ExperimentCard` 的土壤歸屬。

本次依「移除長出新卡及其連結功能」規劃：

- 來源卡與衍生卡本體都保留。
- 兩者若存在 `experiment_cards`，皆遷移成「既有材料與線索」中的材料卡片。
- 舊來源卡 → 衍生卡譜系不轉成探索線成果，也不為此建立 result source 表。
- 必須先改寫卡片詳情、總覽、回流與 repository 查詢，再移除 `CardRelation` entity、API 及資料表。
- 最終刪表仍需使用者在備份及資料確認後決定執行。

#### 實作前仍需核對的遷移資料

- 本機各 stage 的實際筆數、重複資料、孤兒關聯及 owner 一致性。
- `ExperimentCard.note`、`added_at` 的 null／異常狀況。
- 由探索紀錄整理成卡片所建立的 GROWING 關聯數量。
- `CardRelation` 在卡片詳情、總覽與回流查詢的實際資料量。
- Demo／測試資料的 owner、外鍵與清理順序。
- migration 中途失敗的 transaction 範圍及回復步驟。

## 6. 探索線的內容模型

### 6.1 左欄：材料與線索

- 一條探索線可以不關聯任何卡片。
- 一條探索線可以關聯一張或多張卡片。
- 同一張卡片可以出現在同一實驗的不同探索線。
- 關聯不複製、不移動、不消耗卡片，也不改變卡片回流排程。
- 解除關聯只移除探索線與卡片的關係，不刪除卡片。
- 刪除卡片後如何清理探索線關聯，須依既有卡片刪除規則及外鍵盤點定案。

探索線左欄雖然延續「材料與線索」的文字語意，但它不是舊土壤區塊：

- 不再分種子／茁壯／成熟。
- 卡片只對某一條探索線提供材料，不再直接隸屬整個實驗的某塊土壤。
- 沒有卡片也能建立、記錄及收束探索線。

### 6.2 中欄：試法與發現

一筆試法歸屬一條探索線，具有目前可採用的文字、零至多筆活動發現，以及該試法自己的歷次整理文字。討論中的「活試法／活發現」在 UI 使用目前試法與發現等用語；「死試法與發現」使用「歷次整理」。

中欄必須按每個試法完整分組，不將全部目前資料放在前面、全部歷史放在最後：

```text
試法 A：目前文字
├─ 發現 a、b、c
└─ 歷次整理（長文可展開）

試法 B：目前文字
├─ 發現 d、e
└─ 歷次整理（長文可展開）

未指定試法
├─ 尚未指定試法的發現
└─ 未指定試法歷次整理（長文可展開）
```

- 試法可單獨存在；發現可選擇連結一個試法。
- 上方探索歷程與此處活動發現使用同一筆資料，不再以「匯入後獨立副本」作為新流程。
- 同一試法可有多次整理，每次文字追加至該試法歷次整理欄位。
- 每次整理保留當時試法文字、紀錄期間與整理時間；日後改名不改寫舊段落標頭。
- 「未指定試法」只是每條探索線中的分組，不建立空白試法、不計入試法數，也不出現在選單中。
- 無試法的發現整理後，文字保存於該探索線層級的「未指定試法歷次整理」。
- 歷次整理只在探索線中欄呈現，不混入上方待整理紀錄，也不計為活動發現筆數。
- 已清除的活動紀錄只留下使用者確認的整理文字，不保證逐筆還原；整理前仍可選擇保留原紀錄。

### 6.2.1 調整發現歸屬

共用「調整歸屬」操作支援未指定 → 指定試法、試法 A → 試法 B，以及已指定 → 未指定。

- 只調整關聯，保留發現文字與發生時間，不建立副本。
- 預設選目前探索線的試法；跨線調整時先明確選目標探索線，再選試法。
- 確認前顯示目的地；試法必須屬於目標探索線與同一實驗，並驗證 owner。
- 取消連結試法後，留在已選探索線的「未指定試法」，不自動退回系統「未設定」。
- 已整理為文字且清除原紀錄的內容不適用改派；若要重新探索，須明確建立新紀錄。

### 6.3 右欄：狀態、結論與成果

右欄預計承接三種不同資訊：

1. 探索線本身是否仍在進行。
2. 這條探索線目前形成的小結論。
3. 從這條探索線形成的卡片、作品或其他成果關聯。

探索線小結論與實驗結論不同：

- 探索線小結論回答某一個探索方向目前得到什麼。
- 實驗結論回答整個實驗目前累積出的整體理解。
- 探索線不必收束才能填寫小結論。
- 多條探索線的小結論不應自動拼接成實驗結論。

探索線狀態定案為「未開始／進行中／暫放／已收束」，對應 `NOT_STARTED / IN_PROGRESS / PAUSED / CONCLUDED`。新探索線預設未開始，新增內容不自動切換狀態，由使用者明確決定。

成果包含卡片與作品，不直接關聯奇珍。卡片材料與成果共用 `exploration_thread_cards` 並以角色區分；作品使用獨立關聯表。第一版已於卡片與作品詳情提供反查探索線的彈窗入口，新版沿用。

## 7. 目前試法的選取、複製與更新

### 7.1 自由文字與選單的分工

選單負責選擇既有試法，文字欄位負責新增草稿或明確啟動的編輯。自由輸入不能被既有選項取代，但修改已選文字不再默默解除關聯或建立另一份試法。

| 選項 | 已確認規則 |
| --- | --- |
| 最近用過 | 最多 3 筆，依實際採用時間排列；同一試法不重複計入 |
| 我的常用試法 | 使用者指定，最多 3 筆；是既有試法的捷徑，不是固定文字模板 |
| 探索線目前試法 | 依探索線分組或篩選；顯示所屬探索線以辨識同名項目 |
| 自行輸入 | 確認後建立新試法；未明確選目標時歸入「未設定」探索線 |

同一個試法可以同時出現在最近、常用及探索線選項中，三者指向同一 ID，不增加資料副本。更新試法後，常用選單顯示新文字；複製成新試法不改變原常用指向，新試法也不自動加入常用。

### 7.2 同名試法限制

- 同一探索線內，新增或更新後不得與另一筆試法的目前文字完全相同。
- 比較時忽略頭尾空白；不靠語意推測自動合併意思相近的試法。
- 不同探索線允許同名，選單以所屬探索線區分。
- 輸入已存在名稱時，提供「使用既有試法」與「繼續修改文字」，不暗中合併發現與歷史。
- 更新同一筆試法時，新舊值相同可以保存，代表整理本輪後繼續採用。
- 複製則必須不同於來源文字，也不能與目標探索線的其他試法同名。

### 7.3 複製為新試法

1. 將來源試法目前文字帶入新草稿，讓使用者修改。
2. 確認目標探索線與新文字，通過第 7.2 節檢查後建立新 ID。
3. 不複製發現、歷次整理或常用標記。
4. 原試法與發現、歷史全部保留；取消不產生任何資料。

### 7.4 更新目前試法

沒有連結發現時可直接修改。已有發現時，必須先進入整理流程：

1. 載入該試法目前全部發現與當時試法文字。
2. 顯示整理預覽與新試法欄位，可編輯整理文字；新舊試法值相同也可繼續。
3. 明確警告本次將保存歷次整理、清除哪些待整理紀錄及更新哪筆試法。
4. 確認後於單一交易追加歷次整理、清除本次全部舊發現並更新目前文字。

為更新試法而整理時，不允許只清除部分舊發現後把其餘發現留在新文字下面。歷史段落保存舊試法文字，不動態讀取目前名稱，避免「閱讀 20 分鐘的發現」被解讀為「閱讀 30 分鐘的結果」。

整理期間若試法、選取紀錄或完整發現集合有變動，須阻止提交並要求重新確認，不能刪除未出現在預覽中的新紀錄。失敗或取消保留草稿，資料不得部分更新。

### 7.5 記錄發現

有目前試法時預設連結該試法，並提供取消連結的選擇。取消後按無試法發現保存，不留下隱藏的來源試法關聯；仍保留明確選定的探索線。沒有探索線時進入系統「未設定」。

## 8. 將探索紀錄整理為歷次文字

### 8.1 整理與分類分開

分類是調整同一筆發現的探索線／試法歸屬；整理是將使用者選取的內容轉成可回顧的文字。整理不再逐項複製成另一組活動試法與發現。

| 目的 | 保存結果 |
| --- | --- |
| 調整歸屬 | 更新同一筆活動發現的關聯 |
| 整理至探索線 | 追加到所屬試法的歷次整理，無試法者放探索線的未指定試法歷次整理 |
| 整理成卡片 | 建立新卡片或追加既有卡片，供回流閱讀及作品參考 |
| 用於作品 | 關聯探索線，或先明確整理成卡片再加入作品；不直接引用暫存紀錄 |

### 8.2 操作入口與流程

上方探索歷程、單筆／試法操作與探索線中欄使用同一個整理流程，入口僅預填不同上下文。

1. 選取整個試法群組、部分發現，或目前探索線的可整理內容。
2. 可只選試法、只選完整發現或兩者；第一版不支援任意字元範圍勾選。
3. 依試法分組預填整理草稿；跨試法選取分別保存至各自歷次整理，未指定者另分組。
4. 使用者保留原文、精簡或改寫，並可補充整理心得。
5. 一般整理可選擇是否清除本次已輸出的活動紀錄；更新試法模式依第 7.4 節強制處理全部舊發現。
6. 顯示保存位置與清除紀錄範圍，確認才保存；失敗保留草稿。

若只輸出一筆發現的部分意思，不能自動認定整筆原文已完整保存。刪除仍以明確列出的整筆紀錄為單位，不清除未選取內容。

### 8.3 整理文字格式

預覽預設區分觀察與歸納，最後可保存成同一個文字欄位：

```text
當時試法：睡前閱讀 20 分鐘（無試法時標示未指定試法）
紀錄期間：……
整理時間：……

發現／觀察：
日期一：……
日期二：……

整理心得：
……
```

使用者可編輯內容；保留當時試法與時間脈絡。若原觀察被改寫且原紀錄被清除，保存的是使用者確認的整理敘述，不宣稱是完整原始證據或可逐筆還原的版本。

### 8.4 一般整理與更新試法的差異

| 行為 | 一般整理 | 更新試法前整理 |
| --- | --- | --- |
| 選取範圍 | 可選部分或全部 | 該試法目前全部發現 |
| 可編輯預覽 | 是 | 是 |
| 保留原發現 | 可選 | 否，確認後清除本輪舊發現 |
| 更新目前試法 | 否 | 是 |
| 保存結果 | 追加歷次整理 | 追加歷次整理、清除舊發現、更新試法 |

一般整理保留原紀錄時，允許日後再次整理，但應顯示最近整理時間及本次為追加內容的提示；此提示不代表精確的逐筆輸出歷程。第一版不建立完整 result source 追蹤系統。

## 9. 活動資料與歷次整理的保存

### 9.1 兩個區塊共用活動資料

上方試法與發現、探索線中欄呈現同一份活動試法與發現。改字、改派與刪除需同步反映；不再沿用第一版「原始紀錄匯入後形成獨立活動副本」的寫入語意。

既有原始紀錄與探索線副本可能已各自被編輯，不能只憑文字或來源 ID 自動合併並丟棄其中一份；切換前須盤點並制定保留內容的遷移方案。

### 9.2 歷次整理是獨立文字

- 每個試法保存自己的歷次整理文字；無試法內容由探索線層級欄位承接。
- 依時間追加分段，保留當時試法名稱、紀錄期間與整理時間，不因目前文字更新而重寫歷史。
- 整理只保存最後確認的文字，不額外建立不可變原文與整理稿兩套永久副本。
- 原活動紀錄清除後，歷史文字仍可閱讀，但不能保證還原為原本逐筆資料。
- 整理草稿保護與返回流程沿用共用彈窗；本輪不增加永久輸出草稿庫。

### 9.3 效能與寫入邊界

資料列數或重複外鍵值本身不代表效能問題。先檢查索引、N+1 查詢、一次載入量與真正重複的內容；整理後清理首先是產品生命週期選擇，不以筆數減少保證效能改善。

- 歷次整理先採每試法一個文字欄位，無試法者每探索線一個欄位。
- 主清單維持摘要分頁，不傳輸全部歷史；長文按需載入與展開。
- 追加由伺服器端處理，需衝突保護，避免兩個分頁互相覆寫。
- 歷史文字不作逐筆發現統計；活動計數與歷史閱讀分開。
- 若未來需要按整理批次獨立查詢或管理，再評估每輪一筆文字，不預先建立完整版本系統。

## 10. 清除探索紀錄

### 10.1 清理目的與範圍

活動紀錄可由使用者直接刪除，或在整理後清除。清除前需明確顯示目前實驗、試法及實際紀錄範圍，不能因上方是工作區而無聲清空資料。

| 資料 | 清除後行為 |
| --- | --- |
| 明確選定的活動發現 | 刪除，上方與探索線同步移除 |
| 未選取的活動發現 | 保留；更新試法模式不允許留下舊發現再改字 |
| 歷次整理、小結論 | 保留 |
| 目前試法、常用設定 | 不應隱含刪除；既有整批清除是否另含重設設定，須依第 18 節定案 |
| 已建立或追加的卡片 | 保留 |
| 作品與正文、卡片參考素材 | 保留 |
| 探索線與材料／成果關聯 | 保留 |
| 實驗目的、實驗結論與主題說明 | 保留 |

整理後清除以文字追加成功為前提；與清除、更新試法相關的保存須具備交易一致性及提交期間變更檢查。

### 10.2 既有作品引用的保護

新版停止新增作品對暫存探索紀錄的直接引用，也不新增作品專用文字素材。現有作品引用如何遷移仍須盤點實際資料後提出具體方案。

完成遷移前，清理不得讓作品已使用的內容消失；不得僅以實驗場或探索線連結取代原有具體素材。此為新版清理切換的必要前置條件，不代表已核准自動轉卡或新增文字素材欄位。

### 10.3 刪除與保留的提示

一般整理可選保留原紀錄；選擇清除時顯示會刪除的完整紀錄與保留位置。更新試法的確認需同時說明舊試法文字、全部舊發現數量與新試法文字。

不提供「一般清除時連歷次整理、卡片及作品一併刪除」的隱含行為；若未來需要此能力，另行設計。

## 11. 從探索線整理與輸出

### 11.1 閱讀模式與整理模式分開

一般瀏覽時不在所有內容旁顯示核取方塊。探索線以閱讀、比較及掌握目前理解為主。

使用者啟動「整理內容」後才進入選取模式，支援三種顆粒度：

| 選取層級 | 行為 |
| --- | --- |
| 整條探索線 | 選取該線目前可輸出的全部試法與發現；輸出卡片時亦包含歷次整理 |
| 指定試法或多筆發現 | 只整理所選項目 |
| 試法／發現個別選取 | 可以只輸出試法，或只輸出發現 |

第一版不支援任意字元範圍勾選；選取完整項目後可編輯輸出草稿，不要求先修改來源內容。

輸出卡片時，可另選各試法或未指定試法分組的歷次整理文字；這些文字不是活動發現，不納入清除紀錄的範圍。第 8 節整理活動紀錄的流程不重複將既有歷史追加回自身。

### 11.2 輸出前提供預覽

選取內容後產生可編輯草稿，再確認建立新卡片或追加既有卡片。歷次整理可作卡片整理的內容來源，但不還原或偽造已清除的活動紀錄。

- 卡片輸出延續可回流閱讀的語意，成功後建立探索線成果卡片關聯。
- 已存在同一成果關聯時不重複建立；追加內容與關聯保存應保持一致。
- 輸出草稿的編輯不回寫試法、發現或歷次整理；清除活動紀錄須另依第 8、10 節明確選擇。
- 不建立 result／result source 逐項輸出歷程。

### 11.3 作品關聯與用於作品

作品輸出改為兩條明確流程：

1. **關聯作品**：關聯新／既有作品與探索線，提供探索背景及返回入口，不搬移文字。
2. **整理成卡片後用於作品**：使用者明確建立或選擇整理卡片，再透過既有作品流程加入參考素材。

不再提供暫存探索紀錄直接加入作品，也不新增作品專用文字素材。作品正文不因關聯或加入素材而被插入、覆寫。具體卡片建立與作品選擇可銜接，但不得隱藏建立卡片的事實或跳過確認。

## 12. 共用操作與呈現

### 12.1 探索線主要操作

保留建立、編輯名稱、狀態、小結論、排序、材料與成果關聯；增加／調整選取試法、複製試法、更新前整理、記下發現、調整發現歸屬及歷次整理操作。

刪除探索線與系統「未設定」的操作限制須依第 18 節補完；不能直接沿用第一版刪除整組子資料的行為而無視新版的共用活動資料與歷史。

### 12.2 共用彈窗與上下文

上方試法與發現、探索線區塊共用選擇／建立試法、複製試法、更新前整理、新增／編輯發現、調整歸屬及整理彈窗；業務驗證與保存規則也共用。

| 入口 | 預設上下文 |
| --- | --- |
| 上方快速記錄 | 目前試法與選定探索線；未指定時使用系統「未設定」 |
| 探索線內 | 該探索線 |
| 試法內 | 該探索線與試法 |
| 未指定試法區 | 該探索線，試法留空 |

預填後建立的發現立即顯示在兩個區塊，不需再執行一次匯入。一般整理與更新前整理共用流程，但各自遵守第 8.4 節限制。

### 12.3 共用顯示元件

| 共用呈現 | 職責 |
| --- | --- |
| 試法標頭 | 目前文字、必要探索線名稱、操作選單 |
| 發現紀錄 | 文字、發生時間、編輯與整理操作 |
| 試法與發現群組 | 試法及其活動發現 |
| 歷次整理 | 文字、展開／收合 |
| 整理選取清單 | 沿用紀錄呈現，增加勾選與選取狀態 |

上方外層強調目前行動與近期紀錄；探索線外層依試法顯示目前文字、發現及歷次整理。外層可控制範圍、排序與密度，但不得各自複製內容呈現及業務操作。既有三欄摘要、詳情布局保持，僅為新版分組與操作加入必要呈現。

## 13. 正式概念資料模型

第 13.1～13.8 節記錄第一版資料模型基線，包含現行原始紀錄與整理副本的分離設計，不代表 v0.6 已完成 schema 切換。新版必須依第 13.9 節調整，不能直接繼續使用舊來源快照與複製規則。實際表名、欄位與 SQL 須經資料盤點及契約設計後確認。

### 13.1 `experiments` 擴充

新增 `conclusion TEXT NULL`。既有 `hypothesis` 沿用為實驗目的；既有 `description` 繼續作為主題說明，不搬移舊資料。

### 13.2 `exploration_threads`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `experiment_id` | 必填；刪除實驗時連帶刪除探索線 |
| `name` | 必填；同一實驗可有同名探索線 |
| `status` | `NOT_STARTED / IN_PROGRESS / PAUSED / CONCLUDED`；預設未開始 |
| `conclusion` | nullable；該方向的目前小結論 |
| `sort_order` | 必填；使用者自訂順序 |
| `last_activity_at` | 必填；內容活動時間，不因拖曳排序更新 |
| `migration_key` | nullable；只供系統遷移冪等性，不顯示於 UI |
| `created_at / updated_at` | 建立與修改時間 |

建議索引及約束：

- `(experiment_id, sort_order)`。
- `(experiment_id, last_activity_at)`。
- `(experiment_id, migration_key)` 在 migration key 非空時唯一。

### 13.3 `exploration_thread_methods`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線時連帶刪除 |
| `content` | 必填；trim 後不得空白 |
| `sort_order` | 必填；試法顯示順序 |
| `source_record_id` | nullable；原始紀錄刪除時設為 null |
| `created_at / updated_at` | 建立與修改時間 |

試法可以獨立存在而沒有任何發現。

### 13.4 `exploration_thread_records`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線時連帶刪除 |
| `method_id` | nullable；空值顯示於「未指定試法」 |
| `discovery` | 必填；trim 後不得空白 |
| `source_record_id` | nullable；原始紀錄刪除時設為 null |
| `occurred_at` | nullable；原始事件時間，沒有時以建立時間顯示 |
| `sort_order` | 必填；群組內顯示順序 |
| `created_at / updated_at` | 建立與修改時間 |

`method_id` 必須指向同一 `thread_id` 的試法。後端必須驗證；若 migration 可合理使用複合唯一鍵與複合外鍵，資料庫也應同時保護。

### 13.5 `exploration_thread_cards`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線只刪除關聯 |
| `card_id` | 必填；刪除卡片時刪除關聯 |
| `role` | `MATERIAL / RESULT` |
| `note` | nullable；保留舊實驗卡片備註及未來脈絡 |
| `sort_order` | 必填；角色內順序 |
| `created_at` | 建立關聯時間 |

唯一約束為 `(thread_id, card_id, role)`。同一卡片可同時作為材料及成果。

### 13.6 `exploration_thread_works`

| 欄位 | 規則與語意 |
| --- | --- |
| `id` | 主鍵 |
| `thread_id` | 必填；刪除探索線只刪除關聯 |
| `work_id` | 必填；刪除作品時刪除關聯 |
| `created_at` | 建立關聯時間 |

唯一約束為 `(thread_id, work_id)`。

卡片與作品在資料庫分表以保持非空外鍵及清楚的刪除規則；Service／API 合併成統一成果清單，前端不建立兩套管理介面。

### 13.7 現有探索資料擴充

`experiment_explorations` 新增 nullable `current_try_source_method_id`：

- `current_try` 保存選取當下的文字快照。
- 來源試法 ID 提供返回來源及後續整理預設。
- 使用者直接修改文字時清空來源 ID。
- 來源試法刪除時設為 null，current try 文字保留。

`experiment_exploration_records` 建議新增 nullable `source_thread_method_id`：

- 表示這次原始探索當時採用哪個探索線試法。
- 不表示這筆發現已整理進探索線。
- 即使使用者取消「把試法一起留下」，來源仍可保存。
- 來源試法刪除時設為 null，原始紀錄保留。

### 13.8 第一版不建立的資料表

第一版不建立 `exploration_thread_results` 或 `exploration_thread_result_sources`。目前只需知道探索線關聯了哪些成果，不永久追蹤每項成果精確使用哪些試法與發現。若後續確有逐項追溯需求，再新增聚焦的輸出來源關聯。

### 13.9 v0.6 已確認的模型調整方向（待實作）

| 對象 | 新版必要資料與限制 |
| --- | --- |
| 探索線 | 系統「未設定」識別及每實驗唯一性；未指定試法歷次整理文字 |
| 試法 | 所屬探索線、目前文字、歷次整理文字、最近整理時間；同線目前文字去除頭尾空白後唯一 |

## 15. 介面資訊密度原則

- 表格每列只顯示足以辨識探索線的材料摘要、少量最近發現、總數、狀態與小結論。
- 長篇探索紀錄不在主表格完整展開。
- 點擊「查看全部」或展開單列後，再閱讀完整試法與發現。
- 一般模式不顯示大量核取方塊。
- 整理模式才提供選取、批次輸出與選取數量。
- 左欄沒有卡片時使用簡短空狀態，不把卡片變成必填步驟。
- 中欄按每個試法依序顯示目前文字、活動發現、歷次整理；未指定試法另分組，長歷史可展開。
- 上方與中欄重用試法／紀錄呈現及操作，只由外層決定近期範圍、排序與歷史是否顯示。
- 右欄的狀態、小結論與成果不能擠成一段無層級文字。
- 桌面表格與手機直向卡片使用相同資料與操作語意，不建立兩套功能。
- 彈窗、選擇器、按鈕及文字層級應沿用專案既有共用元件與 `DESIGN_SYSTEM.md`，不另造一套視覺系統。

### 17.4 API 能力規劃

以下描述能力範圍，不先鎖死 URL；真正修改 endpoint 前需再次核對現有 controller 與 request／response 慣例。

- 探索線：清單、單筆詳情、建立、編輯、刪除及批次排序。
- 試法：建立、複製、編輯、排序及刪除；更新有發現的試法須遵守第 7.4 節。刪除時如何安置活動發現與歷次整理，須先完成第 18.2 節方案，不預先固定為移至未指定或連同刪除。
- 發現：建立、編輯、改派、排序及刪除。
- 卡片：批次加入／移除材料，加入／移除成果。
- 作品：加入／移除成果關聯。
- 整理：將選定活動內容追加為歷次文字；更新試法模式同交易保存歷史、清除全部舊發現與更新文字。
- 當前專注：採用既有試法、建立新試法、最近／常用與同名檢查，不默默解除來源。
- 歸屬：調整同一筆發現的探索線與 nullable 試法。
- 輸出：新建／追加卡片及成果關聯；作品只關聯脈絡或經卡片加入參考素材。
- 保護：驗證整理期間的文字及集合變動，歷史追加防止互相覆寫；確切 endpoint、版本與鎖策略尚待技術契約設計。

所有能力都要驗證 user owner、experiment、thread、method、card／work 的一致性。批次排序不得接受跨實驗、重複或不完整的非法 ID。整理與清除的併發保護已列為必要行為，實際版本欄位、鎖與衝突回應依技術契約設計決定，不預設所有子資料使用同一全域版本鎖。

## 19. 驗收情境

以下為新版驗收要求，尚未代表已通過：

1. 沒有卡片或自訂探索線也可記錄；未指定方向時使用同實驗唯一的系統「未設定」。
2. 明確選探索線時尊重目標；取消試法連結仍留在該線的未指定試法分組。
3. 最近用過與常用各最多 3 筆，同一試法多組入口仍使用同一 ID；更新常用指向的試法後顯示新文字。
4. 同線同名建立／更新被拒絕，忽略頭尾空白；跨線同名可依探索線辨識。
5. 複製須改字，不帶發現、歷史或常用標記，取消不建立資料，原試法完整保留。
6. 沒有發現可直接更新；有發現必須先整理全部舊紀錄，舊名保存於歷史，更新同值也可完成一輪整理。

11. 一般整理可選試法／完整發現與清除選項，跨群組分別追加歷史；未選取紀錄不被清除。
12. 整理格式區分觀察與心得；歷史保留當時名稱與時間，不因改名而重新解釋舊結果。
13. 清除後文字可閱讀，但不提供虛假的逐筆還原能力；保留紀錄後再次整理清楚提示為追加。

### 22.2 實際 API

探索線 API 使用 `/api/experiments/{experimentId}/threads`：

- `GET /`、`GET /{threadId}`、`POST /`、`PUT /{threadId}`、`DELETE /{threadId}`。
- `GET /summaries?page={zeroBasedPage}&size={size}` 只回傳清單所需的計數與近期摘要；單次 `size` 最多 20。
- `PUT /order` 調整同一實驗內的完整探索線順序。
- `PUT /{threadId}/position` 以目標探索線及前後位置調整順序，供分頁清單使用；排序範圍仍是同一實驗的完整探索線集合。
- `POST／PUT／DELETE /{threadId}/methods...` 管理試法。
- `POST／PUT／DELETE /{threadId}/records...` 管理整理後發現。
- `POST /{threadId}/imports` 批次將原始探索紀錄整理成探索線自己的試法與發現。
- `POST／DELETE /{threadId}/cards...` 管理材料或成果卡片。
- `POST／DELETE /{threadId}/works...` 管理成果作品。

- v0.6 的活動資料整合、歷次整理、試法複製／更新與清理、卡片輸出及作品引用切換尚未實作；作品不再直接接收暫存探索紀錄或新增文字素材。
- 尚未進行瀏覽器桌面與手機尺寸人工驗收；發布前需依第 19 節逐項操作。

### 22.5 後續迭代：摘要載入、選取流程與作品反向入口

- 實驗詳情初始只取得每頁最多 20 條探索線的摘要資料；摘要包含總數、最近材料、最近發現與第一筆試法，不載入整條探索線的完整子集合。
- 每頁前 5 條探索線預設展開摘要，其餘維持收合。收合時保留名稱、狀態、最近整理時間、查看詳情、排序與更多操作；使用者自行展開後才閱讀既有三欄摘要。此調整不改變探索線詳情彈窗的內容與排版。
- 分頁只限制取得與呈現的資料量；使用者調整順序時仍以同一實驗的完整探索線排序保存，重新載入後維持順序。
- 卡片加入探索線改為與「加入既有作品」相同的單選候選列表：整列選取、選中淺底與明確停用狀態；候選範圍、加入材料的業務規則及保存時機不因此改變。
- 作品詳情右側顯示關聯探索線；點選後開啟探索線詳情彈窗，不導向實驗詳情頁。卡片詳情的關聯探索線亦採相同閱讀方式。
- 摘要 API 曾因 PostgreSQL／Hibernate 原生查詢回傳 `Instant` 時間型別而造成 500。服務層時間轉換已支援 `Instant`、`OffsetDateTime`、`Timestamp`、`LocalDateTime` 與 `Date`；此修正不改變 API 欄位格式。
