# 工作流程選擇（唯讀）

## 職責與啟動

- 優先由使用者明確呼叫（例如 `$workflow-selector`）；僅在使用者明確詢問「用什麼 Skill／哪些開發階段／如何安排工作方法」時才考慮自動啟用。
- 目的只在**選擇方法與執行深度**，不代替需求設計、程式調查或功能開發。
- 不因使用者提到「新增功能」、「修改 UI」、「修 Bug」就主動進行完整評估。若使用者已指定 `$feature-development`，不再要求先經過此 Skill。
- 優先遵守目前 repository 的 `AGENTS.md`、使用者本次授權與其他上位限制；本 Skill 不授權程式、文件、Git、資料庫或部署寫入。

## 快速判斷（只依必要資訊）

1. **任務目的**：討論／規劃／實作／除錯／審查／其他；辨識本輪「只分析」或「可實作」的授權範圍，不把貼上的 ChatGPT 對話當作自動實作許可。
2. **規模與風險**：局部或跨模組；是否改動產品行為、API、資料模型、使用者草稿、權限或既有操作流程。依**變更風險與不確定性**判斷，而非以程式碼行數決定。
3. **既有進度**：是否已有使用者確認的設計、計畫或測試結果，可以直接承接；別把 AI 曾建議但未獲確認的事項視為定案。
4. **方法選擇**：選擇下表一路徑，僅推薦必要階段；若資訊不足以精確選擇，標明假設或一項關鍵待確認事項，不為分類而全專案掃描。

| 路徑 | 適用任務 | 建議處理 |
| --- | --- | --- |
| A：一般直接處理 | 明確、影響局部且風險低，例如調整標題旁數量排列 | 依 `AGENTS.md` 一般流程；是否可免再次核准，以**目前有效**的 `AGENTS.md` 為準 |
| B：部分開發能力 | 需要現況核對或 UI 模式比較，但不用完整功能規劃 | 建議 `$feature-development` 指定階段或只進行唯讀設計對照 |
| C：完整功能開發 | 新工作流程、跨前後端整合、重要資料／互動設計變更 | 建議 `$feature-development` 完整深度；本輪若只要求設計，就停在規劃確認點 |
| D：非功能開發 | Git 檢查、純技術問答、既有文件閱讀、其他專業任務 | 使用一般指令或其他真正適用的 Skill，不強迫採用開發流程 |

`feature-development` 階段代號：①需求理解、②現況盤點、③UI 模式對照、④實作規劃、⑤實作與程式驗證、⑥交付／人工驗收銜接。可略過不相關階段，也可輕量執行；**建議階段不等於開始執行的授權**。

## 成本與停止條件

- 預設只依本次使用者訊息、目前上下文與既有已確認方案判斷。只有分類會因此改變時，才選擇性閱讀少量相關檔案。
- 不進行全專案掃描、完整需求拆解、UI 元件逐一清點、測試／建置、啟動瀏覽器、產出 PNG／HTML 草圖、修改檔案、Git 操作或建立永久報告。
- 一旦能判斷合適工作路徑，就停止；不要假裝已經檢查過實際程式或驗證過可行性。
- 若使用者只是請求評估，不代替其啟動下一個 Skill；可以提供可直接引用的階段選擇結果。

## 預設輸出（簡短）

以 3～6 行回答；極簡任務可更短。依需要呈現：

- **任務性質／授權**：例如「跨功能 UI 流程設計；本輪僅規劃」。
- **建議方法**：例如「`$feature-development`，②③④；①輕量，⑤⑥暫不執行」。
- **判斷依據**：最重要的 1～2 項原因。
- **不需要做**：指出容易浪費成本的工作（若有）。
- **需確認的風險**：只列真正阻礙下一步的事；未發現則略過。

## 範例判斷

- 「幫我決定探索線拖曳排序該走哪些步驟」→ B；①輕量、②③④，先規劃，不改程式。
- 「請依剛才核准的計畫開始實作」→ 不需要本 Skill；直接由開發流程承接⑤⑥。
- 「把紀錄數量移到標題右邊，直接改」→ A；不為此自動啟用開發 Skill，仍受當前 `AGENTS.md` 授權限制。
- 「卡片、實驗、作品要新增一套共用關聯管理」→ C；建議先做①②③④，取得實作授權才執行⑤。
