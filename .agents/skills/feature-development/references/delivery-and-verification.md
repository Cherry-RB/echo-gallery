# 程式驗證、視覺驗收與成本控制（第五、六階段）

僅在真正進入修改／驗證或需要交付檢查時讀取。本文件不得降低 `AGENTS.md` 的安全與測試要求。

## 第五階段：依風險驗證，不省略重要測試

1. 先檢查工作區既有修改，僅變更授權範圍；不得覆蓋使用者既有工作或順手重構。
2. 前端修改：依 `AGENTS.md` 執行必要 build／測試，並確認元件的 props、響應式與操作行為。後端修改：執行必要測試；前後端契約變更需雙方檢查。
3. 涉及資料的建立／刪除／清理、權限、草稿或非同步保存時，檢查真實影響、失敗情境和必要的整合測試；SQL、schema 及環境操作遵守既有授權規則。
4. 修改途中優先跑聚焦驗證；最後跑必要完整檢查。已通過且未受新改動影響的檢查不為形式反覆重跑。
5. 若環境限制阻止測試，指出原因及受影響範圍；不可聲稱已通過，也不可為此私改 `.env` 或創造高成本新驗證框架。

## 第六階段：客觀 UI 驗證與人工視覺驗收

### 交付前的 UI 對照複核

逐一回到第三階段列出的受影響畫面與重要流程，依實際程式／diff 核對以下適用項目；不適用者註明原因，不為填表擴大任務：

| 核對面向 | 要確認的實際結果 |
| --- | --- |
| 外殼與留白 | 頁寬、對齊、layout／route 留白責任、工作底與內容表面；沒有無理由的重複 padding 或巢狀面板 |
| 資訊與操作層級 | 標題、說明、日期、計數、按鈕與操作群組的 token、位置及密度符合對應角色 |
| 資料狀態 | 載入、更新、空集合、無符合結果、錯誤／重試、長名稱及失效來源使用同一外殼，未將未知數量當成零 |
| 實際組合 | props、slots、事件與可見內容正確；導頁、選取、取消、草稿及提交時機保留，操作不誤觸外層 |
| 響應與可存取性 | 相關斷點、窄螢幕、明暗主題、鍵盤與焦點的處理，以及尚未實際檢查的範圍 |

發現授權範圍內的具體不一致應先修正；重大設計衝突依既有授權規則處理。向使用者交付精簡複核結果，指出各畫面已套用的模式、必要差異及未驗證項目，可與變更說明合併，不另建永久報告。不得僅以使用共用元件或測試通過取代這份複核。

### 實際驗證與限制

- 布局溢位、響應式重排、焦點、彈窗關閉、選取與導航等可客觀判斷的行為，若既有瀏覽器工具或測試可直接覆蓋，執行與改動範圍相符的聚焦驗證。
- 色彩、間距密度與整體感受等主觀視覺品質由使用者人工驗收。提供具體檢查路徑，例如「探索線詳情 → 新增紀錄 → 取消保留內容；手機窄寬度下計數與操作重排」，並標示尚未驗證的部分。
- 不進行無目標的瀏覽器巡頁、批次截圖、建立 PNG／HTML 草圖、建立 demo UI 或多輪自動美化。既有方式無法覆蓋重要風險而需要新增高成本驗證方式時，先說明目的與範圍。測試資料需隔離，遵守既有資料清理規定。
- 使用者交付圈選截圖：直接核對實際程式做局部修正；**不要生成替代草圖**。新修正視為下一項局部任務。

## 交付狀態分層

| 狀態 | 可以宣稱 | 不可推論 |
| --- | --- | --- |
| 程式／自動測試已通過 | 指定測試命令及結果、改動檔案 | UI 視覺已符合使用者偏好 |
| 程式層 UI 對照已完成 | 已核對的外殼、元件契約、樣式及必要差異 | 實際瀏覽器無溢位、視覺已對齊或人工已驗收 |
| 瀏覽器／畫面檢查已執行（僅在實際做過時） | 實際檢查的操作、環境、限制 | 已代替使用者主觀驗收 |
| 待人工驗收 | 尚未確認的視覺、互動與裝置 | 「全部驗收完成」 |
| 使用者已確認 | 經使用者實際認可的明確範圍 | 其他未檢查的畫面也通過 |

一般交付：**變更範圍 → 已完成／未完成 → 測試結果 → 人工驗收點**。不要為單次修改建立新的永久報告；PR 截圖只在使用者要求、團隊審查需要，或畫面差異難以從程式碼判斷時提供。
