# UI 模式對照方法（第三階段）

新增頁面、UI／UX 流程設計、跨畫面 UI 功能或使用者明確要求一致性檢查時，必須讀取並完成本對照。局部修正可只查相關條目。先按任務查 `docs/DESIGN_SYSTEM.md` 相關段落，**不要全文抄寫或自造第二套設計規範**。

## 盤點粒度

以獨立使用者目的切分：例如「新增探索線」、「選取材料」、「記錄試法與發現」、「開啟歷程」、「整理成果」。

- 「選取材料」可包含搜尋、瀏覽、暫選、移除、取消與確認：它是一段完整流程，不必為每顆按鈕建立一列。
- 同一新頁面可能參考多個不同的現有流程；不要要求整頁只能參照某一個功能，也不要把所有彈窗硬套相同布局。
- 只有在視覺／互動影響實作選擇時才深挖 CSS 與元件細節；純技術 API 任務不用跑第三階段。

## 對照次序

1. 確認使用者任務、輸入、結果、取消／返回與保存時機；辨別 UI 上相似、業務行為卻不同的情況。
2. 查設計規範的「使用情境 → 設計模式 → 現有元件／功能流程」與適用章節（如計數 §5.1、按鈕 §5.2、歷程 §6.3、彈窗 §7）。如果目前工作區尚未更新到含此對照表的文件版本，先依原有 §9.1 元件索引與現行程式查證，不假設新表已存在。
3. 在 repo 實際讀取參考頁面、共用元件及呼叫端，核對布局 CSS／token、props、slots、事件與保存時機。另查外層 layout／router 的留白責任，避免共用元件外再疊一套頁寬、padding 或表面。可查 `RecordCount.vue`（資訊計數）、`RecordHistoryTrigger.vue`（開歷程）、`SectionHeader.vue`（章節標題操作）、`AppDialog.vue`（彈窗外殼）、`CardPickerDialog.vue`／`PickerWorkspace.vue`（選擇與已選摘要）、實驗與奇珍等實際頁面。**這些是搜尋線索，請先驗證檔案與目前用途，不能保證所有實作已符合規範。**
4. 對每個重要流程選一項：「**沿用**（可直接重用）／**調整**（沿用骨架但因需求不同而改動）／**新增**（沒有合適模式）」。補充選擇理由、差異、不能擅自改變的語意。
5. 如發現已人工驗收的設計與文件有矛盾，告知衝突及推薦處理方式；在使用者核准前不做全域修正。

## 修改前必須提供的對照結果

以精簡表格或同等資訊的文字向使用者呈現；每個受影響畫面都要涵蓋其外殼，每個重要流程都要涵蓋其互動。同一列可涵蓋共用模式，不要求每顆按鈕各列一筆。

| 畫面／操作流程 | 使用情境／對照模式 | 實際讀取的參考檔案 | 沿用／調整／新增、重用部分與必要差異 |
| --- | --- | --- | --- |
| 新集合頁 | 頁首、工具列、集合與空狀態 | `src/views/experiment/ExperimentList.vue`、`src/layout/MainLayout.vue`、`src/style.css` | 沿用工作底與集合外殼，外層管理頁面留白；篩選欄位依本次需求調整 |
| 選取多張卡片 | 候選、已選摘要與確認 | `src/components/CardPickerDialog.vue`、`src/components/ui/PickerWorkspace.vue` | 調整：重用候選／摘要布局，核對 slots、多選上限與暫選；確認帶回父表單仍不寫入資料 |
| 新的專用操作 | 現有模式不足 | 列出已查閱但不適用的實際元件或流程路徑 | 新增；說明不適用原因及仍沿用的 token／外殼 |

表中檔案僅為範例，必須換成當次真正讀取且適用的檔案。未找到適用模式時應列明查閱範圍與理由，不得只填「無」後另造整套外觀。

**完成條件：**有實際來源、可核對的重用判斷，且每個受影響畫面／重要流程均已涵蓋。單純羅列元件名稱、宣稱「沿用全站風格」或只讀設計系統，不算完成。明確的小型 CSS／文案／既有模式修正可縮成一句，仍須指出參考位置與要修正的差異。

## 一致性驗收原則

- 同一資訊群組內的短名稱、數量、狀態與操作，寬度足夠時優先同行；避免無故拆成多列；窄螢幕可按語意換行，不能縮字或壓操作範圍硬塞。
- 區分純計數與可互動的計數，頁級／區塊／單筆操作與主要／次要／破壞性操作。
- 遵循現有對話框尺寸、關閉／草稿保護、選擇狀態、鍵盤與響應式規則；不得只為視覺一致而改變提交時機、業務資料或權限。
- 「與既有頁面一致」必須說清楚**哪個頁面、哪種角色、哪些可重用部分、哪些不應複製**。
