# UI 模式對照方法（第三階段）

僅在新功能包含 UI／UX 設計、操作方式改變，或使用者明確要求跨畫面對照時讀取。先按任務查 `docs/DESIGN_SYSTEM.md` 相關段落，**不要全文抄寫或自造第二套設計規範**。

## 盤點粒度

以獨立使用者目的切分：例如「新增探索線」、「選取材料」、「記錄試法與發現」、「開啟歷程」、「整理成果」。

- 「選取材料」可包含搜尋、瀏覽、暫選、移除、取消與確認：它是一段完整流程，不必為每顆按鈕建立一列。
- 同一新頁面可能參考多個不同的現有流程；不要要求整頁只能參照某一個功能，也不要把所有彈窗硬套相同布局。
- 只有在視覺／互動影響實作選擇時才深挖 CSS 與元件細節；純技術 API 任務不用跑第三階段。

## 對照次序

1. 確認使用者任務、輸入、結果、取消／返回與保存時機；辨別 UI 上相似、業務行為卻不同的情況。
2. 查設計規範的「使用情境 → 設計模式 → 現有元件／功能流程」與適用章節（如計數 §5.1、按鈕 §5.2、歷程 §6.3、彈窗 §7）。如果目前工作區尚未更新到含此對照表的文件版本，先依原有 §9.1 元件索引與現行程式查證，不假設新表已存在。
3. 在 repo 查既有程式與呼叫端。可查 `RecordCount.vue`（資訊計數）、`RecordHistoryTrigger.vue`（開歷程）、`SectionHeader.vue`（章節標題操作）、`AppDialog.vue`（彈窗外殼）、`CardPickerDialog.vue`／`PickerWorkspace.vue`（選擇與已選摘要）、實驗與奇珍等實際頁面。**這些是搜尋線索，請先驗證檔案與目前用途，不能保證所有實作已符合規範。**
4. 對每個重要流程選一項：「**沿用**（可直接重用）／**調整**（沿用骨架但因需求不同而改動）／**新增**（沒有合適模式）」。補充選擇理由、差異、不能擅自改變的語意。
5. 如發現已人工驗收的設計與文件有矛盾，告知衝突及推薦處理方式；在使用者核准前不做全域修正。

## 輕量輸出（可視任務縮成一句）

| 操作流程 | 使用情境／對照模式 | 既有元件或流程 | 沿用／調整／新增與理由 |
| --- | --- | --- | --- |
| 查看所有探索紀錄 | 區塊歷程入口 | `RecordHistoryTrigger` 與既有歷程對話框 | 沿用入口模式；核對總數是否代表所有紀錄 |
| 選取多張卡片 | 搜尋／候選／已選摘要與確認 | `CardPickerDialog`、`PickerWorkspace` 等 | 調整：核對多選上限、暫選及確認保存語意 |
| 新的專用操作 | 現有模式不足 | 尚無確認的共用流程 | 新增；說明為何不能直接重用 |

## 一致性驗收原則

- 同一資訊群組內的短名稱、數量、狀態與操作，寬度足夠時優先同行；避免無故拆成多列；窄螢幕可按語意換行，不能縮字或壓操作範圍硬塞。
- 區分純計數與可互動的計數，頁級／區塊／單筆操作與主要／次要／破壞性操作。
- 遵循現有對話框尺寸、關閉／草稿保護、選擇狀態、鍵盤與響應式規則；不得只為視覺一致而改變提交時機、業務資料或權限。
- 「與既有頁面一致」必須說清楚**哪個頁面、哪種角色、哪些可重用部分、哪些不應複製**。
